# 48. UI 架构与设计系统规范 (UI Architecture and Design System)

本文档定义全平台的 UI 架构、设计系统令牌（Tokens）与视觉交互规范。适用于 `user-web`（用户端）、`admin-web`（品牌后台）、`platform-web`（平台总后台）与 `agent-web`（独立代理端）。

在进行任何前端页面修改、重构或新增时，所有开发人员及 AI（CODEX / AGENT）必须严格遵守本规范，**禁止私自另造一套设计风格、禁止随意引入未约定的突兀颜色、正文、说明、状态和交互统一使用 `--body-font-size`（14px）普通字号，禁止局部缩小字号**。

---

用户端必须先识别当前域名的品牌，再展示品牌名称、Logo、登录表单和业务界面。未绑定或已不可用的品牌入口使用无品牌的独立“站点不可用”页面，不显示默认品牌、不使用普通记录错误提示，也不跳转到其他品牌；暂时的读取失败才提供重试。

总后台、品牌后台和代理端使用固定域名，登录页不依赖用户端品牌 context。品牌后台登录后仅从账号授权列表选择品牌，单品牌账号自动进入；多品牌账号使用共享 SelectControl 选择。代理用户名全平台唯一，会话确定所属品牌，登录后再读取该品牌展示。登录页可以请求 me 恢复会话，未登录的 401 不显示为业务错误。

## 1. 核心设计原则 (Design Principles)

1. **一致性与复用（Consistency & Reuse）**
   - 优先使用已在 `:root` 中声明的设计令牌（CSS 变量）和既有通用类（如 `.button`, `.panel`, `.card`, `.status-chip` 等），不随意在页面局部硬编码新的颜色值或内联样式。
2. **KISS 原则（Keep It Simple, Stupid）**
   - 遵循项目基础规则，保持清晰扁平的 CSS 架构，不为简单状态引入过度抽象的组件或重量级 CSS-in-JS 框架。
3. **清晰可读的现代层级（Legibility & Modern Hierarchy）**
   - 彻底废除旧版 6px~10px 的微型字号。正文与交互元素必须达到人机交互可读标准。
   - 卡片层次分明，采用柔和的环境环境阴影（Ambient Shadow）与干净的边框线条，避免死板脏乱的泥浊色调。
4. **严格的视口与无横向溢出标准（Zero Horizontal Overflow）**
   - 所有页面必须随实际 CSS 视口连续自适应，覆盖手机横竖屏、短屏与长屏、平板和桌面；不得固定为 360×800，不按操作系统判断页面宽度，也不得整页缩放或隐藏溢出来掩盖布局问题。所有验收视口均须满足：
     `document.documentElement.scrollWidth <= window.innerWidth + 1`
   - 移动端交互触控区最小高度不小于 44px。

### 操作原因

所有端取消人工操作原因输入及其必填、按钮禁用、提交前拦截；请求中审计附注可为空，不自动补造原因。确认层仅在恢复的旧请求带有原因时显示原附注。历史记录仍保留已有说明、操作人、时间及变更内容，业务原因类别和自动失败信息继续展示。权限、版本、金额和未知结果原键重试的校验保持不变。

### 下拉框交互与加载

- 四端同类单值选择统一复用共享 `SelectControl`，包括用户端顶栏彩种选择；选项在顶层浮层内展示、滚动，不以字段下方的按钮组或独立平铺菜单代替，不撑开页面布局。
- 四端下拉菜单的展开、关闭、键盘定位和本地值选择不触发全局加载；菜单定位所等待的直接或间接 `nextTick` 属于本地 UI 操作。选择后确实读取服务端数据的操作仍按原有前台加载规范处理，不能为消除误报而取消真实请求的加载反馈。
- 共享选择控件支持鼠标和触屏选择、跳过禁用项、方向键、Home/End、Enter/空格、文字定位、Escape 取消和 Tab 确认并移出；选择后焦点返回触发按钮，点击外部或失焦时关闭。弹层随实际视口定位，长列表在弹层内滚动，不得溢出屏幕。
- 四端语言菜单的触发按钮和选项、共享选择控件的触发按钮显式使用 `tabindex="0"`，确保 Safari 也可通过 Tab 进入选项、Enter 选择、Escape 关闭并返回触发按钮。选择控件沿用共享 SelectControl 的键盘、触控和顶层 Popover 交互。
- 验证同时检查最终加载状态与交互期间的状态变化/遮罩新增，不能只在操作完成后检查遮罩消失。使用独立浏览器会话和模拟只读接口，不占用开发者账号或写入业务数据。

### 四端统一表格表头

- 用户端、品牌后台、总后台和代理端的所有表格统一采用浅灰蓝表头，使用共享语义令牌 `--table-header-bg`（引用既有 `--line-subtle`），正文色 `--ink-secondary`、字重 650，底部使用 `1px solid var(--line)` 分隔线。规则维护在 `shared/src/styles.css`，页面不得添加强制白底或独立深色、品牌色表头。
- 统一覆盖原生 `thead`、共享 `ManagementTable`、页面内表格、弹窗明细、报表、资金来源/余额对账网格和 `role="table"` 的列标题行；固定首尾列及吸顶表头与其他表头保持相同浅背景，避免白色断块。既有字号、列宽、行高、排序与操作行为沿用原规则。
- 仅列标题区域加背景，`tbody` 中的行标题和普通数据行不套用表头背景。手机端保留既有响应式重排：隐藏的表头不恢复显示，卡片内 `data-label` 字段标签不整块铺色；仍以表格呈现的手机列表和弹窗使用同一浅背景。
- 验收覆盖四端原生表格、共享表格、语义表格、固定列、报表行标题和弹窗；保留安卓、iOS 横竖屏设备预设，并检查桌面及 320 CSS px 重排、文字对比度和页面无横向溢出。

### 用户端页面标题与彩种上下文

- 用户端所有业务页面的主标题统一置于公共顶栏返回按钮“＜”右侧，作为唯一的页面 `h1`（顶栏标题 18px）；页内不重复主标题和返回入口。首页保留品牌入口，登录/注册沿用统一认证布局。
- 同一页面只提供一个彩种选择器，统一使用公共顶栏入口；投注记录与开奖结果随该入口切换彩种，页内不再添加同义下拉框。已有彩种上下文时，不在内容区、每条记录或明细中重复当前彩种标题。
- 用户端业务内容区使用可用宽度的 100%，不受 1100px 居中上限限制，保留既有响应式内边距；认证卡片与弹窗保持各自的阅读宽度。
- 投注记录使用表格呈现期号、投注内容（玩法与选号）、赔率、投注积分、中奖积分、状态及投注时间；投注内容只显示投注时的玩法与选号，不随结算变化，也不重复显示已有独立列的积分和赔率。四端统一使用 `BettingHistoryTable`，业务列顺序固定为期号、投注内容、结果、赔率、投注积分、中奖积分、正额附加金额、状态、投注时间；彩种、会员仅在当前查询范围需要时置于前方独立成列。金额保留接口十进制原文，桌面金额列右对齐；未结算中奖积分显示“—”，已结算零中奖显示“0”。附加金额不得叠进投注或中奖单元格。手机端标签和值同行、两列紧凑重排，期号、投注内容和投注时间按可用宽度独占行；不继承旧表格固定最小宽度或单元格固定高度，不缩放页面或截断金额。品牌后台和总后台注单列表的中奖、未中、退本使用独立“结果”列，分别引用成功、失败、警告文字色；待结算显示“—”，不把结算结果拼接到玩法中。风险冻结、实际亏损、和局退款及风险解冻有正额时独立成列，全页为零的附加列不显示，零额单元格显示“—”；中奖积分已含本金，和局退款不属于中奖派彩。表格使用自动列布局，列宽按实际内容分配，不给投注内容设置固定占比；桌面及横排表格的投注时间保持单行。表格单元格垂直居中，正文行高一致，段落无首尾额外外边距；状态只用语义文字色，不加胶囊边框或背景。待结算中奖积分显示“—”，不把未结算显示为已结算零奖；不提供仅显示 UUID 的“详情”。多条投注逐条展示，复用历史快照和已有翻译，不用当前规则补造历史信息。
- 用户端投注确认弹层使用“投注内容、赔率、投注积分”三列表格，表格宽度为弹窗内容区的 100%，各列按实际内容自动分配，不设固定占比；积分与赔率数值保持单行、右对齐，列标题与数据对齐，手机保留紧凑内边距，长投注内容及串关名称可换行但不得挤断数值。每条服务端报价对应一行；已确认的原请求重试也使用同一表格和保存的规则快照。注数、总积分及风险冻结积分统一置于底部按钮区左侧，按钮靠右；窄屏不足以同排时，汇总在上、按钮在下，数值不拆行；操作按钮和提交校验不变。
- 700 CSS px 及以下表格按记录重排为带字段名的两列布局，投注内容和时间独占整行；320 CSS px 保持可读且页面无横向溢出。顶栏标题允许按实际宽度换行，不挤压返回和菜单按钮。

### 全站紧凑布局

- 移动端短表单优先使用标签与控件同行：共享登录字段沿用 `LoginCredentials`，其他已审查的短字段使用 `.ui-field-row` 并将标签文字包在 `span` 中。标签允许自然换行，控件保持至少44px触控高度；长地址、复杂选择及多行输入保留独占行，不对全部字段强制套用。登录页移动端不展示卡片内装饰图，品牌、页签、字段之间使用紧凑间距。短表单在常用手机竖屏尽量首屏可提交，横屏保持内容可滚动、操作可达，不强行限制页面高度。

- 移动端（900 CSS px 及以下或粗指针触屏）优先压缩纵向留白：内容顶间距、卡片上下内边距、表单字段与主要区块行间距采用 8px，标签与控件、筛选换行及记录字段采用 4px；弹窗标题上下 4px、正文和底栏上下 8px。横向留白、字号、至少 44px 触控区、内容自然换行和导航安全区保持原规范；本条优先于下文的桌面或默认间距。

- 用户端及其共享组件的背景、文字、边框、阴影、选中、悬停、焦点、禁用、原生控件、滚动条和文本选区均从 `shared/src/themes.css` 的当前主题及日夜模式取值；不得在页面或组件重新声明固定的深色配色。成功、警告、错误与号码波色保留业务语义，并按日夜模式保证文字可读；号码球和筹码的材质高光、二维码白底不随主题主色替换。
- 四端业务表格通过共享 `--table-cell-padding-inline` 保留默认 8px 的单元格左右内边距，表头与数据列边缘一致，首列左对齐和末列右对齐不得清零贴边。移动端卡片若由行容器提供留白，须检查最终可见内容与卡片边界的间距，不叠加不必要的留白。居中的日历日期网格与开奖号码加号分隔列保留其紧凑结构。
- 四端普通单行输入框、下拉框和动作按钮统一由 `shared/src/controls.css` 的 `--control-height` 控制：桌面（大于 900 CSS px 且精确指针）为 32px，窄屏或粗指针触屏为 44px；页面不得另设普通表单控件高度。输入框与下拉框使用 border-box 与紧凑垂直内边距，避免内边距撑高。四端普通按钮、翻页动作、侧栏导航、页签、操作菜单、账号菜单、语言菜单和可展开行同样复用 `--control-height`：桌面单行 32px，窄屏或粗指针触屏至少 44px；菜单项纵向内边距 4px、行高 22px，多行文字自然撑高。不得固定使用移动端 44px 或以大内边距撑高桌面菜单行。多行文本框、多选列表、复选框、单选框、筹码、号码卡片及导航维持各自结构与尺寸；触屏普通输入保持 16px 字号。管理端 `--console-control-height` 引用同一令牌。


- 加拿大28等配置化彩种的用户端玩法导航按既有分组展示：同组由单个选项构成的逐注玩法集中在同一入口，如“两面”“总和”；右侧展示各原始选项及其销售赔率。加拿大28导航统一为“两面、组合、总和、尾数”；极大、极小归入两面；各组独立逐注选项支持多选、再次点击取消及跨组保留，按每项积分累计金额，通过原玩法逐项报价并整批确认；总和选号项仅显示0～27，尾大小单双与尾数字选项同属尾数，1尾～8尾在前，其后显示大、小、单、双、大单、大双、小单、小双，不重复添加“尾大小单双”前缀，原始标识及规则快照不改写。分组只影响导航，不合并规则、赔率键或投注编号；具体选号、报价、规则说明及金额校验仍绑定原玩法。已有多选、组合或单位倍数玩法保持其选择约束和独立入口。中英文组名使用共享目录，导航支持方向键及 Home／End，320 CSS px无横向溢出。合并后的玩法说明按当前分组展示全部选项，标题、选项顺序与选号区一致；逐项展开当前中奖／退本条件和对应销售赔率，不再只解释当前原始子玩法。尾数共有不中奖结果按当前规则及其金额分支计算显示，不硬编码为固定例外，不改写规则快照。

- 选号卡片内的赔率值（单档和多档）必须保持完整，不在小数点或数字中间断行；赔率文字单独设置不换行，不继承按钮标题的任意断行规则。网格根据当前玩法、盘口的完整赔率文本长度计算最小卡片宽度，并计入内边距与边框；窄屏通过减少列数保持可读，不缩小赔率字号或裁切数字。单档与多档共用此规则，不分别设固定宽度。卡片内的名称和赔率按自然文档流分行并随内容增高，长名称换行时不得压缩或挤出赔率。
- 用户端投注页统一提供“玩法规则”入口，桌面和移动端均可打开；仅展示当前玩法的选号方法、中奖条件、销售赔率及退回规则，不展示后台规则定义、字段、版本或 JSON。说明随当前发布规则和销售赔率更新。

- 香港官方搅珠日历位于彩种时间设置，采用完整月历：周日至周六七列、整月日期及相邻月补齐日期、上／下月切换、搅珠日／金多宝／预售日圆形标记和图例。过去日期保持官方标记；未公布月份明确提示，不将无数据显示为无搅珠安排。只使用来源保存的日期，不推算预售日；切月是本地展示操作。样式沿用统一令牌、共享浅色表头与普通正文字号，不复制外站品牌色或逐日卡片列表。普通搅珠日使用信息蓝令牌`--info-bg`（#dbeafe）、`--info-text`（#1d4ed8）和`--info`（#2563eb）作为底色、文字及边框，图例同步；金多宝保留金色实心圆，预售日保留金色空心圆。

- 彩种各入口只显示对应业务：期次显示期号与排期，不混放开奖结果；玩法规则显示当前规则与编辑保存；号码模型以只读摘要展示，编辑时使用表单；时间设置作为独立入口维护开奖日期规则、开奖时刻、开盘提前小时数、封盘提前秒数和采集延迟秒数；开奖数据源独立维护来源及映射。开奖页只显示采集状态、待开奖操作与结果历史，不提供时间设置、来源配置或重复的“手动开奖结果”期次列表，人工发布通过待开奖记录的操作进入。六合彩期次由日程自动生成，期次页不提供手工创建或逐期改开盘入口，开奖页不重复开盘／封盘字段。香港官方搅珠日历置于香港彩种的时间设置页。加拿大28等非六合彩彩种同样提供独立时间设置入口；来源排期模式只维护开盘提前秒数和封盘提前秒数，期号与开奖时间沿用来源。已有来源排期配置的时间字段不再放在数据源编辑表单；切换来源不得恢复旧的开盘或封盘参数。详情不重复铺开彩种目录、标题、版本列表或无关记录。
- 共享玩法规则直接保存生效，不提供草稿、验证用例、审核和发布流程。模板导入、新增玩法和本地试算按需展开；服务端仍校验结构、号码模型、权限、并发版本和幂等，历史下注快照保持不变。

### 写入入口防重复提交

- 用户端、代理端、品牌后台与总后台的写入表单、独立操作按钮统一使用共享 `vWriteGuard` 指令，绑定覆盖接口、响应解码和后续页面更新的完整操作状态。点击、回车及程序触发的表单提交共用入口限制：立即锁定，至少经过 1 秒且操作完成后才解除；失败也遵守此间隔。查询、筛选、分页不加此限制。
- 同一表单中从提交按钮切换到重试按钮仍受原表单限制。指令在捕获阶段阻止重复事件，保留原有权限与业务 `disabled` 条件，卸载时清理计时器；不通过延迟发送请求或增加确认弹窗实现。
- 结果未知时保留原请求体和幂等键，重试不可产生新的扣款意图。前端限制仅防误操作；后端必须继续使用品牌与操作范围内的幂等、账户事务锁、对象版本校验、状态机及业务入账唯一约束。临时 5xx 响应整体回滚且不缓存，允许原键在恢复后重试；成功及明确业务拒绝保留原回执。
- 充值申请尚未实现的用户端入口不伪造成功；今后接入时复用同一指令。现有后台人工充值、确认及取消入口均应用上述限制。

### 操作按钮文案

- 三端按钮使用简洁动作词，如“保存”“提交”“创建”“重试”，英文同步使用 Save、Submit、Create、Retry。不在按钮中堆叠“核对并”“确认并”或内部实现术语；影响说明放在字段说明和确认内容中。结果未知时保留“重试原请求”等必要区别，沿用原请求和幂等键。
- 代理设置不展示或查询策略历史。两组策略只保存当前配置与并发版本，不写策略修订和策略变更审计；结算以投注时由数据库捕获的不可变规则快照为依据，不再查询策略历史。代理节点记录、资金流水和幂等回执继续保留。

### 账号术语

用户端、品牌后台和总后台的界面标签、占位符、筛选、确认及错误提示统一使用“账号”（英文 Account），不再使用“用户名”或“账户”。API字段、程序标识符和标准 autocomplete="username" 保持协议语义。

系统默认通知使用 `shared/src/notification-catalog.ts` 的中英文目录；数据库模板和通知内容只保存 `i18n_key`、`i18n_version`，事件参数单独保存在 payload。三端统一解析同一目录，未知 key、版本及混合格式明确报错。品牌通过内置编辑器自定义的文案使用明确的双语内容格式并按版本保存；修改自定义模板不重写已经发送的自定义内容。

### 用户投注记录

- 写入失败、版本冲突或结果未知不能作为成功关闭依据；保留原有输入、请求正文、幂等键及必要的核对、刷新、原请求重试入口。不得仅凭 HTTP 请求已发出、异步任务已受理或后续只读刷新成功，声称业务已执行完成。成功后的刷新失败须说明读取失败，不撤销已确认回执。
- 字段级校验仍紧邻输入项展示；权限说明、加载/空状态、可供核对的业务明细和详细回执属于页面内容，不转换为短暂提示。错误提示旁的恢复操作按钮可保留，接口结果正文由 Toast 展示。

- 提示保存双语消息或捕获的消息及其语言格式化函数，切换语言更新显示，不重发操作。新增文案进入现有中英文目录；不得直接展示服务端原始错误。
- 验收同时检查提示实际位置、成功后弹窗消失、列表刷新、失败恢复和幂等重试，并覆盖中英文、安卓/iOS 横竖屏及 320 CSS px 重排。`tests/static/admin-operation-feedback.test.mjs` 防止旧的右上角提示及页面内操作成功条重新出现。

投注页不可投注状态（尚未开盘／已封盘）使用同一共享 Toast，仅以红色语义文字在视口正中央显示，不展示标题和关闭按钮，使用统一浅色底避免文字与页面内容重叠，持续显示至恢复可投注，离开投注页时清除；不在期次栏下重复提示。其他操作结果保持右下角。

### 三端接口错误提示

- 用户端、品牌后台、总后台统一使用 `shared/src/public-api-errors.ts` 的错误分类和中英文目录，通过当前 i18n 的 `errorMessage(cause)` 创建消息，渲染时用 `displayError(message)`（品牌后台也可用既有 `display`）。保存双语消息而非翻译后的字符串，切换语言不重新提交请求。
- 禁止把接口 `Error.message`、错误码、HTTP 状态号或“未识别的接口错误”直接显示在错误框、弹窗、toast 或任务失败提示中。代码与原始原因保留在错误对象、服务端日志和必要的诊断数据中，不拼接进操作提示。
- 优先保留实际业务含义：积分不足、已封盘、角色被使用、权限不足、状态变化、超出限额等有独立提示。未分类错误明确提示操作未完成；网络失败或服务端结果无法确认时，不能声称成功或确认失败。
- 只读刷新失败使用 `errorMessage(cause, 'read')`，不能让已确认的写入回执变成“提交结果未知”。写入结果未知继续保留原请求、原幂等键和原有复核、重试限制，不自动换键、不重复提交。
- 错误提示仅负责呈现，禁止通过修改权限、品牌范围、业务状态、余额、版本或跨期校验来消除报错。新增页面必须复用此入口；静态检查防止重新引入原文或错误码拼接。


### 三端关联信息展示

- 品牌后台和总后台的系统管理员（`is_bootstrap`）角色统一只读：角色名称可点击查看详情，不显示“系统内置角色，不可修改”等只读说明，也不显示编辑或删除入口。名称、状态和权限均不可通过角色编辑接口变更，非内置角色仍遵循原有授权、版本及关联校验。

- 关联角色、品牌、彩种、玩法、期次、会员、代理及操作人，统一显示名称、具体期号或账号名；不得在列表、选项、详情、确认提示中用内部代码、UUID 或 ID 代替名称。内置系统管理员角色按当前语言显示名称。订单号、审计编号及有业务用途的推荐码保留。
- API 成功响应的 `associations` 只投影本次已授权数据中的结构化关联字段，不解析审计快照、请求正文或规则定义里的任意 ID，不提供任意 ID 查名称的公共入口。投影不修改原始业务 DTO、报表分组键、CSV、冻结请求或幂等摘要。
- 三端 API 客户端通过 `readApiJson` 读取响应，页面复用 `AssociationName`、`associationLabel`、`associationGroupLabel`。名称元数据绑定本次响应对象，不按 ID 全局缓存，不写入浏览器存储；复制展示对象时用 `copyAssociationNames`，不能把展示数据混入提交正文。
- 名称缺失或读取失败时显示对应语言的明确提示，不回退显示内部代码、ID 或伪造名称。名称投影失败不改变已经确认的写入结果。界面切换语言时重新渲染，不重新提交业务操作。
- 创建代理、推荐码等关联表单按账号名精确选择；查询仍要求目标操作原有权限和品牌范围。提交继续使用原来的 ID、版本和幂等键，原有权限、关联一致性、余额及状态校验不变。普通表单不得要求操作者输入内部 UUID。
- 新页面及关联字段必须遵循上述规则；机器可读导出、审计原始快照、规则定义及冻结请求诊断数据与面向用户的关联标签分离，不修改其业务含义。
- 权限名称目录必须覆盖迁移注册项及 `backend/cmd/platform/admin.go` 初始化的内置角色权限，不能只检查 SQL 迁移。缺失翻译须由测试提前发现，不得用原始权限代码兜底。账号管理浏览器回归须覆盖“查看内置角色详情 → 关闭 → 新建账号 → 分配角色 → 提交”，并断言无页面渲染异常、正确品牌范围及单次提交，避免详情渲染失败连带破坏后续弹窗。

## 2. 全局设计令牌 (Design Tokens)

### 筛选栏与关联信息

- 控件选项、占位提示或相邻操作已明确表达用途时，不重复显示字段标题（如顶栏品牌选择、全部彩种筛选和带搜索提示的搜索框）；控件仍须通过现有 i18n 提供无障碍名称。日期范围、金额、密码及仅显示“全部”的筛选等仍需标题才能区分含义的字段保留可见标签，不统一隐藏所有表单标题。

- 筛选栏复用所属面板的边界和留白：`ManagementList` 的筛选表单放入 `filters` 插槽，与右侧动作共用工具栏的 12px 内边距；普通内容面板沿用 `console-panel` 的既有留白。不把 `.panel` 混在 `.ui-filter-bar` 自身，也不靠页面局部 padding 覆盖公共筛选规则。验收检查控件与外框间距、字段互不重叠及实际视口无溢出。开奖结果短屏允许筛选区独立纵向滚动，记录区至少保留 80px，分页不得被底部导航遮挡。
- 所有列表、报表、审计和明细筛选栏使用共享紧凑布局：控件按内容宽度从左向右排列，查询按钮与控件同行并底部对齐，空间不足再自然换行，不使用等分 Grid 或宽输入框制造多行。文字输入通常为 168px，日期控件通常为 148px，实际容器较窄时可收缩；保持 320 CSS px 重排和触屏操作区。
- 筛选日期统一使用共享日期控件的 `date` 模式，结束日期包含当天，转换为次日零点的排他结束边界。各接口原有 UTC 或本地时间解释以及查询上限必须保留，查询、翻页和导出复用同一已确认范围。业务排期、开奖等操作表单仍按业务所需精度处理。
- 彩种、会员、代理、佣金周期、奖励/投注记录、期次和操作人等关联筛选必须按名称、账号、日期窗口或明确期号选择，禁止手填内部 UUID。请求仍传内部 ID；请求编号等有明确排查用途的业务编号不属于关联名称输入。
- 关联选项使用 `FilterAssociationSelect.vue` 和当前端的 `/filter-options`，继承目标页面读取权限与当前品牌隔离，不要求额外会员浏览权限，不开放通用全库名称查询。多于一页必须提供更多选项入口；读取失败显示本地化错误及“重试”，不得静默按空列表成功。
- 切换品牌、账号或权限时清空旧选项、取消旧请求并拒绝迟到响应；卸载时取消读取。选项展示不改变后端原有权限、余额、幂等和审计规则。

### 四端表单结构（共享实现）

- 用户端、品牌后台、总后台和代理端的列表筛选容器统一使用 `.ui-filter-bar`，编辑表单使用 `.ui-form`，提交/取消区使用 `.ui-form-actions`；规则由 `shared/src/controls.css` 维护，页面不再独立定义同类表单的间距、边框、按钮铺满或对齐方式。
- 账号搜索统一复用 `DirectorySearch.vue`，使用普通搜索输入和简洁的“查询”按钮；清除与刷新按实际需要提供。筛选栏不额外套卡片、装饰图标或大段说明，使用所属内容面板的背景与边界；字段间距 10px、与后续内容间距 12px；年份等简短单选标签需同行时使用共享 `.ui-filter-field-inline`，不另写局部几何规则；高度不超过 450px 的横屏统一缩为 4px 行间距和 4px 底部间距，保留触控高度。文字输入 168px、日期 148px，空间不足自然换行。

- 编辑表单字段间距 12px，标签与输入间距 6px；保留业务分组及必要的复选框行结构。提交/取消按钮靠右、按文字自然宽度排列，窄屏可换行但不拉满整行。所有控件沿用统一颜色、圆角、桌面 32px 和触屏 44px 几何令牌。
- 同类弹窗继续复用 `DetailModal.vue` 与共享创建字段、选择器、校验和操作组件；普通单栏创建、编辑与申请弹窗统一使用 `.ui-form-dialog`（上限 520px），表格明细和复杂分组沿用对应内容宽度；关闭按钮统一为无边框样式、16px 图标及桌面 32px / 触屏 44px 点击区，不继承各页面导航图标按钮的外观。登录、验证码、投注选号及投注确认的专用业务布局按对应章节执行，不通过通用表单规则改变其操作流程。

### INPUT、SELECT 与 BUTTON 宽度（四端统一）

- 四端及共享组件的单选统一使用 `shared/src/SelectControl.vue`，禁止新增原生 `<select>`。组件接收字符串、数字或布尔值的 `modelValue`、`options`（`value`、本地化 `label`、可选 `disabled` 和分组 `group`）、本地化无障碍 `label`、`disabled`、`required` 和 `name`；选择保留值类型，先触发 `update:modelValue`，值变化后再触发携带新值的 `change`。业务处理器直接接收新值，不再读取原生事件的 `target.value`。
- 触发器按最长选项及箭头确定固有宽度，复用 `--control-height`、颜色、圆角和阴影令牌；桌面 32px，移动端及粗指针 44px，移动端文字 16px。选项使用顶层 Popover，随视口空间向上或向下展开，长列表限高滚动、长文本换行，避免被底栏、弹窗或滚动容器裁切；支持分组、禁用项、键盘导航、输入字符定位、确认、Escape 取消及外部关闭。
- 必填选择使用组件内的校验字段参与表单约束，并由共享 `vInlineValidation` 显示当前语言错误和标记可见触发器；空值或已不存在的选项不能通过必填校验。`false` 和 `0` 为有效值。组件和父级 fieldset 的禁用状态须阻止操作及表单校验；关联筛选继续使用 `FilterAssociationSelect` 原有品牌/权限隔离、分页、失败与重试流程。当前单选不提供搜索或多选。
- 所有 SELECT 按选择项内容、内边距和下拉箭头所需的最小固有宽度显示，以最长选择项能正常显示为基准；不得固定为 200px、280px 等宽度，不得用 `width: 100%`、固定最小宽度或 Flex/Grid 拉伸填满整列。
- 四端统一由 `SelectControl.vue` 实现内容固有宽度、`min-width: 0`、`max-width: 100%` 和不扩张的 Flex 行为，业务页面复用，不另写控件外观或放大尺寸覆盖。
- 选项较长或屏幕较窄时限制在实际容器内，筛选项自然换行；保留字体、内边距、箭头空间及移动端 44px 触控高度，禁止靠缩小字号或页面缩放压窄控件。
- 筛选栏优先紧凑同行排列，INPUT 按实际输入内容设置合理宽度；日期范围按天选择，结束日期包含当天，接口使用次日零点的排他结束边界。保留各业务已有的时区规则。

- 桌面精确指针视口（大于 900 CSS px）普通输入框默认 28ch，邮箱和 URL 为 40ch，电话为 24ch，数字与金额为 16ch，日期为 20ch，一次性验证码为 12ch。按已知字段内容可通过 `--input-width` 调整；筛选框继续使用现有 168px 紧凑规则，日期组合控件保留自己的内部布局。不用 `width:100%` 或 Flex/Grid 扩张输入框。移动端保留自适应宽度、16px 输入字号及 44px 触控高度。
- 三端动作按钮统一使用 `.button` 加主、次、危险等语义变体；桌面按文字与内边距定宽，禁止拉伸铺满表单。图标、文字菜单、导航和号码选择继续使用各自的统一控件结构。所有普通动作按钮只过渡颜色、边框和阴影，Hover 不移动、不切换渐变图。
- 代理新增、层级配置、策略和详情弹窗采用单栏，宽度上限 520px，窄屏按实际视口收缩；子表单也不使用双栏。

### 3.1 彩票号码球 (Lottery Balls)
彩种选号、开奖结果及订单快照中的号码球统一具备拟真 3D 放射高光与立体阴影（由 `shared/src/mark-six-balls.css` 统一维护，禁止使用紫调属性色）：
- **红波（Coral Red）**：`--lottery-wave-red: #f43f5e`（高光 `#fda4af` → 暗部 `#9f1239`）
- **蓝波（Ocean Blue）**：`--lottery-wave-blue: #0ea5e9`（高光 `#bae6fd` → 暗部 `#2563eb`）
- **绿波（Electric Jade）**：`--lottery-wave-green: #10b981`（高光 `#6ee7b7` → 暗部 `#065f46`）
- **特别/金球（Champagne Gold Halo）**：通过 `--accent`（`#f59e0b`）金色外圈光环标记，数字使用 `--font-mono` 与 `font-variant-numeric: tabular-nums`。
- **选号器未选中球（默认态）**：
  清晰边框、高对比数字，Hover 时呈现翡翠色轮廓。
- **排除号码球**：
  浅红底色（`#fff1f2`）、玫红边框、删除线文本。

六合彩号码球统一复用 `MarkSixBall.vue`：红波、蓝波、绿波分别使用 `--lottery-wave-red`、`--lottery-wave-blue`、`--lottery-wave-green` 及对应浅色令牌。这些颜色仅表示号码属性，不改变页面品牌主色。号码与波色、生肖、五行的对应关系由总后台按年度及生效区间发布，组件必须读取对应期次或注单的属性快照，禁止硬编码号码映射。开奖特码通过金色外圈标记；选中态使用卡片背景和边框，不覆盖波色，不再显示复选框或勾选图标。

### 3.2 按钮体系 (Buttons)
- **主操作按钮 (`.button-primary`, `.button-dark`)**：
  统一主色底、白色文字与共享阴影，Hover 只加深颜色和阴影，尺寸与位置保持不变。
- **次级按钮 (`.button-secondary`)**：
  纯白底色，`1px solid var(--line)` 边框，Hover 时淡灰高亮，避免刺眼反差。
- **幽灵按钮 / 文字链接 (`.button-quiet`, `.text-link`)**：
  透明底，翡翠绿字，用于紧随卡片的跳转行动。

#### 三端图标

- 三端统一使用 `@lucide/vue`，通过 `@lottery/shared/SiteIcon` 按需导入的图标映射复用；禁止在导航与常用操作中混用 Unicode 字符、Emoji 或另画 SVG。
- 所有操作、语言切换、导航和辅助箭头图标默认统一为 20×20 CSS px；品牌后台与总后台的紧凑界面由共享 `.management-console` 统一设置 `--site-icon-size: 16px`。几何尺寸由 `SiteIcon` 读取该令牌，页面不得自行传入其他尺寸或覆盖描边。描边统一为 1.75px、圆角端点，继承 `currentColor`。图标与文字居中对齐，不用字体基线模拟对齐；缩小图标不缩小移动端 44px 触控区域。
- 语言切换使用 Lucide `Languages`（文/A），与刷新按钮共用 `--icon-control-size`，后台该令牌引用文字按钮（如“新建品牌”）使用的 `--console-control-height`：后台桌面精确指针视口为 32×32px，与普通文字按钮同高；触屏及窄屏为 44×44px。两者均为 10px 圆角方形、白底细边框，不使用圆形外框。
- 装饰图标使用 `aria-hidden`，图标按钮必须保留本地化的可访问名称；不能把可读标签仅替换成无名称图标。
- 三端入口先导入 `shared/src/styles.css`，业务样式之后导入 `shared/src/controls.css`；按钮和输入框使用共享圆角与配色，移动端触控高度至少 44px、文本输入字号 16px。

#### 四端数据刷新按钮

品牌后台、总后台和代理端的常驻页面级刷新统一置于列表上方 `.console-page-heading` 内的 `.console-page-actions`，靠右排列；不放在分页底部或左侧独立工具行。局部区块与详情刷新置于所属区块标题右侧，错误恢复留在对应错误场景；已有查询/筛选按钮的同一列表不重复提供常驻刷新。四端均复用共享刷新指令和样式，代理端与后台采用相同尺寸。

用户端页面级刷新按钮统一通过 `<Teleport defer to="#user-page-refresh">` 放入 `Page.vue` 顶部导航栏的唯一刷新插槽，沿用原页面的点击处理、加载禁用条件及本地化标签，不使用整页 reload 或同时刷新多个页面。切换路由、注单分类后由组件生命周期移除旧按钮，不保留上个页面的刷新动作。钱包概览、积分明细、变动记录、注单、消息、开奖结果、充值、提现和彩种目录遵循该规则；没有页面级刷新动作的页面不显示按钮。嵌入式区块、验证码换图和只刷新局部注单等操作不迁移。移动端删除或隐藏原来仅容纳刷新按钮的工具栏，不留下空行、不增加导航高度；共享组件按 `surface` 明确区分，品牌后台和总后台保留其原操作位置。

用户端使用下述彩种工作区导航，不再在顶部重复堆叠积分、消息、语言和刷新按钮。刷新仍使用唯一 `#user-page-refresh` 插槽，位置移到半屏菜单内；关闭菜单时插槽保持挂载，不能丢失当前页面的刷新动作。

#### 用户端彩种工作区

- 首页直接展示上次选择的彩种；选择按品牌 ID 保存在本地。首次没有记录时选择目录首个开放彩种；已保存但不可用时明确提示重新选择，不静默切换。
- 顶栏首页左侧显示品牌，非首页显示上级返回图标；彩种名称和下拉按钮以整条顶栏的几何中心居中，左右使用等宽布局区域，手机、电脑及横竖屏均保持一致；品牌靠左、菜单靠右，长名称在各自区域省略并保留完整标题，不能挤偏彩种或覆盖相邻控件。彩种浮层每行三列，只显示名称，不显示内部代码。右侧菜单从左侧滑出，宽度为视口的一半；消息、语言、页面刷新和帮助集中放在这里。
- 半屏菜单顶部操作区按“语言、刷新、关闭”排列，语言和刷新不放在菜单列表底部。窄屏品牌名称独占一行，三个图标保持同排、44px 触控区域；语言下拉相对菜单标题区展开，宽度限制在菜单内，不能因向左偏移被裁切。
- 顶栏下的账号概览通过箭头展开/收起，箭头随面板位于底部。三列为积分、未结金额、今日输赢。后两项由 `GET /api/v1/betting-summary` 在后端汇总当前品牌、当前会员的全部彩种；统计日期按平台时区，牛牛输赢使用实际输赢而非最大冻结金额。积分继续使用原钱包快照，不能将读取失败显示成零。
- 账号概览保留三列，每列的标题与数值优先同行居中展示，减少面板高度；长金额或翻译确实放不下时自然换行，不截断数值、不缩小字号。
- 未登录访问首页、彩种、注单、钱包或个人等业务页时，必须先校验真实会话并跳转登录页，不展示业务导航、不读取彩种列表。登录、注册、隐私和条款页可公开访问；校验中的服务故障明确显示错误与重试，不当作未登录。用户端不提供规则草稿导入、预览等开发工具。已保存彩种失效时保留明确提示，并提供“选择彩种”按钮打开列表；只有目录读取失败才使用“重试”。
- 开奖横条直接展示具体已开奖期号，不显示“上期”占位标题；当前期展示期号、封盘时间、开奖时间。封盘前倒计时指向封盘，封盘后指向开奖，所有钟点遵循平台显示设置。
- 当前期信息优先同一行展示；倒计时仅显示数值，阶段含义保留在无障碍标签中。期号旁不放日历或期次选择图标，当前彩种的开奖结果入口放在菜单中，不改变正常期次衔接逻辑。
- 工作区六合彩开奖结果在每个号码球下展示对应生肖（含特别号），使用该期开奖结果自带的生肖映射和当前界面语言；不能用当前待开奖期或本机年份重新计算历史生肖。仅影响开奖结果横条，不恢复投注卡片上已移除的生肖/五行附注。
- 玩法帮助放在顶部导航当前彩种名称右侧，选号区不再占一行；每注最低/最高积分放在投注预览层。积分、未结金额、今日输赢概览及其折叠柄仅在首页和投注页显示，其他页面不渲染。概览开关使用居中的小折叠柄，不使用整行按钮；视觉高度缩小，但保留 44px 触控区域。
- 投注区左侧纵向分组，右侧选号。未选号不显示“未选择项目”、零注数底栏或空占位；六合彩连续点选只更新 `MarkSixDraft` 底部汇总，不自动弹层；点击汇总在同一位置展开核对，收起保留项目和金额。其他引擎沿用 `BettingSheet` 居中确认弹窗。只有明确点击确认投注才允许写入订单；保留服务端报价、身份校验、请求快照和未知结果原键重试。
- 六合彩底部核对层为非模态区域，不锁页面滚动、不遮四个主导航入口。实际高度为选号区和玩法分组预留空间，短屏允许内容滚动；展开/收起按钮提供 `aria-expanded`，Esc 收起。首项选择固定该批次期号和所见赔率；轮询切期后保留旧项目供查看/清空，禁止自动迁入新一期。报价变化仍在原层再次明确确认。未加入的组合切换分组或子玩法时，须明确确认放弃；重复组合拒绝后保留候选号码。
- 各彩种选号区不再提供独立的“快捷选号”面板或金额输入，包含六合彩组合玩法。投注积分仅在底部确认层填写；多项投注保留统一金额输入及“应用到全部”，同时允许逐项调整。通用规则彩种按自身单位积分/倍数模型在固定底栏填写，不改变计价规则；请求结果未知时仍锁定原始金额和请求快照。
- 通用规则彩种的固定底栏展示可用积分、已选数量和实时总投注积分；盘口、每注积分的标签与控件同行，“清空”和“投注”并排，窄屏不为清空单独增加一行。每注积分初始为空，按品牌与会员在当前浏览器记忆最近一次有效输入或快捷选择；已选数量放在每注积分输入框后面，输入框内容宽度为 6 个字符；仅点击积分输入框时在上方以不同颜色的筹码展示常用积分，点击标签或键盘聚焦不打开快捷菜单，浮层宽度按筹码数量收缩，始终对齐积分输入框上方居中，靠近视口边缘时保持 8px 边距。常用积分按当前品牌与会员保存到服务器，WEB、移动端及换设备登录共用；不读取浏览器里的快捷积分副本。个人设置支持添加、编辑、删除最多 5 个正整数常用积分，常用积分范围为 1～999999，筹码随 2～6 位数字逐级增大，同排筹码按垂直中心对齐；快捷浮层筹码间距为 12px，预留选中外圈，选中与悬停不缩放筹码；一位数沿用最小尺寸，完整显示数值；管理筹码聚焦时使用浅色背景和强调边框；空筹码显示居中的闪烁插入光标，输入后切换为原生文字光标，避免重复光标。管理区固定展示 5 个可编辑筹码，未设置的显示空值筹码，输入和删除仅编辑当前草稿，点击统一“保存”按钮后写入服务器；保存期间禁用编辑，失败保留草稿并允许重试，数字校验错误使用 Toast 提示，右上角红色关闭图标点击删除；不另设添加按钮，不常驻展示规则说明，WEB 与移动端共用设置组件，触屏输入和操作至少 44px，并保持 320 CSS px 无横向溢出。
- 多项投注确认层中，“投注积分＋输入框＋应用到全部”同排展示；投注项采用“名称＋金额输入＋删除图标”的紧凑行。删除同步更新选号状态、注数和总额，最后一项删除后关闭确认层。删除图标使用本地化名称和至少 44px 触控区域；提交中禁用，结果未知时不得删除或修改原请求。
- 确认层汇总优先同排显示“可用积分、注数、投注积分”；可用积分和投注积分的数值使用危险色令牌并加粗。按真实语言和数值长度自然重排，不为强制单行缩小字号或裁掉金额。
- 多项投注确认层底部“清空、确认投注、继续选号”使用同一行等宽操作区，不为继续选号单独占一行；顶部统一金额输入框与逐项金额输入框等宽，不拉伸填满空白。登录、重试、重复上次选号等既有状态入口沿用原语义，在同一操作区按实际按钮数分配宽度，保留至少 44px 触控高度。
- 各彩种只使用一个确认层，不再让用户先点击预览、再打开另一层确认。六合彩和加拿大在确认操作中先请求服务端报价，与所见期号、版本、金额、展开后的项目赔率（含特殊档位）及冻结积分比较，一致才继续提交；变化时在原层显示服务端新明细，必须再次明确确认，不自动接受变化。通用规则彩种在选号完整、倍数有效时静默计算服务端金额并显示在当前层，确认时重新核对报价；只读自动计价不能触发订单，也不显示全局加载。
- 校验与提交期间锁定可编辑内容并防止连点。身份或页面作用域变更、迟到报价、校验失败、封盘均不得继续下单；未知写入结果仍使用保存的请求体和原幂等键重试，不重新报价或生成新键。前端流程测试只使用合成接口，不能用真实会员点击确认投注来验收。
- 彩种面向会员只显示名称；投注项目卡片只展示名称（或号码球）与赔率，不显示内部代码、生肖/五行附注及对应号码列表。详细规则在帮助中查看，组合玩法的必要选号操作和最终投注核对仍保留。
- 投注项目卡片的赔率统一加粗（700），沿用现有字号和颜色令牌，不在各彩种另设字体样式。
- 正码特位置选择、连码等组合玩法与其他玩法的子类型下拉不重复显示“正码位置”“具体玩法”等说明标题，保留当前选项和本地化无障碍标签。
- 正码过关使用六个位置切换按钮与当前位置的项目卡片，不使用六个下拉框。每个位置最多一项，点击已选卡片取消，切换位置保留选择；卡片只显示名称和赔率。缺少赔率、未开放销售、封盘及提交锁定仍禁止选号，不自动补赔率或绕过销售校验。
- 投注卡片使用原生 `button type="button"`，点击整个卡片切换选中/取消，以 `aria-pressed` 表达状态并支持键盘 Enter/Space；不用可见或透明覆盖式复选框。选中态统一用设计令牌背景与边框区分，封盘、提交中及未知请求重试期间保留原禁用保护。
- 六合彩A/B盘口在选号区明确展示；切盘保留选号并更新对应价格。正码过关使用六个位置单选控件，至少2关、最多6关；确认层显示盘口及每关购买赔率。玩法说明采用概览、49速查、分组折叠条目和本期属性四层结构，不能合并成整块长文。
- 底部“首页、注单、钱包、个人”四个入口保持不变，不复制到菜单或投注内容区。新彩种页面复用 `UserPeriodStrip`、`BettingSheet`（六合彩使用 `MarkSixDraft`）和工作区布局，不另造导航/金额汇总/时间格式。

- 设置页读取失败或版本冲突后的“重新读取”按上述设置页规则保留文字入口；此例外仅适用于明确的错误或冲突状态，不适用于常驻刷新和未知写入重试。
- 不常驻提供低实时性页面或历史记录的刷新按钮。任务记录、账号与角色、通知模板、报表归档、审计日志、通知、奖励及其操作历史在进入、打开、查询、翻页或操作成功时读取；失败时才显示重试。已有轮询的投注记录和开奖概览不再重复提供常驻刷新，也不为删除按钮新增轮询。
- 充值待处理、提现审核、待结算注单和计算中或发放中的佣金保留必要的更新入口；完成状态隐藏。用户端开奖记录只在当前日期的快彩或读取失败时提供刷新。钱包去除流水的常驻刷新，总后台余额保留单一入口。验证码换图、认证恢复、读取失败及版本冲突后的重新读取继续保留。
- 所有“刷新/重新加载当前数据”的原生 `button` 必须使用共享 `v-refresh-button="本地化标签"`（从 `@lottery/shared` 导入）。四端统一导入 `shared/src/refresh-button.css`，不得在页面另画刷新图标或自行设置刷新按钮外观。
- 使用 Lucide `RefreshCw` 循环箭头，沿用上述共享图标和控件尺寸：后台桌面按钮 32×32px、图标 16px；后台触屏及窄屏按钮 44×44px、图标 16px；用户端按钮 44×44px、图标 20px。统一 10px 圆角、设计令牌配色、外边距 0，所在操作组间距 12px。正文标签视觉隐藏但仍提供当前语言的 `aria-label` 与 `title`，语言切换同步更新；不使用缩小到不可读字号的方式隐藏标签。
- 指令保留原生点击、禁用、焦点、权限和幂等流程，不触发任何额外请求，不把错误重试或未知写入重试改成普通刷新。加载期间按钮保持原尺寸和原禁用条件，页面进度继续使用全局加载组件。
- 验证码换图、Telegram 验证挑战的“刷新”也使用同一图标，标签需明确具体用途，保留各自原有的点击行为。查看历史、确认丢弃意图和写入重试不是刷新，不套用刷新图标；兼有“查看历史/刷新历史”的控件需拆成条件分支，只有刷新分支使用该指令。
- `scripts/refresh-button-audit.mjs` 与 `tests/static/refresh-button.test.mjs` 约束四端及共享业务组件接入；中英文、44px 触控区、图标可见、键盘焦点和禁用行为须回归验证。

### 3.3 卡片与面板 (Cards & Panels)

- 文本输入的 placeholder 只说明填写内容，不重复字数限制或编码术语。需要长度限制的 textarea 在右下角显示 `当前字符数/上限`；品牌运行状态当前不提供原因输入框；其接口仍允许可选原因，上限为 500 个 Unicode 字符，前端计数、API 校验与数据库约束使用同一口径（中文和单个 emoji 都计为一个字符），不得按 UTF-8 字节计数。

- 卡片内部采用规整的内边距（桌面端 20px~26px，移动端 14px~16px）。
- 数据标签（`<dt>`）与数值（`<dd>`）统一对齐，长哈希或长编号必须带有 `overflow-wrap: anywhere`。

### 3.7 管理端共用框架

- 品牌后台和总后台统一导入 `shared/src/management.css`，置于各自业务样式之后、共享 `controls.css` 之前；已登录外壳统一标记 `management-console`。共用侧栏、顶栏、页面标题、列表密度、筛选区和移动端空间规则，不再在单端复制一套基础框架。
- 品牌后台保留品牌名称、Logo、favicon 和语言配置；管理操作界面采用系统默认设计令牌。品牌展示配置中的自定义配色、字体等仍保存并作用于用户端，不修改其配置或历史记录。
- 品牌后台使用当前管理入口 `/api/v1/context` 识别的品牌，并核对当前账号的品牌授权与授权品牌目录；不显示品牌选择器，不保存手工选择，不取授权目录的首个品牌。入口品牌读取失败或不在账号授权范围时明确阻止业务页面加载，不向其他品牌发起业务请求。品牌名称与 Logo 显示在侧栏标识中，不显示“运营控制台”副标题；首页作为独立导航入口，不设“概览”分组，不再提供与首页重复的“运营工作台”页面；总后台需要品牌上下文的页面统一在顶栏语言切换器之前显示品牌选择器，不在页面内重复展示；品牌目录、平台账号与平台设置的基础、佣金结算页签等平台级页面不显示；平台设置的登录页签按配置范围提供品牌选择。窄屏下品牌选择器独占顶栏第二行，保留本地化无障碍名称、中英文选项文案和操作锁定，不重复显示“品牌”标题；顶栏与账号菜单均不展示账号角色，角色信息仅在个人资料中展示。账号操作集中在顶部账号菜单，个人信息和修改密码使用共享 `DetailModal`，保留焦点约束、Esc 关闭和动态视口内滚动；密码提交处理中不得关闭。
- 会员页默认展示列表，新建表单通过列表面板工具栏入口展开；表单收起保留本页输入，权限判断和创建流程不变。手机端会员列表按字段重排为卡片，保留全部业务字段和操作。
- 品牌后台积分和账本统一从会员列表操作菜单打开弹窗，自动带入当前会员，不重复显示会员目录或查询表单。关闭后保留列表筛选与页码，积分写入成功后刷新当前列表；提交中及结果未知时禁止关闭，未知结果保留原请求及幂等键，并提供“重试原请求”。两个入口要求当前品牌的会员查看与钱包查看权限，不自动补授权限。充值记录和提现申请保留独立入口；资金策略位于品牌设置的“资金”页签，移动底栏保留首页、会员和彩种及更多菜单。充值、提现及结算操作从对应业务分区进入。视图切换使用既有组件实例，保留筛选、草稿和原请求重试状态；不能通过切换视图重新生成资金请求。充值列表先展示摘要，详情展开后才显示原有确认和取消表单。
- 品牌设置按运行状态、品牌展示、资金、提现设置、投注限额、代理设置及通知模板分区；期次开奖按排期、开奖、结算、更正、取消退款分区，默认显示日常排期。切换时保留原组件实例与操作状态；更正页的结算跳转仍带入原期次。
- 顶栏不提供按菜单名跳转的“查找管理页面”；用户、订单和资金查询保留在各业务页面。成员编辑、踢出和密码重置复用共享 `DetailModal`，保留原权限、业务必填字段和提交校验；提交中阻止关闭。
- 会员钱包的来源明细及对账明细按需展开，对账不一致时明细默认展开，异常提示始终可见。充值和提现列表在窄屏重排为带字段标签的卡片，详情内容不得裁切。期次记录优先显示，排期配置和生成期数通过折叠区进入，收起不卸载草稿。
- 注单页优先展示查询及列表，投注限额通过“品牌设置 → 投注限额”页签进入。后台中英文文案、名称投影、资金幂等和品牌权限规则继续沿用既有实现。

### 3.8 平台、品牌、代理列表页统一契约

本节统一三个管理端的页面结构和操作位置，适用于目录、业务记录、报表及弹窗内列表。相同能力使用相同结构；功能是否提供由已有业务接口和精确权限决定，不能以页面作者偏好决定，也不能为凑齐按钮新增删除权限。既有页面改动和新增页面均须执行，不能仅统一颜色或组件名称。

#### 固定结构与容器

```text
公共顶栏：面包屑 / 当前品牌上下文 / 语言 / 账号
页面标题区：唯一页面标题（公共导航已展示时不重复）
列表面板（一个外层边框、圆角、阴影）
  工具栏：有筛选时，左侧查询字段 → 查询 → 清空，右侧新建等全局动作；空间不足自然换行
          视图页签位于筛选操作行之前；无筛选时与右侧动作同行
  汇总区：仅业务确实需要的完整查询范围汇总
  批量区：全选 + 已选数量；右侧批量动作
  表格：识别字段 → 业务字段 → 状态 / 时间 → 操作
  分页区：左侧条数摘要；右侧翻页、跳页、每页条数
```

- 共用 `ManagementList` 提供上述容器、工具栏、筛选及汇总插槽；表格复用 `ManagementTable`，分页复用 `TablePagination`（`PaginationControls` 为同一分页组件的参数适配）。不为单页另造列表壳。批量区域由共享批量组件输出，与表格和分页同属该面板。
- 筛选与全局动作由共用工具栏统一布局，不得在宽度充足时将右侧动作另放在筛选栏上方。工具栏、表格、分页是面板内的平级功能区。禁止新建按钮游离面板、页签独立套白色卡片、表格再套一层带边框面板，或表格与分页分属不同卡片。详情、编辑表单和独立业务分区保留各自边界。
- 页签仅切换视图；新建、导出、刷新属于动作区，不混入 `tablist`。没有页签或动作时不渲染空工具栏，没有筛选、汇总或批量能力时不留占位空行。
- 面板与表格边缘一致，筛选、工具栏及批量区沿用共享 12px 内边距；表格和分页不叠加第二层 16px 留白。统一令牌、字号、行高、浅色表头及控件高度，页面不得重写列表基础密度。已有复杂业务表格可保留专有列和分组，但仍执行区域顺序及单一容器规则。

一期各端页面不提供业务数据导出、归档文件下载或规则配置导出入口，不显示导出确认、回执或导出授权提示。

业务报表的汇总指标使用共享 `report-summary-tags` 紧凑标签块，标签与数值相邻并按实际宽度换行，不重复“整个筛选时间范围汇总”“分组数据”标题。查询区提供“显示汇总”“显示明细”复选框，默认都选中；仅改变当前报表的呈现，不重新读取或改变统计口径，隐藏明细时同时隐藏分页，两项均关闭时不显示结果区域。

#### 功能适用规则

| 列表类别 | 分页 | 全选与批量动作 | 行操作 |
| --- | --- | --- | --- |
| 平台品牌目录 | 完整分页，使用完整品牌目录的筛选结果分页 | 有品牌删除权限时提供批量删除，沿用品牌删除影响确认 | 名称识别；更多菜单承载成员、账号、域名、状态及删除等授权操作 |
| 平台账号 / 角色、平台管理的品牌账号 / 角色 | 完整分页 | 已支持删除的对象提供批量删除；当前账号、内置角色及其他受保护对象不能选中 | 统一更多菜单；详情、编辑、改密、删除按授权出现 |
| 品牌后台管理账号 / 角色 | 完整分页 | 当前业务只有编辑、改密时，不添加删除及无用复选框 | 使用同一更多菜单结构，保留现有授权和只读限制 |
| 平台 / 品牌会员目录 | 完整分页 | 有删除权限时提供全选、已选数量及批量删除 | 会员名称打开详情；更多菜单承载积分、账本及删除等授权操作 |
| 品牌代理目录、代理端会员 / 下级代理 | 完整分页 | 没有现有批量业务时不显示复选框；不擅自新增删除 | 查看、下级、编辑等已有操作保持同类入口；只读列表保持只读 |
| 注单、资金流水、审计、报表、归档等记录 | 按接口采用页码或游标分页 | 不提供记录删除；已存在的批量业务使用相同批量区域 | 查看 / 业务动作，保留各自权限和资金确认约束 |
| 设置表单、固定枚举、详情字段 | 不冒充分页列表 | 不添加选择和批量删除 | 保存、取消按表单规范 |

#### 选择与批量处理

- 可见文案统一为“全选 / Select all”，选择范围为当前页可操作记录；不隐含跨页或整个查询结果选择。该范围写在本规范，不增加常驻说明文案。
- 有批量业务且有权限时才显示复选框和批量区；部分选中使用半选状态。零选中禁用批量动作；无数据不显示批量区。翻页、应用查询、切换视图或品牌后清空选择，禁止把旧范围选择带入新页面。
- 已选数量只统计可操作记录；当前账号、内置角色等受保护对象不可选，全选也须排除。无权限时隐藏入口，服务端仍须逐对象验证权限及品牌范围。
- 批量删除必须先确认实际对象及数量，品牌删除保留已有实际影响提示；逐对象保存请求快照、版本及幂等键。成功项不重复提交；失败项明确反馈；未知结果沿用原键原体重试并锁定关闭，不显示整个批次成功。不能用前端隐藏或过滤记录代替真实删除。

#### 分页与查询

- 代理端四个业务页成功空结果隐藏分页栏，保留表头与空状态；有记录时统一使用箭头、页码和跳页控件，不直接显示“上一页 / 下一页”文字按钮。
- 其余管理端可增长的业务列表即使只有一页也展示统一分页栏，不能有的页面仅展示条数、有的页面展示全套控件。四端成功空结果统一隐藏整条分页栏，只保留列表空状态；读取前和首次失败时不伪造零条成功结果。
- 页码接口必须提供真实总数、当前页、当前页条数、每页条数及跳页回调。每页条数显示的是实际生效值，不将静态文字伪装成可切换下拉；不同业务既有的 20 / 50 / 100 条可保留，同一业务跨端使用相同口径或在实现记录中明确原因。
- 一次性读取完整且规模受控的目录允许在前端对完整结果分页，禁止对服务端截断的首批数据冒充完整分页。游标接口只允许访问已获得游标的页面；不能补造游标或把任意跳页伪装成可用。分页等待、失败保留原页及作用域隔离遵循 §5.2。
- 查询动作统一“查询 / Search”；文本筛选输入复用 `ClearableInput`，有值时显示统一的框内 X，清除本字段后保留焦点；隐藏浏览器原生清除按钮，不再重复提供“清除 / 清空 / 重置”按钮。清除输入只更新待查询条件，由查询按钮读取第一页。Enter 与点击查询执行同一逻辑；应用新条件回到第一页。分页使用已应用条件，不能将尚未提交的输入意外带入翻页请求。
- 同一列表有查询就不再堆叠刷新；无查询但支持重新读取时，刷新位于同一面板工具栏右侧。详情和失败恢复按各自作用域显示重试。

#### 内容、行操作与状态

- 名称 / 账号等识别字段在首列，允许点击名称打开详情；“操作”列在末列，使用共享 `MemberActionsMenu`，菜单顺序为查看、常规业务动作、编辑 / 改密、危险操作。相同对象跨端入口位置一致；只有只读数据且无动作时不强加空操作列。
- 状态名称按同一业务语义复用翻译及状态令牌，在线状态与账号状态分列，不混用圆点、胶囊来表达同一字段。金额保持精度、单行及一致对齐，时间使用平台显示配置，缺失字段用“—”，受权限限制的值使用明确的本地化受限状态，不能冒充零或未设置。
- 已有顶栏品牌上下文时不在列表重复品牌；固定角色权限、完整权限集合和技术编号放详情。表头名、按钮和状态全部进入现有中英文目录，不能只改中文。

- 桌面及窄屏维持上述功能顺序；工具栏和筛选按可用宽度换行，表格按既有字段卡片规则重排，分页摘要和动作自然分行。不能隐藏批量动作、分页或必要字段来通过手机验收。

## 4. 新增页面与后续迭代开发准则 (Developer Guidelines)

### 展示型标题和值：优先同行

三端共同加载 `@lottery/shared/key-value.css`。账号信息、积分明细、状态、时间、详情和报表摘要等展示型字段，默认标题在左、值在右，同一行优先；不要为一个短数值单独占用下一行。语义结构优先使用 `dl > div > dt + dd`，平铺的 `dl > dt + dd` 同样遵循该规则；非定义列表使用 `.key-value-row`、`.key-value-label` 和 `.key-value-value`，不再各页面重写上下堆叠布局。

保留各页面既有字号、颜色、卡片令牌和数值精度。列宽受容器约束，长标题、长积分、UUID、网址和正文允许自然换行，不缩小字号、不截断内容、不固定手机宽高。长说明可用 `dd.key-value-wide` 占满整行；包含段落、列表或表格的说明也采用整行。该规范只约束信息展示，不把编辑表单的标题和输入控件强制挤在一行。

钱包四来源的每个状态使用相同同行结构，来源名称仍作为卡片标题；可用、人工冻结、系统冻结、提现中的业务含义和金额保持独立，不因压缩高度而合并。

用户钱包首页 `/wallet` 只展示积分概览及“积分明细”“变动记录”两个入口，不默认展开来源明细或流水，也不请求流水接口。明细位于 `/wallet/buckets`，流水位于 `/wallet/ledger`，各自只展示对应内容，使用现有二级导航返回钱包；不重复积分概览。概览的提现金额标签为“提现积分”，金额仍为原提现中状态的积分，不改变账务含义。

用户流水表格按“类型、积分变动、变后积分、时间”排列，不提供独立明细列或弹窗；变后积分只汇总该笔流水的 `after_snapshot` 可用状态，不能使用当前钱包余额冒充历史余额。普通用户不展示完整 16 桶前值/变化/后值表，管理端与接口保留完整账务快照。钱包与流水页不设置独立五秒轮询，流水仅在进入、翻页、主动刷新时读取；钱包只接收同品牌、同会员、版本未倒退的现有钱包更新事件。顶部积分保持可见页面的低频刷新，后台更新仍静默。

总后台订单详情与操作记录分开加载：先展示当前订单，用户点击后读取历史，历史失败保留详情并提供独立重试；关闭、切换品牌或卸载后，旧请求不得回填当前视图。

### 新增页面检查清单

后续新增业务页面或对已有页面进行维护时，必须执行以下流程：

1. **结构一致**：
   - 平台、品牌、代理列表必须逐项执行 §3.8 的结构、功能适用表和验收清单；复用列表壳、表格、行操作及分页，不能仅复用颜色。
   - 用户端业务页面主标题使用公共顶栏 `.workspace-page-title`，紧邻返回按钮；后台沿用标准标题区 `.page-heading`。副标和说明仅在有实际业务信息时展示。
   - 移动端导航栏已显示页面标题时，内容区不再重复标题、副标题或宣传区；优先展示当前任务需要的信息。
   - 后台页面宽度沿用 `.page-section` 规范；用户端业务内容区使用 100% 可用宽度。
2. **样式归属**：
   - 全局及各端共用的样式统一维护在 `shared/src/styles.css` 或各前端包的 `style.css` 中。
   - 页面特有的局部样式可使用 `<style scoped>`，但变量与颜色必须继承自 `:root` 令牌，**禁止硬编码孤立颜色**。
3. **测试契约与语义化选择器保护**：
   - 现有测试（包括 Playwright E2E、契约测试、静态规范测试）所依赖的选择器（如 `.footer-online`, `.page-footer`, `.brand`, `[data-testid="..."]` 等）**必须完整保留**。
   - 国际化文案与免责声明文字不得随意修改或删除。
4. **验证门禁**：
   - 四端空状态须明确列表对象及适用的查询范围，只有读取成功且结果为空时展示；加载、读取失败与空结果不能同时出现。需要用户先选择对象时，明确说明要选择什么。成功提示须对应已确认的实际操作及对象，后续刷新失败不得抹掉已确认结果，切换语言时保持提示同步。
   - 确认弹窗统一复用 `DetailModal`，展示操作对象、变更内容和实际影响，确认按钮写明动作。提交中及保留未知写入请求时，沿用业务关闭限制；键盘焦点不得进入背景，关闭后恢复焦点。短屏可滚动正文，长标题和按钮可换行，关闭入口须可触达。加载提示须在原生弹窗上方实际可见；成功提示支持手动关闭，鼠标悬停或键盘聚焦时暂停自动关闭。
   - 表单验收必须实际触发必填、格式、长度或数值范围等本页适用的错误状态，核对中英文提示及切换语言后的文案；提示须明确字段和实际限制，禁止只显示“填写内容过短”等笼统结论，不得以正常页面截图代替错误态检查。
   - 格式限制必须通过共用校验入口提供本地化的具体要求或示例，不能只给正则表达式或“格式不正确”；数值提示读取实际上下限和间隔。按字节限制的字段须与服务端单位一致，并说明常用字符的计数方式。输入无效导致按钮禁用时，必须提供可见的要求或字段提示；修正后清除过期的校验错误。密码长度和确认不一致分别提示。只读读取失败不得表述为提交结果未知，未知写入结果仍保留原操作及原键重试约束。
   - 验证范围按当前改动风险确定：纯样式和布局修改运行涉及页面的中英文、设备横竖屏及 320 CSS px 重排检查；组件行为或接口修改补充对应单元测试、类型检查与构建；资金、认证、权限、迁移或共享基础逻辑修改运行相应业务回归。全仓测试用于跨模块修改或发布前验证，不作为每次局部样式修改的固定门禁。已有必要保护测试不得为了通过检查而删除。


## 5. 三端共用的全局状态与时间显示（新页面必须遵守）

以下约定同时适用于用户端、品牌后台和总后台，禁止按页面另写一套实现。


总后台登录页通过公开只读接口 `GET /api/v1/platform/presentation` 读取当前平台名称和 Logo，响应仅含 `display_name`、`logo_text`、`logo_url`，禁止携带管理配置、版本或审计字段，使用 `Cache-Control: no-store`。登录前后使用同一平台展示配置；读取失败显示本地化的“无法加载平台名称和 Logo，请重试。”及“重试”按钮，不使用写死的名称或 Logo，也不显示记录删除、原请求重放等不适用文案。

### 5.1 日期与时间显示

- 唯一配置来源是总后台的 `timezone`、`date_format`、`time_format`。三端启动由 `shared/src/DisplaySettingsGate.vue` 读取公开只读接口 `GET /api/v1/display-settings`，校验成功后才展示应用。接口只公开三个显示字段，不公开管理资料或审计信息，也不缓存响应。
- 所有人类可读的时间戳统一调用 `formatDisplayDateTime(value, locale)`（`shared/src/display-settings.ts`）。已有明确传入显示配置的通用组件可调用 `formatPlatformDateTime`；配置必须来自同一平台设置，不能另造默认值。
- 禁止在业务页面使用浏览器默认 `Date.toLocaleString`、`toLocaleDateString`、`toLocaleTimeString` 或自行创建用于完整时间戳展示的 `Intl.DateTimeFormat`；禁止写死 UTC、设备时区、彩种时区或页面自己的日期顺序。日历月份/星期名称的本地化、协议校验和时区换算不属于时间戳展示。
- 中英文切换只影响文案及上午/下午等语言内容，不改变平台设定的日期顺序、12/24 小时制和显示时区。总后台保存配置后更新共享状态，另外两端重新加载时重新读取配置，不使用本地缓存或默认日期格式兜底。
- 日期/时间表单统一使用 `PlatformTemporalInput.vue`（或现有 `PlatformDateInput`、`PlatformTimeInput` 组合）；禁止直接使用受浏览器区域设置支配的原生 date/time/datetime-local 输入。控件显示遵循平台格式，绑定值仍为规范的 `YYYY-MM-DD`、`HH:mm:ss` 或本地墙上时间字符串；业务输入原先明确的时区解释不可因显示改造而改变。
- API、数据库、幂等请求体及导出文件的规范时间值保持各自协议格式；显示格式不可写回协议字段。报表统计时区、归档期间键、开奖期号和投注截止计算属于业务事实，不得为统一显示而更改。
- 配置加载失败必须显示本地化错误和明确重试入口，不能悄悄退回浏览器格式或旧配置。新增加载接口必须先让运行中的后端提供该接口，再发布依赖它的前端，避免将整个应用拦在配置加载错误页。

### 5.2 全局加载提示

#### 分页异步加载

- 四端所有上一页、下一页、页码跳转及详情内分页统一使用异步请求；点击后立即显示共享、本地化的“加载中…”提示，并禁用分页操作，完整等待响应解码和数据应用后解除。继续复用 `withGlobalLoading`、`LoadingOverlay` 及现有请求范围校验。
- 同一账号、品牌和彩种上下文内翻页时，保留已展示的列表、表头、摘要和分页区域，直到新页成功返回后一起更新；不得先清空数组、置空分页结果，或通过 loading 条件卸载/隐藏整个列表。页码随成功响应更新。不得整页 reload、重建路由页面或主动滚到页首；等待期间列表高度和滚动位置应保持稳定。
- `v-global-loading` 只能绑定独立的纯进度提示，禁止绑定列表、表格或业务内容容器，否则隐藏占位的逻辑会使正文消失、页面高度塌缩。开奖结果归档列表使用独立状态节点，列表保留并设置 `aria-busy`。
- 切换账号、品牌、彩种或详情对象时仍须清除不属于新范围的数据、重置分页并拒绝迟到响应，不能以保留页面为由泄漏旧身份内容。请求失败沿用明确的错误和重试流程，不把旧页当成新页成功结果，也不显示虚假空状态。
- 验证须延迟真实分页响应，检查等待期间“加载中…”可见、旧内容仍可见、分页禁用、列表高度和滚动位置不跳动；放行响应后新内容与页码同步更新，加载提示消失。覆盖中英文、安卓/iOS 横竖屏和 320 CSS px 重排。


本地复制和系统原生分享不属于应用数据加载，不启动全局加载提示；它们沿用各自的成功、取消和失败处理。

- **按操作意图区分前台与后台**：三端后台轮询、会话心跳、导航积分定时更新和窗口恢复焦点检查必须静默更新，不显示全局加载，不清空已展示的数据，也不把页面重新置为首次 loading。保留真实失败、会话失效、品牌隔离和写入结果未知的原有处理，静默不等于吞掉错误。定时器、焦点监听和它们的读函数不得调用 `withGlobalLoading`。
- **显式前台任务**：首次进入或切换数据身份时，用已有 `v-global-loading` / `LoadingOverlay.active` 表达初始化状态；没有局部初始化进度节点的组件，在初始化读取的 `onMounted` / 身份 `watch` 中显式调用 `withGlobalLoading(reader, ...args)`。手动刷新、查询、翻页、提交和明确重试的异步事件也调用该共享函数，完整等待响应体、状态更新及操作后续读取。无参数用 `withGlobalLoading(load)`，有参数用 `withGlobalLoading(loadPage, nextPage)`；多步骤用 `withGlobalLoading(async () => { ... })`。沿用原操作参数、幂等键、权限检查和错误处理，不自动重试、不改变成功/未知结果判断。
- **唯一实现与并发边界**：`shared/src/global-loading.ts` 对每个前台任务独立计数，在 `finally` 中释放，任意一个任务结束不能隐藏另一个仍在执行的任务。`LoadingOverlay.vue` 只展示显式任务和初始化状态，禁止覆盖 `window.fetch`、按 URL 猜测请求类型，或用全局静音布尔值影响同时发生的前台提交。也不能通过延时显示/隐藏掩盖轮询闪烁。
- **新页面门禁**：`scripts/loading-action-audit.mjs` 与 `tests/static/global-ui-architecture.test.mjs` 检查三端和共享组件的异步 UI 事件、刷新和表单提交接入。新增轮询必须核对其所有下游读函数不会登记首次读取状态；新增异步 UI 入口必须显式登记前台任务。回归需用未完成的请求验证：后台请求等待时没有全局提示；同时手动刷新或提交仍显示；响应头到达但正文或后续处理未完成时不提前消失；并发、异常和卸载后的迟到结果不泄漏计数。

- 三端统一复用 `shared/src/LoadingOverlay.vue`，不得再增加一套全屏加载框、正文“正在读取…”卡片或启动配置占位文案。应用启动阶段也使用同一个加载组件，不暴露“正在加载显示设置”等内部步骤。
- 纯加载/读取/刷新占位元素使用 `v-global-loading`（从 `@lottery/shared` 导出），保留原有的 `v-if`/`v-else-if` 条件及 i18n 文案。指令把该文案登记到共享全局状态并隐藏正文占位；状态结束或组件卸载时必须注销，语言变化时同步更新。
- 只允许把纯进度提示交给全局加载。错误、空状态、成功回执、未知提交结果、冲突确认、重试按钮和业务操作入口仍在原页面展示，不能因为全局加载而吞掉。
- 操作按钮可保留自身的禁用与提交中状态；它们不是正文占位，不能为了消除加载文字而隐藏整个按钮。带加载/空状态二选一文案的节点用 `v-global-loading="loading"`，只在真正加载时隐藏并登记全局提示。
- 页面已有独立异步状态时，使用 `LoadingOverlay` 的 `active` 与 `label` 覆盖完整任务周期，包括读取响应体和应用数据；不能只根据 fetch 返回响应头就认为所有业务读取已经完成。
- 首次进入和刷新时，数据身份尚未确认应处于 loading，而不是先渲染“未登录”或空的红色错误框。只有请求明确失败后才显示错误，并且非空错误文案才创建错误提示容器；禁止用定时隐藏、自动重试或延迟显示掩盖真正失败。
- 加载期间不得闪出空状态。滚动列表的“没有更多”仅在实际加载过后续数据并到达末尾时显示；消息列表首次为空显示“当前没有新消息”，首批已有消息则不显示结束提示。

### 5.3 新页面接入与回归检查

1. 先确认三端现有的共享组件、显示配置、全局加载和语言目录，再开发页面，不复制旧页面的局部实现。
2. 明确区分初始读取、成功、空数据、读取失败和写入结果未知；不要用 `!data` 同时表示这些状态。
3. 新增时间戳使用统一格式化函数，新增纯进度提示接入 `v-global-loading`，新增文案提供 en/zh-CN。
4. 回归覆盖启动、刷新、切页、弹窗、滚动加载、失败重试、语言切换和卸载后的迟到响应；只读检查不能偷偷触发业务写入。
5. `tests/static/global-ui-architecture.test.mjs` 约束共享入口、时间格式化和加载占位接入。修改全局规则时必须同步文档、实现与检查，不得删除检查来绕过约束。


## 6. 移动端适配与布局验收

### 6.1 布局规则

- 使用浏览器提供的 CSS 视口，物理屏幕像素不能直接当作 CSS 宽度。各端保留 `width=device-width, initial-scale=1.0, viewport-fit=cover`，不得禁用用户缩放。
- 外层布局采用自然文档流、Flex/Grid 与可收缩列（例如 `minmax(0, 1fr)`、`min-width: 0`）。正文保持可读，空间不足时换行或调整列数；控件可以有明确尺寸，页面不得写死手机宽高。
- 断点依据内容排列是否容得下设置，不依据手机品牌；修改断点时同步增加其前后 1 CSS px 的布局检查。
- 内容高度由内容决定并允许纵向滚动；满屏外壳使用 `min-height: 100dvh`。弹窗使用动态视口约束高度，正文区域独立滚动，关闭按钮必须可触达。
- 固定导航与操作栏须预留底部安全区和正文空间，横屏注意左右安全区。不得以 `overflow-x: hidden` 或缩小到 11px 以下消除验收失败。
- 320 CSS px 是重排检查点，参考 WCAG 2.2 SC 1.4.10，不宣称为手机市场最低宽度；360px 同样只是一个宽度样本，不能代表全部手机。

### 6.2 分层测试与执行

1. **设备预设布局检查**：`pnpm test:layout`。使用锁定版本 Playwright 的 Pixel 7 竖屏/横屏（Chromium），以及 iPhone SE、iPhone 13、iPhone 13 Pro Max 和 iPhone 13 横屏（WebKit）。直接使用 `devices[...]` 提供的 viewport、screen、DPR、触摸及 UA 参数，禁止再次统一覆盖 viewport。Playwright Test 的 screen 参数须放入 `use.contextOptions.screen`，测试同时校验实际 viewport/screen/DPR，不能只依赖对象展开。设备屏幕尺寸与浏览器可见视口可能不同；预设是可复现的模拟参数，不是所有浏览器状态的真机测量值。
2. **重排和高度检查**：同一命令中，Chromium、WebKit 分别验证 320～480px 每 20px 一个宽度，以及 620/640/700/768/820/900/1000/1080/1200/1440px 断点前后各 1px，并检查 1024px，共 40 个宽度样本。弹窗在 412px 宽度下验证 320/420/568/900px 高度，检查可滚动正文和可见关闭按钮。这些是尺寸压力样本，不冒充设备型号或软键盘模拟。
3. **业务回归**：现有 `test:e2e`、`test:responsive`、`test:webkit`、`test:pwa`、review 和 qualification 保持真实服务/数据库与现有幂等、余额、品牌权限保护；普通 Chromium 手机项目采用 Pixel 7，WebKit 手机项目采用 iPhone 13，平板/桌面项目保留。review 手机项目名更新为 `mobilepixel7`，CI 使用同名独立测试账号；旧 `mobile360` 测试账号不会自动改名或复用。
4. **少量真机试用**：iOS Safari、安卓浏览器，以及产品实际使用的鸿蒙浏览器/内置浏览器，重点检查软键盘弹出、地址栏变化、旋转和安全区。自动化调整视口高度只验证空间变小后的布局，不等同于操作系统软键盘，也不能把 Chromium 模拟结果称为鸿蒙已验收。

首次运行：

```sh
pnpm exec playwright install chromium webkit
pnpm test:layout
```

Linux CI 沿用受限时长的 `scripts/prepare-ci-browser.mjs` 安装并探测 Chromium，另外执行 `pnpm exec playwright install --with-deps webkit` 安装 WebKit 及其依赖。允许通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`、`PLAYWRIGHT_WEBKIT_EXECUTABLE_PATH` 明确指定相应引擎；缺失引擎应直接报错，不切换引擎、跳过用例或自动重试。

使用 Playwright 虚拟时钟测试轮询、切期或封盘时，必须在 `page.goto` 及应用创建定时器之前调用 `page.clock.install()`。页面加载后才安装不能接管已存在的原生轮询，会让实际 5 秒轮询与默认 5 秒断言超时竞争；禁止通过延长超时、自动重试或跳过用例掩盖。推进时间后核对实际期号和页面状态，继续验证旧期选号不可提交、未加入组合不可跨期及读取失败不可沿用缓存下单，不修改业务校验来适配测试。参考 [Playwright Clock 安装顺序](https://playwright.dev/docs/clock)。

Vitest 的 `vi.useFakeTimers()` 同样必须在组件挂载、会话心跳、钱包轮询或弹窗超时启动前安装，卸载组件后再恢复真实定时器。`tests/static/virtual-clock-order.test.mjs` 扫描浏览器测试目录及三端、共享单元测试，要求安装语句位于所属测试或 setup 函数首条语句，并用晚安装的反例验证检查本身；辅助函数创建的定时器仍需在审查时核对调用顺序。当前钱包轮询、会话替换与 Telegram 弹窗超时用例均遵循该顺序。

布局套件使用独立端口 15273/15274/15275/15276 启动用户端、品牌后台、总后台和代理端真实页面，显式合成只读 API 数据，检查中英文登录/注册、开奖结果、投注布局、导航/操作栏及长内容弹窗。未知 API 与写请求使测试失败。该套件提供布局证据，不提供真实登录、资金或后台登录后全部业务页的验收证据；这些由原业务回归负责。

截图、失败 trace 与设备 viewport/screen/DPR 记录写入 `test-results/layout/`，CI 上传留档。不得只凭无横向滚动条宣布适配完成，还需检查关键内容可见、操作栏不互相遮挡、输入框可滚动到可视区以及弹窗关闭与正文末尾可达。

参考：[Playwright 设备与视口模拟](https://playwright.dev/docs/emulation)、[W3C 重排要求](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。

### 代理模式和周期切换

- 占成比例和佣金比例使用百分比输入，输入框旁固定显示 `%`，填 `20` 表示 `20%`；编辑回显、只读信息、待生效配置与确认内容保持相同百分比口径。提交接口时精确转换为既有的 0–1 比例格式，整条代理线的下级新比例同样处理。

- 根代理在界面统一称为“一级代理”。创建一级代理必须明确选择输赢或流水，不提供继承；模式在比例之前，未选择模式时不显示比例。输赢显示占成比例，流水显示佣金比例，不能把一个模式的比例自动复用于另一个模式。
- 一级代理切换模式时，品牌后台读取整条代理线，将所有层级下级的新比例重置为 0，可逐个调整后一起确认提交。切换提示按说明事项逐条展示。服务器校验完整名单、品牌、版本和新模式下的父子比例及品牌上限；下级统一跟随一级代理，新模式和整条线的新比例在现行佣金日历的下个边界同时生效。未配置佣金日历时明确报错。
- 当前周期的投注继续保存旧模式、旧比例和对应修订；边界后的投注按投注时间选择新修订，不能依赖后台任务是否已运行。保存的历史投注不受后续配置影响。待生效期间显示新模式、比例和生效时间，并禁止编辑该线或新增下级及变更佣金日历和代理政策；生效后恢复编辑。

### 独立代理端

- 代理和会员使用独立账号、密码、会话和佣金钱包；创建代理不得查找会员、升级会员或创建隐藏会员。账号名允许与会员同名；代理账号按品牌唯一。
- 所有层级共用 `agent-web` 代理端。代理可以在“直属会员”和“整条代理线”之间切换，查看自己及下级发展的会员基本资料、可用积分、四类注单和已结算净输赢。数据归属在服务端核验，任意会员编号、品牌路径和会员/管理员会话不能越权。
- 允许发展下级的代理可以添加直属下级；上级由当前会话确定，不允许通过请求指定其他上级。层级上限、上级比例、模式继承及停用祖先校验继续生效。关闭发展下级权限时，同时隐藏操作并由后端拒绝。
- 代理添加的会员仍是独立会员，新会员首次登录确认当前条款。代理创建和会员添加使用事务、冻结请求及幂等键，结果未知保留原请求重试；不在确认内容、审计和日志中展示密码。
- 四端登录及用户注册统一复用 `shared/src/LoginEntry.vue`、`LoginCredentials.vue` 和 `login-entry.css`，共用顶部品牌区、语言选择、居中卡片、账号密码字段和错误样式。品牌名称/Logo、账号标识规则、验证码、注册/条款及 Telegram 入口通过参数和内容插槽保留；不得在单端另写登录骨架、字段组件或覆盖基础布局。账号密码字段统一使用可见标签，不添加 placeholder。登录语言按钮四端统一为 44px，语言偏好沿用共享 Cookie。
- 代理端复用共享设计令牌、语言目录、日期格式及注单展示组件；支持中英文、安卓/iOS横竖屏和320 CSS px重排。

代理端会员范围统一使用 `scope=direct|line`，默认为直属会员；整条代理线包含当前代理及其所有下级发展的会员。会员列表、搜索和汇总使用同一范围，详情和注单也校验范围及品牌。积分按会员独立汇总，注单按实际订单独立汇总，禁止累加各层代理汇总。汇总覆盖完整查询结果，与分页无关；列表显示归属代理。

品牌代理规则展示、编辑两个独立百分比上限：占成比例上限、佣金比例上限。创建一级代理按当前选择的输赢/流水模式显示对应上限，超限在提交前明确提示；总后台只读展示两项。

### 用户可理解的业务展示

四端均面向业务使用者。核对、详情、历史和错误提示只展示操作对象、业务内容、变更前后、积分、状态、时间及影响。禁止展示原始 JSON、请求正文、幂等键、请求追踪编号、数据库编号、hash、协议字段、HTTP 错误码和内部审计编号，不提供“高级信息”折叠区绕过此规则。确认内容必须使用双语业务字段；程序排障通过服务日志及内部记录关联，不依赖用户复制技术数据。已有直接保存的流程保持直接提交。

### 独立代理端的管理结构

- 代理端沿用共享 `management.css`、`ManagementShell`、`AccountMenu`、`TablePagination`、`DetailModal` 与既有表单/写入指令；品牌后台、总后台和代理端共用同一个账号菜单，不另画账号交互。
- 桌面左栏提供“会员管理、下级代理、会员注单、佣金”四个独立地址；移动端沿用品牌后台的底部导航习惯。每次只加载当前页面业务，支持刷新、前进与后退。会员注单单独读取已授权会员，不把会员管理、代理管理、投注明细和佣金流水铺在同一页面。
- 个人信息、修改密码和退出位于顶栏账号菜单。代理改密验证当前密码，事务内更新凭据、记录脱敏审计并撤销该品牌该账号全部代理会话；成功后重新登录。原键重试、至少一秒写入入口限制、品牌与代理归属权限继续生效。
- 佣金页仅显示当前代理账户实际入账和扣回的佣金流水，不把核算中金额当成已入账收益，也不开放其他账号或品牌的筛选参数。

品牌后台与总后台的管理账号列表共用 `ManagementTable` 和 `.account-directory-table`，统一表格骨架、状态与操作列的布局基础及窄屏重排；各端只提供已有权限范围内的字段和业务操作。品牌后台分页复用 `PaginationControls`，不得另写账号卡片列表。

代理管理的会员、下级代理及佣金表格与品牌后台会员/代理目录、总后台代理目录共用 `management.css` 的 `.console-table` 基础规则，统一表头、行高、分隔线、悬停、首尾列与窄屏重排。禁止代理端另写表格基础样式；空表使用共享 `.empty-state` 的 `td` 和正确 `colspan`。

代理管理不维护独立通用样式文件；品牌标识复用品牌后台同用的 `BrandLockup`，名称、标志文字与图片来自品牌 context 的已校验展示配置，登录页同样使用品牌标识。管理外壳的布局规则统一维护在 `management.css`，表单复用品牌代理编辑器的 `.am-form` 结构，面板和资料区共用 `.console-panel`、`.console-stack`、`.console-facts`，并在品牌后台会员列表、两端账号资料和总后台代理列表实际引用。品牌配色不覆盖管理端设计令牌。

### 代理管理展示复用

- 品牌后台、总后台与代理管理的个人信息和修改密码使用共享 `AccountProfileDialog`、`ChangePasswordDialog`，统一字段、表单、按钮、关闭和键盘行为；业务提交仍由各端处理，代理管理未知结果的冻结请求和原键重试保持不变。

### 注册链接与二维码

- 用户端提现申请只展示可提现积分、最低提现积分与一个金额输入框；按品牌允许来源自动分配，不让用户手填来源，不展示流水计算明细和泛泛说明。未满足流水时简短提示。积分步长为正整数，1 表示整数积分，10/100/1000 分别表示整十/百/千；提现金额须同时满足最低积分、最高积分、可用余额和步长整除校验，后端统一校验并保留原请求幂等重试。

### 当前配置化完整流程

玩法规则使用共享 `ManagementTable` 展示玩法、分组、计注方式、选择数量与配置入口，提供本地搜索与分组筛选。单条配置使用共享 `DetailModal`，按“基础与选号、中奖与结算、规则试算”分区；普通字段桌面两列、窄屏单列，复杂结构独占整行。添加玩法按“复制玩法／新建号码组”切换平铺表单，继续配置沿用同一弹窗；属性绑定按属性选择器与“分组／绑定号码”平铺编辑，校验号码池、完整归属、排他分组与单个固定号码约束，不因局部固定归属锁定整个属性；公共价格表按价格项与实际盘口组成矩阵，共用价格键仅保留一行，窄屏按记录重排。两类数据不再使用递归树形编辑器，查看账号可切换属性但不能修改或应用。属性绑定与公共价格表独立进入；共享选号域编辑前列出受影响玩法。弹窗应用仅更新页面待保存配置，页面统一保存整套规则；取消不应用修改，未保存状态与返回提醒须清晰。品牌与只读账号仅查看规则和试算，不能应用平台规则修改。

平台创建彩种后，模板必须匹配已选号码模型；不允许静默替换模板模型。规则保存立即生效，无规则时禁用手动开期。品牌只维护接入状态、投注赔率／开关及投注限额，不提供独立自动开奖采用开关或提前封盘表单；全部品牌使用共享期次窗口。开奖来源仅维护当前映射配置，旧来源明确提示停止执行及重新配置。相关操作、接口与验证以65号完整流程复核为准。

账号关联筛选及人工发放、充值、提现中的会员账号选择统一使用共享 `FilterAssociationSearch`；输入至少 2 个字符后自动匹配（300ms 防抖），服务端按账号开头匹配（右侧通配，如 `te` 匹配 `test`，不匹配 `other_test`），大小写不敏感，通配符按普通字符处理。人工发放搜索沿用 `reward.grant.brand` 与当前品牌权限，选定账号后方可审核。账号关联筛选复用共享 SelectControl 的可搜索下拉框，匹配结果在顶层下拉列表中选择，不在字段下方平铺按钮；支持键盘定位、确认、Escape 关闭、外部关闭及结果分页，不提供独立“搜索”按钮。选中账号仅更新筛选条件，由页面“查询”按钮读取业务数据；输入未选定时继续阻止查询，保留清除、结果分页及读取失败后的重试。自动匹配不显示全屏加载遮罩，避免打断输入。账号无匹配结果时不显示常驻提示，未选定结果继续禁用查询；清除框内输入同步清空选定账号和待选择状态。

### 统一分页文案

四端及共享业务组件的分页均使用 `TablePagination`（或其操作封装 `PaginationControls`），传入当前页码 `page`、本页业务记录数 `count`、当前查询范围的真实总条数 `total`（十进制字符串）和 `locale`。文案由共享 `pagination-catalog` 统一生成：中文“第 X 页 · 本页 N 条 · 共 M 条”，英文“Page X · N records on this page · Total: M”。四端所有列表在本页无记录或真实总数为零时统一隐藏整条分页栏，不提供页面级空结果显示开关；首次读取前和首次失败时隐藏分页栏，不把未读到数据当成成功零条；计数不包含预读的下一条记录，也不按一条记录展开后的表格行数累加。页面不再传入独立 summary、裸数字、偏移量或记录区间。右侧统一使用前后箭头、当前页及相邻页码、首尾页与省略号、跳页输入和 GO 按钮、每页条数；当前页使用主色。四端所有分页列表统一使用每页条数 SELECT，可选 10、20、50、100 条；切换后从第一页按所选 limit 重新查询，游标列表同时清空旧游标。页面内主列表、明细和历史列表分别保存条数。整批读取后本地分页的列表须重新读取来源数据并重置第一页。跳页与数字按钮调用原页面读取流程，读取中禁用；游标列表仅允许跳到已掌握游标的页码，接口既有偏移上限继续生效。手机端（不大于 640 CSS px，或无悬停的粗指针设备）一行显示“共 N”、首页图标、上页图标、当前页数字、下页图标及尾页图标，图标按钮之间保留 4px 间隔，保留中英文无障碍名称，隐藏页码序列、跳页输入与每页条数 SELECT；游标不足时禁用尾页。保持至少 44px 触控高度和 320 CSS px 无横向溢出。用户端投注记录空结果隐藏分页；用户端通知在移动端同样使用上述精简分页。
