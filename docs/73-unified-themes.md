# 四端统一主题

本规范补充并更新 48 号文档中的配色规定。用户、品牌、平台、代理共用同一主工作区视觉语言；业务布局和权限不因主题变化。

## 所有权

平台设置的 `theme` 是全局配色来源，使用平台设置读写权限、版本号、审计及幂等机制。公开 `/api/v1/display-settings` 只下发主题标识和日期时间策略。各端启动读取；保存平台设置立即更新当前平台页，其余已打开客户端重新打开或刷新后读取新值。

日间、夜间、自动是设备偏好，四端顶栏共用 `ThemeSwitcher`。默认日间，自动跟随系统。该偏好保存在当前来源的浏览器存储，不写入品牌或平台设置。不同域名各自保留模式选择。配色风格始终由平台统一决定。

## 主工作区

主画布、卡片、表格、表头、表单、按钮、弹窗、顶栏及导航统一从 `shared/src/themes.css` 取得颜色。主色用于选择和动作，强调色用于业务强调；错误、成功、警告以及号码波色具有独立语义，不能随主题替换。不得将新配色写进各端组件，禁止蓝紫渐变。背景只使用代码 SVG 的低对比纹理，不增加装饰动效。

保留现有紧凑尺寸、列表结构、字号下限、触控区域和响应断点。内容不整体缩放；表格依照现有组件重排。切换配色不得重挂载业务页面或丢失表单输入。

## 新增主题

1. 在 `shared/src/theme.ts` 注册稳定标识并补齐中英文名称。
2. 在共享 CSS 增加日间及夜间配色，复用既有语义令牌和组件结构。
3. 同步更新数据库主题约束、平台服务校验和 OpenAPI 枚举。正式发布前合并基线，已有库必须先备份并验证副本结构及数据后同步迁移记录。
4. 验证平台权限、非法标识、版本冲突、幂等重放与公开策略下发。
5. 四端实际渲染核查：文字、留白、层级、颜色、交互、安卓/iOS 横竖屏及 320 CSS px 重排。检查日间、夜间和系统自动切换，不增加解释性页面文案。

未知主题明确报错，不自动改用其他主题。不开放任意 CSS 或任意颜色输入。
