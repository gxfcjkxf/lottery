# 验收标准与未决事项

## 1. 验收优先级

- P0：资金、品牌隔离、投注幂等、期次状态、开奖和结算正确性；不通过不得交付。
- P1：玩法配置、提现、代理佣金、报表、通知、风控配置和移动端管理。
- P2：真实支付、原生 App、完整 KYC、更多外部通知渠道和平台自开奖扩展。

## 2. 核心验收场景

### 站内通知（S6-b/S6-c 当前范围）

- 入品牌、充值确认及四类注单事件来自业务 outbox，事务回滚不生成通知；重复消费不重复落库。
- 单条错误不阻塞后续；站内内容、消费者确认和 sent 同事务，失败不能留下半条消息。暂时性失败退避至五次，永久无效事件隔离，运营手动重试带理由、权限与审计。
- 只显示当前品牌会员消息；同品牌其他会员也不可读写。已读必须整批验证，未知编号不能造成部分成功。退出/撤权后旧幂等回执拒绝。
- 内容与来源不可改写，仅首次读时间可追加；只按本页观察到的 IDs 标读，刚到的新消息保留未读。
- 双语版本化模板和精确积分格式，不允许模板变量读取内部理由、管理员、密码、令牌或充值证明。畸形成功回执/断网按未知结果保留原请求，刷新不是成功证明。
- 正额派奖与全额奖金冲正仅由实际账本事务生成；待批准/零额/失败不提前通知。更正后延迟消费依然校验旧不可变证据，旧消息保留，新代次另记；消费不改变积分。
- 后台投递查询与失败重试需真实权限；未知请求在页面重挂载后保留同正文/键，只读已投递状态不能代替原回执确认，退出清除。UI 响应模拟仅证明客户端状态，不替代真实数据库和 HTTP 重试证据。
- 品牌模板初始十四种/v1（原八种加六种提现状态），中英两份必填，未知字段/占位符、控制字符、HTML、地址和超字节限制服务端拒绝。欢迎通知不引用积分，其他正文保留真实积分变量。
- 写入单人确认、版本冲突、同键异体/换事件、撤权/停用后的重放拒绝、审计故障整体回滚；平台查看不要求伪造品牌成员，超管不可写。初始/后续审计规则可查询，历史和直接无修订投影更新不可改写。
- 原生旧schema产生的v1消息升级后原字段不变；新消息复制当前模板。后续改版不修改历史，重复消费不覆盖内容；真实注册与用户中英显示、结果未知离开/返回的原键重试都须覆盖两个视口。派奖/冲正的不可编辑历史说明保留。
- 提现六种状态由同事务的不可变状态证据生成，重复请求不重复入队；outbox失败须使资金处理整体回滚。延迟消费按历史版本验证，不因当前状态变化失效；用户只显示订单ID、积分和历史说明，不泄露内部审核理由，不把paid当作真实外部转账证明。开奖受众和外部发送仍未完成。

### 运营报表（S6-d 当前范围）

- 投注按原提交时间统计当前最终代次，连续更正不得重复累计旧派奖；更正中/部分结算、异常、取消与退款单独显示。
- 账本按实入账时间保存充值、派奖、反向及退款事实，冻结转移净积分为0；当前桶余额与区间流水分开，不冒充全链对账一致。
- 品牌/会员/彩种筛选不可忽略，两种读取权限独立、超管需显式平台权限；成功查询可审计、审计失败不泄露半份数据。不返回用户名、证明、人员或内部理由。
- 汇总/分页单响应快照一致，聚合超过int64仍精确；from含/to不含，等价时区与尾零格式匹配，真正纳秒边界变化拒绝。
- 筛选草稿/只读刷新/已显示范围分开，新失败和品牌/会话变化不得留旧数据冒充新范围；两个视口无页面横向溢出。
- CSV导出要求view与export分别通过，每个动作可来自明确品牌或平台授权，超级管理员标记不直接授权；等待授权锁时撤权不能下载。审计失败不输出附件。
- 导出同一筛选范围的单语句快照而非当前页；真实库10,000分组完整、10,001拒绝，4 MiB超限无截断附件。BOM、固定列、公式防护、精确大整数/负净变动、余额行与分组总计可校验。
- PC和360px移动端真实下载采用已提交筛选，未提交草稿不改变范围；切换品牌/会话/报表后迟到响应不得自动下载。CSV详情见 [导出合同](11-report-csv-exports.md)。
- 提现报表按申请created_at筛选，以品牌时区按day/member/state分组，当前状态投影与实际出款时间、不可变结账分开。超int64汇总保持字符串；会员筛选回显在CSV的summary和每组一致，LF/CRLF文件均能验证完整摘要、列和金额总计。报表权限、工作台提现查看权限及导出权限互不推导。
- 0053实际佣金入账报表及0057奖励实际入账/订单队列报表已接入。尚不证明不可变日/月结、完整代理归属分析、大规模异步全链对账或生产负载验收完成。

### 合规配置与伪适配器检查

- 品牌初始全部关闭，新增品牌有政策及系统初始历史；既有品牌、成员、资金、注单和其他配置不改变。
- 严格五键配置、年龄/国家工程范围、排序与重复、未知/缺失/null/控制字符在服务端验证；不依据客户端传入的生日、国家或身份宣称验证。
- 真实并发修改仅一版成功；审计失败不留半份政策，缺历史的直接投影更新及历史/决策修改删除被数据库拒绝。
- 显式检查锁定当前版本；关闭项只代表跳过、开启项只返回待复核/未接适配器；记录快照、原因、版本、操作人和审计，不变更用户或资金。
- 原键检查重放不重复记录，改配置后仍返回原历史快照；撤权/停用/会话失效后缓存拒绝，其他品牌无权限不能查询。
- PC/360px浏览器真实配置和检查提交后分别丢失响应、离开返回原正文/键重放；不清空限流或业务数据，通过审计写恢复本测试改动的配置。
- 新注册/首次入品牌/运营新增/首次接受条款、真实投注预览及提交在开启未接适配器时被服务端拒绝；旧预览不能放行，不新增身份、会员、积分账户、借记或注单。已有成员登录/会话读取/取消/原路退款不因开关被阻断。
- 政策启用写必须实际等待旧检查事务共享锁释放；后续准入读取新政策。拒绝采用不可变原版本保存，政策后来改变不改写证据。
- 拒绝证据与加密负回执同事务，故障注入不得保留业务、孤立审计或缓存；恢复后原未提交键可重试，已提交拒绝键则保持历史409且不重复记录。
- 本机浏览器执行真实注册拒绝及原键重放，明确分开管理模拟与业务记录；默认关闭路径500/s受控基线只证明当前合成投注场景，不代表真实验证负载、真机或生产容量。
- 提现申请同样拒绝启用而未接适配器的合规检查，正式流水资格器也不能绕过；平台已接入真实流水资格，品牌默认关闭提现，申请时重新计算且拒绝不占用积分。真实身份验证、复核队列、合规资金冻结和完整责任博彩仍未完成，整体合规任务仍未完成。

### 多品牌隔离

- 显式平台权限可在没有种子品牌的可信管理入口创建首个品牌；超级管理员标记本身不能创建，未知Host不能访问。
- 创建固定暂停/v1，同事务初始化七项配置、十四类双语通知模板及不可改写审计/创建证据，不生成会员、消息、管理员范围、域名、游戏或积分；原品牌数据不变。
- 相同代码并发仅一品牌，一键并发只执行一次；失败整体回滚，同键异体冲突，撤权后旧缓存拒绝。品牌恢复后原创建键仍返回初始暂停/v1快照而非当前状态。
- PC和移动浏览器真实201提交后丢失响应、离开返回使用原正文/键，只保留一笔创建；完整刷新丢失内存键不在自动恢复范围内。

- 创建两个品牌和同一个全局用户。
- 用户分别加入两个品牌。
- 在品牌 A 创建余额、订单和提现后，品牌 B 的接口、缓存、报表和后台查询不得看到 A 的数据。
- 品牌域名解析错误或伪造 X-Brand-ID 时必须拒绝。

### 注册和登录

- 注册必须保存隐私条款和服务协议版本。
- 用户名、手机号全局唯一。
- 首次缺失的用户名/手机号只允许补充一次；已填写后普通修改被拒绝。
- Telegram 同一全局标识不能绑定多个用户，且不能解绑。
- 踢人后现有会话立即失效。

### 品牌暂停

- 暂停生效后新投注返回 `BRAND_PAUSED`。
- 登录、查询、提现仍可用。
- 已创建注单、开奖、结算和提现不被自动取消。
- 暂停/恢复使用真实品牌版本、原因、幂等回执和不可变历史；审计失败整体回滚，撤权后不能重放旧成功响应。
- 后台采用核对后提交，未知意图切换页面仍保留原键；恢复状态须等待成功回执后再读取当前值。提现申请/出款仍以其独立模块验收为准，品牌暂停不能作为它们已实现的证据。

### 积分和账本

批量检查已接入固定品牌账户范围的持久任务、三类不可变观察、单人确认和失败人工恢复；0061至0063增加显式wallet_and_business范围，双向核对已实现充值、投注、退款、历史派奖/反向、提现、奖励和佣金原派发/修正/更正引用。钱包一致不能覆盖业务异常，未知类型明确报不支持；真实零额不造流水，缺动作或指针不隐藏所需引用。创建/重试幂等、热账户不阻塞其他品牌、多worker去重、资金不变、禁止晚加目标和伪完成、PC/移动端未知回执原键恢复按[对账交接](13-wallet-reconciliation.md)独立验收。结果completed只表示检查完成，不表示全部账户正常；不会自动修复。独立于账户范围的孤立业务行检查、不可变日/月结和大范围并发负载仍未完成。

- 充值、中奖、佣金、赠送积分只能为整数且不过期；0050支持审核与实际佣金来源派发，0051支持独立人工差额修正；0058至0060更正计划、实际差额、显式继续、原子历史通知及实际报表已接入，特殊OPEN-117组合仍阻止。
- 四来源升级后投注按充值 → 中奖 → 佣金 → 赠送扣款，并记录每个来源的扣款金额；取消按原分配全额退回，旧三来源摘要、回执和历史不得改写。
- 每条账本记录必须有变更前、变更额、变更后四类余额快照。
- 冻结/解冻、取消退款、提现冻结、派奖和人工修正都产生追加流水。
- 并发扣款不能使余额为负，也不能重复扣款。
- 相同幂等键重复请求只产生一个业务结果。

### 用户人工充值记录

- 后台创建pending不加积分、确认只入账一次、取消不加积分；用户真实列表和详情对应这三种状态，没有演示提交或支付按钮。
- 只返回当前品牌会员的九字段安全投影，跨会员/品牌详情统一404；证明、备注、后台操作人、理由和内部审计ID均不泄露。
- 大于JavaScript安全整数的积分和版本精确显示；分页默认20、最多100、稳定双键排序，同次页/总数/查询时间一致，空页返回数组。
- 无正文、未知/重复/空查询参数及非规范分页数字均拒绝；两条品牌路径与域名入口按同一会员认证执行。
- 读取只追加脱敏查询审计，不改变订单、余额或积分流水；审计失败不释放数据，审计等待期间会话过期时整笔回滚并返回401。
- 暂停品牌/冻结会员查询可用；禁用、协议缺失或失效会话仍受现有认证门禁限制。换会员Cookie后清除旧记录，迟到查询不能污染新会员。
- 中英文、桌面和360px浏览器验证真实后台创建/确认/取消、本人查询和账户切换；Chrome双视口不代替iOS、Android、HarmonyOS真机及PWA安装验收。

### 投注和取消

- 期次不是投注中、规则版本失效、品牌暂停或限额超出时，投注失败且不扣积分。
- 同品牌、同彩种上期未结算时，下一期不能开放；已开奖、仅计算完成、等待审核、已批准但未完成派奖、结算失败均须阻止。异常注单按既定规则排除，整期已结算后才放行。
- 取消上期后只有全额原路退款完成才放行；部分退款、处理中或失败均阻止下一期。成功旧单的原键重放只返回历史回执，不产生新投注。
- 下一期窗口已过则按日历跳过，保持原计划时间和历史；阻塞或跳过不得增加开期序号、激活下期规则。未来日历预生成不得阻塞按时间排序的较早合法期次。
- 投注成功必须同时存在注单、扣款流水和 Outbox 事件。
- 用户取消只有在配置允许且满足开奖前条件时成功。
- 运营取消异常注单可以随时执行，但必须记录原因。
- 期次/注单取消全额按原来源原路退回。

### 玩法和结算

S5-c1 当前核算预览的独立门禁（不替代下述正式结算门禁）：旧规则后来更换仍使用购买时定义；规范选号/全部展开/倍率/积分/来源分配及原借记逐桶证明全部匹配；任一数据异常整注不给计算金额，人工异常不跑引擎；预览/审计同事务、跨品牌和无权限/超管写拒绝、同键不重建、撤权后不复用缓存。核算前后钱包/流水/注单/期次不变；过时记录保留且 current=false，正常结果可分页追溯奖级 trace。丢失回执原请求重试，已取得匹配回执后只读失败不能再变为未知写入。

- X+Y、M 选 N、0~9 N 位数字都能完成选号、校验、预览、投注和结算。
- M 选 N 校验 M 为非 0 正整数、N < M、N=N1+N2。
- 0~9 N 位数字正确处理允许重复和不允许重复。
- 复式注数、倍投总额、奖级排他性、封顶和四舍五入结果与规则模拟一致。
- 注单始终使用下单时规则版本。
- 异常注单不进入普通结算重试。
- 结果纠正先冲正原结算产生的数据，再重新结算；原记录仍可查询。

### 开奖

- 主来源超时、错误、无数据或异常时按优先级切换备用来源。
- 期数、数量、范围和高风险重复结果校验均有记录。
- 人工开奖后停止继续使用其他来源。
- 人工开奖和结果纠正第一期不要求双人复核，但必须可按期次、操作人和时间查询审计。

### 提现

当前资金状态机、双端接口/页面、站内通知/运营统计、逐注单快照和真实资格器已接入平台；初始品牌仍关闭。当前会员的只读流水预览和真实双端申请/原键确认/原路取消/内部成功周期已验证。没有银行/虚拟币出款；新版本整套远程CI、生产容量与最终客户人工审核需独立验收。

- 同一用户同一品牌只能有一个审核中/提现中的申请。
- 提交时来源积分转入提现积分并冻结对应金额。
- 门槛基数使用申请提交、占用前当前品牌全部可用充值＋赠送余额的服务端锁定快照；拆分申请金额不能降低该基数，中奖、冻结和已占用提现积分不计入。
- 相同 N 适用时，有效流水未达该基数 N 倍拒绝提现。例如全部可用充值100、赠送50、N=3时，基数150、门槛450，不因仅申请30积分而变成90。
- 跨彩种按每笔有效投注金额除以该笔投注时 N 的快照值精确累加，达标额度至少等于基数。例如100÷2＋250÷5＝100，1÷3＋2÷3＝1；不得逐笔舍入、使用浮点或溢出。
- 新配置N必须大于0，品牌与彩种的前端/HTTP/数据库新写入均拒绝0。旧零值和不可变历史仍原样可读，不静默归一化；授权修正当前配置生成新版本，旧历史保留。
- 充值、中奖、佣金、赠送来源的有效投注均计入，每笔只计一次；佣金和中奖可用余额不计入门槛基数。配置变更只影响新投注，必须使用投注时的版本、继承来源和有效N快照；缺少历史快照时不借当前配置放行。
- 彩种 N 优先于品牌 N。
- 取消、判定取消、异常和无效注单不计有效流水。
- 成功提现以申请提交时间切换流水周期；失败/驳回按原来源退回且不清空历史周期。
- 申请后、成功处理前的有效投注必须保留给下一周期；使用投注借记序号与成功申请的reserve_version比较，不按完成时间丢弃。
- 更正期间旧结算不贡献，重结算完成后只计当前有效代次一次。持钱包锁时遇到期次锁冲突立即退出，不死锁、不占用积分；资格读取后期次锁保持至申请事务结束。

## 3. 性能验收

- 目标负载：约 500 名在线用户、每秒 500 次投注请求。
- 必须压测同一用户并发、重复幂等、期次截止瞬间、同彩种结算门禁及跨品牌/彩种并发。
- 压测报告至少包含吞吐、P50/P95/P99 延迟、错误率、数据库 CPU/连接/锁等待、复制延迟、队列堆积和缓存命中率。
- P95/P99、峰值持续时间、恢复时间和恢复点目标需要在技术验收前由项目方确认。

受控实测证据保存在 [performance](performance) 下。当前已验证固定到达速率的单/双品牌、同用户重复键、同用户不同键及真实截止边界，并逐轮核对资金不变量。只有受控环境的相应场景成立：单热账户有在途丢弃与较高尾延迟，压测返回PASS表示工具/资金校验通过，不表示该场景满足500次/秒SLO。生产参数、完整跨品牌/彩种结算负载、主从复制/切换、复杂玩法负载、长时间峰值、真实终端和完整故障演练仍待验收；不得把性能EPIC标为完成。同彩种上一期结算与下一期新投注重叠不符合已确认需求，不是性能验收目标。
