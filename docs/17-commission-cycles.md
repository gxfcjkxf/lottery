# 佣金周期核算与代次历史

0048把佣金政策和真实注单事实接入持久化周期核算。管理接口登记已结束的周或月窗口，平台worker分批枚举、等待所有注单最终完成、记录精确差额并按代理统一取整。`ready`只是核算完成，不是已审核、已派发或钱包余额；审核、入账、调整及已派发后的追回仍需实现。

## 周期归属与登记

创建请求只提供真实锚定注单编号和原因。服务读取该注单已保存、已启用的金融政策，按投注时间计算完整UTC半开区间；不使用今天的规则替代旧快照。窗口必须已经结束，同一品牌及起止时刻只能登记一个周期。不同规则版本若映射到同一UTC窗口，仍属于同一周期，避免分版本提前舍入。

登记在金融政策上取得短暂独占准入锁，等待此前持有共享锁的投注完成。登记后，数据库禁止向该已封存窗口补插回溯时间的投注。订单身份、投注时间、历史快照不能改写或删除，因此worker可逐页建立稳定清单，不需把整月订单留在一个事务中。

清单包含窗口内全部品牌投注，包含关闭金融政策、无代理、取消或异常的订单。每笔订单根据自己的金融快照判断是否属于本次周期及是否计佣；其他日历映射到不同窗口时记录other_cycle，不在本次产生分配，也不能重复作为本次收入。旧NULL或损坏证据明确失败，不补造规则或假定零额。

当前登记入口是管理员API；尚无自动扫描发现到期窗口的调度器。已登记周期的分页处理、等待和更正后重新核算由平台worker自动推进。

## 持久化阶段

| 状态 | 含义 |
| --- | --- |
| enumerating | 每页最多100笔，按placed_at及UUID建立不可变清单 |
| waiting | 清单完整，但仍有投注或结算未最终完成；5秒后再检查，不忽略或移入下期 |
| calculating | 新核算代次逐页校验最终结算及购买快照，保存精确分配 |
| summarizing | 全部目标已核算，按代理汇总并一次四舍五入 |
| ready | 当前代次全部核算及汇总完成，仍未产生积分入账 |
| failed | 损坏证据、超限或存储失败停止；运营按版本和原因显式重试 |

系统并发worker使用SKIP LOCKED取得周期，每页独立提交。临时的期次锁争用采用NOWAIT，回滚并延后重试，不当作永久证据失败。等待轮询只更新调度时刻，不为每次轮询生成金融版本或海量审计；实际阶段、页提交、失效、失败及重试都有不可变操作记录。

## 数据与精确金额

`commission_cycles`保存品牌、窗口、锚单及代表日历、状态/版本、清单游标/数量、当前run、证据计数和创建审计。`commission_cycle_targets`保存冻结的订单编号与投注时间，不保存可改写的投注内容。`commission_runs`按周期递增generation，保留计算游标、汇总游标、证据计数及阶段，失效run标为abandoned，不删除数据。

`commission_calculations`每个run及订单唯一，保存最终状态、基数、当前结算任务/计算/代次、原始JSONB金融快照及页审计。`commission_allocations`按run、订单及代理唯一，保存受益会员和约分后的精确分数。停用代理不从路径删除，仍使用购买时的比例；不读取今天的比例来补算。禁用政策、无归属、其他周期、取消和异常均有明确排除原因；有效中奖在loss模式下可保留零基数轨迹，不计输钱佣金。

比例精度最多六位小数，单笔约分分母必为1000000的约数。数据库使用numeric把分数精确换算为百万分之一单位后按代理汇总，再由任意精度整数/分数核心统一half-up。两笔3/10得到3/5及1积分，不能逐注舍入成0。每代理结果超过int64则整个当前页回滚并停止，不截断、封顶或转为负数。

`commission_earnings`保存该run及代理的精确总分数和最终整数，禁止修改或删除。原投注快照保持物理JSONB值，不通过时间反序列化再序列化改写其拼写。计算行校验品牌、订单、金额、原快照、结算代次及对应审计；分配校验沿路径比例差；汇总校验全量分配和最终取整。进入后续阶段必须有全部目标、节点分配及代理汇总，孤立run/操作不能提交。

## 更正与并发证据

证据计数属于具体周期，不是品牌所有未来期次共用的重算标志。相关期次离开或进入已结算状态、最终结果/任务变化，以及已最终订单的相关变更，会推进该周期的证据计数。无关未来期次结算不让旧周/月批次反复失效。

worker持有周期行锁，在读取期次时使用共享锁及NOWAIT；期次更新触发的证据计数更新若正等待周期行，worker不反向等待该期次，避免锁循环。每页结束即释放，核算不锁钱包。相关证据变化后，旧run、计算、分配和汇总原样保留，周期重新等待并建立下一代。普通列表可能短暂仍显示ready，但evidence_current为false；旧金额不是当前授权。

未来审核/派发必须在写事务内重新核验证据、目标、权限、状态及金额，不接受较早只读返回的ready/evidence_current作为入账凭证。派发若需要周期、期次及钱包锁，仍需处理NOWAIT与补偿顺序；本阶段尚无派发锁或佣金积分入账。

## 管理接口与权限

以下路径均在`/api/v1/admin/commission-cycles`下：

- GET集合及GET`/{id}`读取当前周期。
- POST集合以anchor_order_id、reason创建，返回201的原始enumerating回执。
- GET`/{id}/earnings`读取当前run的核算金额，不是实际余额。
- POST`/{id}/retry`以version、reason重试failed周期，保留失败及原代次。
- GET`/{id}/runs`读取全部代次，包括abandoned。
- GET`/{id}/runs/{runID}/calculations`明确指定代次读取净化后的计算轨迹，不替换为当前代次。

读取使用commission.view.brand或platform，并在当前会话、权限和审计事务内提交。创建/重试分别要求品牌run/retry权限及view，超级管理员不能写；disabled品牌不允许新登记或手动重试，暂停不取消已登记核算。分页默认20、上限100、offset上限1000000，未知/重复/空查询参数拒绝。计数和总额为字符串，单笔积分保持精确int64字符串。

写操作带幂等键，重放前重新核验当前授权和品牌状态。创建回执不会被worker推进后的状态覆盖；该接口按经校验的原始正文指纹比较，空白改变也属于不同正文。公开DTO不含原始规则快照、代理路径、账户编号或worker游标；管理员可查版本、原因、审计和历史代次。

## 后续金融闭环

尚需自动周期发现、管理员审核、按配置的人工/系统派发、佣金积分幂等入账、独立人工调整、已派发更正补偿、报表/通知及完整管理界面。周期内人工/自动模式混合时采用哪种审核策略仍待用户选择，不能由当前政策覆盖旧投注的审核要求。

这些核算记录不会改变用户或代理钱包、投注/提现周期，也不代表生产500次/秒容量、客户人工代码审核或完整平台交付已经完成。
