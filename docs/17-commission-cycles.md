# 佣金周期核算与代次历史

0048把佣金政策和真实注单事实接入持久化周期核算；0049接入自动发现到期窗口；0050接入独立派发开关、单人审核与佣金来源实际入账。平台worker分批登记、枚举、等待所有注单最终完成、记录精确差额并按代理统一取整，也保留管理员登记入口。`ready`只是核算完成，派发进度必须另查commission_payments及关联账本；0051/0052追加[独立人工修正及入账通知](18-commission-adjustments.md)，已派发后的结果更正补偿仍需实现。

## 周期归属与登记

创建请求只提供真实锚定注单编号和原因。服务读取该注单已保存、已启用的金融政策，按投注时间计算完整UTC半开区间；不使用今天的规则替代旧快照。窗口必须已经结束，同一品牌及起止时刻只能登记一个周期。不同规则版本若映射到同一UTC窗口，仍属于同一周期，避免分版本提前舍入。

登记在金融政策上取得短暂独占准入锁，等待此前持有共享锁的投注完成。登记后，数据库禁止向该已封存窗口补插回溯时间的投注。订单身份、投注时间、历史快照不能改写或删除，因此worker可逐页建立稳定清单，不需把整月订单留在一个事务中。

清单包含窗口内全部品牌投注，包含关闭金融政策、无代理、取消或异常的订单。每笔订单根据自己的金融快照判断是否属于本次周期及是否计佣；其他日历映射到不同窗口时记录other_cycle，不在本次产生分配，也不能重复作为本次收入。旧NULL或损坏证据明确失败，不补造规则或假定零额。

系统登记和管理员登记共享品牌及UTC窗口唯一约束和准入锁，竞争时重新读取同一窗口；已登记周期的分页处理、等待和更正后重新核算由平台worker自动推进。系统创建的creation_actor_type为system且created_by为NULL，不借用管理员身份；旧周期及人工创建仍为admin及真实管理员编号。当前读取总返回创建来源；0048已有幂等回执不改写，可缺少新增来源字段，其含义仍是admin。

## 自动发现队列

0049在真实投注事务的AFTER INSERT中，为保存了启用金融政策的订单创建commission_discovery记录。队列编号就是注单编号，每单最多一条，投注回滚时队列一起回滚；没有每彩票期次计提或资金记录。升级时只把已有真实启用快照排入队列，不给NULL、禁用快照补造规则。无投注的空周期不生成收入或空佣金周期。

发现任务每次最多处理100记录，每条独立事务，按next_check_at和编号用SKIP LOCKED分配。第一次读取并核验真实历史修订、归属及快照，计算该投注的完整日历窗口；未来窗口保存起止时间并将下次检查定在window_to。投注时的周/月、时区、短月规则不因现在改政策或禁用佣金而改变。数据库同时精确校验窗口，拒绝只包含投注时间但不等于原日历窗口的写入；不存在或重复的夏令时边界拒绝。

到期后复用同一窗口已有周期，或以system审计创建新周期。pending→registered只表示已关联核算周期，即使该周期还在等待结算或已经failed，也不自动重试周期、不代表佣金支付完成。多笔订单可以关联同一周期，只产生一条周期创建记录；不同投注日历映射到不同窗口时仍独立登记。

发现任务在品牌共享锁及金融政策独占准入锁上使用NOWAIT；已有周期无需再次获取政策准入锁。锁忙整条回滚并延后1秒，不能被记录为证据损坏。disabled品牌的尚未登记记录延后1分钟，保留原规则等待品牌恢复；暂停允许登记。已登记周期继续原核算流程。发现任务独立于核算任务运行，100毫秒检查一次且每次事务处理有界；该参数不等于已证明500次/秒生产容量。

证据或存储错误整条回滚，再以system审计将该记录标为failed并保存通用错误码；不泄露原始快照或数据库错误。运营须按真实版本和原因显式重试，failed→pending保留历次审计；证据问题未解决仍会失败。正常未来等待和锁忙调度不递增金融版本或生成重复审计。窗口一经保存不可改变，registered记录不能重置、删除或改投其他周期。

管理端GET`/api/v1/admin/commission-discovery`使用品牌/平台commission.view权限，分页与周期列表一致。POST`/api/v1/admin/commission-discovery/{id}/retry`使用view加品牌commission.retry权限及幂等键，拒绝超级管理员写入，正文为version、reason；重放重新授权并返回原pending回执，不以后台已登记状态覆盖。无手动新增或批量强制成功接口，也不接受客户端窗口、规则快照或系统身份。

## 持久化阶段

| 状态 | 含义 |
| --- | --- |
| enumerating | 每页最多100笔，按placed_at及UUID建立不可变清单 |
| waiting | 清单完整，但仍有投注或结算未最终完成；5秒后再检查，不忽略或移入下期 |
| calculating | 新核算代次逐页校验最终结算及购买快照，保存精确分配 |
| summarizing | 全部目标已核算，按代理汇总并一次四舍五入 |
| ready | 当前代次全部核算及汇总完成；仅核算状态，不说明审核或入账状态 |
| failed | 损坏证据、超限或存储失败停止；运营按版本和原因显式重试 |

系统并发worker使用SKIP LOCKED取得周期，每页独立提交。临时的期次锁争用采用NOWAIT，回滚并延后重试，不当作永久证据失败。等待轮询只更新调度时刻，不为每次轮询生成金融版本或海量审计；实际阶段、页提交、失效、失败及重试都有不可变操作记录。

## 数据与精确金额

`commission_cycles`保存品牌、窗口、锚单及代表日历、状态/版本、清单游标/数量、当前run、证据计数和创建审计。`commission_cycle_targets`保存冻结的订单编号与投注时间，不保存可改写的投注内容。`commission_runs`按周期递增generation，保留计算游标、汇总游标、证据计数及阶段，失效run标为abandoned，不删除数据。

`commission_calculations`每个run及订单唯一，保存最终状态、基数、当前结算任务/计算/代次、原始JSONB金融快照及页审计。`commission_allocations`按run、订单及代理唯一，保存受益会员和约分后的精确分数。停用代理不从路径删除，仍使用购买时的比例；不读取今天的比例来补算。禁用政策、无归属、其他周期、取消和异常均有明确排除原因；有效中奖在loss模式下可保留零基数轨迹，不计输钱佣金。

比例精度最多六位小数，单笔约分分母必为1000000的约数。数据库使用numeric把分数精确换算为百万分之一单位后按代理汇总，再由任意精度整数/分数核心统一half-up。两笔3/10得到3/5及1积分，不能逐注舍入成0。每代理结果超过int64则整个当前页回滚并停止，不截断、封顶或转为负数。

`commission_earnings`保存该run及代理的精确总分数和最终整数，禁止修改或删除。原投注快照保持物理JSONB值，不通过时间反序列化再序列化改写其拼写。计算行校验品牌、订单、金额、原快照、结算代次及对应审计；分配校验沿路径比例差；汇总校验全量分配和最终取整。进入后续阶段必须有全部目标、节点分配及代理汇总，孤立run/操作不能提交。

## 更正与并发证据

证据计数属于具体周期，不是品牌所有未来期次共用的重算标志。相关期次离开或进入已结算状态、最终结果/任务变化，以及已最终订单的相关变更，会推进该周期的证据计数。无关未来期次结算不让旧周/月批次反复失效。

worker持有周期行锁，在读取期次时使用共享锁及NOWAIT；期次更新触发的证据计数更新若正等待周期行，worker不反向等待该期次，避免锁循环。每页结束即释放，核算不锁钱包。相关证据变化后，旧run、计算、分配和汇总原样保留，周期重新等待并建立下一代。普通列表可能短暂仍显示ready，但evidence_current为false；旧金额不是当前授权。

0050审核/派发在写事务内重新核验证据、目标、权限、状态及金额，不接受较早只读返回的ready/evidence_current作为入账凭证。派发持有周期证据行锁，期次或订单变更必须更新同一证据计数才能提交；每次入账重新匹配当前订单、金额、原规则及最终结算代次。钱包及交叉锁使用NOWAIT，结算持有钱包等待周期时派发回滚，不反向等待钱包。

## 管理接口与权限

以下路径均在`/api/v1/admin/commission-cycles`下：

- GET集合及GET`/{id}`读取当前周期。
- POST集合以anchor_order_id、reason创建，返回201的原始enumerating回执。
- GET`/{id}/earnings`读取当前run的核算金额，不是实际余额。
- POST`/{id}/retry`以version、reason重试failed周期，保留失败及原代次。
- GET`/{id}/runs`读取全部代次，包括abandoned。
- GET`/{id}/runs/{runID}/calculations`明确指定代次读取净化后的计算轨迹，不替换为当前代次。

读取使用commission.view.brand或platform，并在当前会话、权限和审计事务内提交。创建/重试分别要求品牌run/retry权限及view，超级管理员不能写；disabled品牌不允许新登记或手动重试，暂停不取消已登记核算。分页默认20、上限100、offset上限1000000，未知/重复/空查询参数拒绝。计数和总额为字符串，单笔积分保持精确int64字符串。

写操作带幂等键，重放前重新核验当前授权和品牌状态。创建回执不会被worker推进后的状态覆盖；该接口按经校验的原始正文指纹比较，空白改变也属于不同正文。公开DTO不含原始规则快照、代理路径、账户编号或worker游标；管理员可查版本、原因、审计和历史代次。

## 周期和发现管理界面

后台佣金页按当前账号和品牌加载周期与发现队列，PC和移动端使用同一响应式页面，中英切换不重新提交请求。周期详情独立读取当前汇总、代次历史及明确选择代次的计算轨迹，各自分页。时间以UTC显示到秒，计数、总积分、单笔积分与分子分母保持精确字符串；不把合计强制转换为JavaScript Number。ready标为核算就绪，不能据此宣称未派发；evidence_current为false时显示证据过期，当前汇总代次与详情不一致时拒绝显示混合金额，提示重新读取。

页面提供锚单及原因登记、失败周期重试、失败发现记录重试。查看使用commission.view品牌或平台授权，登记及重试分别检查精确品牌run/retry权限；平台管理员只读。账号、品牌、权限或会话变化会清理可见旧数据并拒绝迟到响应；注销、401和账号替换清除当前会话的待恢复请求。离开佣金页但仍处于同一登录会话时，原请求仅保留在内存，不保存Cookie、访问令牌或请求意图到浏览器持久存储。

写入先冻结目标、版本、原因和幂等键，展示确认内容，再由操作员勾选提交。网络、5xx、成功但格式错误的响应都按未知结果处理，仅允许确认后恢复完全相同的原正文和原键；刷新列表、翻页、切页及后来看到当前状态不能当作原请求已确认。409同样保留原请求，必须明确重新读取相关数据、核对并勾选丢弃后才能重新填写。重读使用请求序号及共享读取序号，旧响应不得覆盖更新的读取或解锁旧冲突确认；发现记录离开当前页时不保留可重试的旧选择。

原始写入回执的状态、版本、编号和审计与当前状态分开显示。后台推进到ready/registered不覆盖回执中的enumerating/pending；旧请求成功只清除当前作用域且同键的意图。所有金额仍是核算结果，本页没有审核、派发、改金额、钱包调整或奖励发放按钮。

独立browserfixture使用正常注册、代理归属、下注、不同开奖号、人工结算审批及核算服务建立真实测试链路。测试通过显式任务推进证明丢失回执后的原键恢复，并在前后比较完整资金指纹。该构建标签不进入生产；初始化仅允许列出的回环测试库、测试环境及显式确认，拒绝已有身份的钱包库，不提供重置或绕过数据库守卫入口。

## 派发启用与审核

新增brand_commission_payment_policies运行开关，所有已有和新品牌均以enabled=false及version=1初始化。修改必须具备品牌commission_payment_policy.write和commission.view权限，提供版本与原因；政策修订及审计不可改写。此开关控制实际入账，不改变投注时的经济规则。开启会处理已有核算就绪但未派发的历史周期；自动快照周期可能立即入账，管理员须在确认页知悉这一影响。关闭只暂停后续入账，不撤销已入账积分或原审核记录。

任务以当前完整run保存整数总额、受益人数、证据计数及不可变模式。模式只汇总本run的eligible注单快照，包含有效零基数，不包含取消、异常等排除项。全人工为awaiting_approval，需单个品牌管理员按版本和原因批准；全自动为系统授权paying。没有eligible注单时为none，系统完成零金额任务，不写零账本。2026-10-08确认OPEN-115后，0054将manual/automatic混合的新任务设为awaiting_approval，保留payout_mode=mixed，整个周期须人工批准，不单独派发自动部分。

0054不改写旧任务、创建审计、投注快照或任何金额。仅旧state=blocked、payout_mode=mixed、错误码为COMMISSION_PAYMENT_MODE_UNRESOLVED、尚无批准且未创建任何派发目标的任务，可以沿用approve入口显式批准；工作器不会自动解除其阻止。当前运行开关、品牌权限、版本和核算证据仍须全部有效。更正、证据损坏及其他blocked任务均不能借此批准；已批准的mixed任务失败后只能按原批准显式retry，不重新授权或重复入账。

同一周期只允许一条非stale派发任务，同一cycle/run最多一条。审核、派发和失败重试使用独立金融权限，不借用核算run/retry权限；超级管理员只读。批准固定于本run及当时总额，后台不能修改金额或将批准转用到新的核算代次。品牌paused可继续财务流程，disabled禁止新授权及入账。

## 佣金目标与积分流水

commission_payment_targets逐项绑定该任务run的真实earning、代理及品牌会员。每个工作步骤只处理一个目标并独立提交；工作器与核算、发现任务使用独立循环。正额通过正式points.Store.Post进入commission.available，entry_type=commission、reference_type=commission_payment_target、reference_id=目标编号、operation_key=`commission-payment:<目标编号>`。其他15个桶不变，每笔流水保存完整之前、变动和之后积分；零金额目标有审计且无账本记录。

目标完成、账本入账、钱包推进、积分审计及派发版本步骤在同一事务提交。数据库同时拒绝无批准、错误受益人/来源/金额、孤立账本、孤立完成目标和重复ledger关联；目标必须有对应支付版本及步骤，不能单独标paid。派发paid要求全部目标完成及总额相等，部分成功仍为paying。失败整笔回滚，保留已成功目标，再记录failed及通用错误码；仅运营按真实版本显式retry，继续未完成目标，不重新发放已完成目标。锁忙或暂时调度不作为永久财务失败。

相关证据变化前尚无正额入账时，旧任务stale并保留原审批及零金额轨迹，新run可单独登记和审核。有任何正额已入账时，原任务blocked及COMMISSION_PAYMENT_CORRECTION_REQUIRED，保留已发总额并停止该周期的新发放；不得以新run完整总额再发一次。OPEN-116已确认：追回只扣commission.available，不足时保留人工待处理并暂停周期，运营处理后显式继续；不扣其他来源、不自动解冻、不形成负余额，也不因余额补足自动恢复。差额补发、追回任务和人工恢复尚未实现，不能把blocked当成已补偿或本模块全部完成。
