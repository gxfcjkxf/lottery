# 58. 移动端六合彩连续选号与首期交付

本页是已退出的新销售专用前端的历史验收记录。六合彩、加拿大彩当前新投注统一使用配置式页面；本页的专用底栏、分组帮助和登录选号草稿已移除。原购买记录、未结订单结算和资金账本保留。当前操作流程见 [59号第15.13节](59-configurable-mark-six-rule-design.md#1513-六合彩加拿大专用新销售退出)。

本轮按已确认草图落地交互，保留现有翡翠绿、琥珀色、Slate 设计令牌和四个底部导航。按后续逐项确认补齐玩法、A/B赔率、报价与判奖；参考规则页中的冲突以用户明确确认的口径为准。

## 已落地的操作流程

| 操作 | 当前行为 |
| --- | --- |
| 连续选择普通项目 | 点选加入，再点取消；跨现有玩法分组累计。每选一项不再弹出确认层。 |
| 底部汇总 | 有项目才出现，显示展开后的注数和投注积分。点击展开/收起，保留选择和金额；收起时继续选号不会自动展开。 |
| 核对金额 | 保留统一金额、“应用到全部”、逐项金额及删除。删到最后一项后汇总消失。 |
| 组合玩法 | 先选择子玩法、号码池，再加入批次，底栏汇总实际组合注数。未加入组合时切换分组/子玩法会要求确认放弃。重复组合被拒绝后保留候选号码。 |
| 未登录选号 | 明确点击“登录后投注”才保存一次性未提交草稿；登录后返回原品牌、原彩种，恢复期次、所见赔率和金额，仍须人工核对确认。草稿与已提交请求分开存储。 |
| 确认投注 | 沿用服务端报价和实时身份校验；赔率/版本/金额变化在同一核对层展示新明细，再次明确确认才提交。 |
| 成功回执 | 使用服务端返回的注单编号、期号和总额，提供注单、历史开奖和重复选号入口。 |
| 结果未知 | 保留原请求内容、账户归属和请求键，恢复后自动展开只读核对层；只能重试原请求，不能修改金额、清空或重建订单。 |
| 切期/封盘/暂停 | 已选号绑定首次选择时的期次；轮询切期后明确提示并禁止提交，须清空重选，禁止自动迁入新一期。未加入的组合选号同样绑定期次。 |
| 读取失败 | 明确报错并阻止按缓存目录继续下单，不伪造余额或默认成功。 |

普通未提交草稿仍不作为长期购物车：正常离开或刷新不自动恢复；只有明确的登录衔接会做一次性恢复。已提交但结果未知的请求继续使用既有持久化保护。

## 已确认规则

- **生肖不中、尾数不中**：用户确认一肖至五肖不中、一尾至五尾不中均加入。检查六个正码及一个特码共七球；所选组合的全部生肖或尾数均未出现才中奖，出现任意一个则该组合未中奖。49 正常参与其本期生肖及 9 尾的匹配。每个中奖组合只派彩一次，采用对应玩法档位的固定赔率，A/B 两盘分别配置，不取组合成员赔率的最低或最高值。此项已实现；与按号码选择的五至十不中分开，后者保留。

- **正码过关**：用户确认最少 2 关、最多 6 关，每个正码位置最多选一项。例如正1大＋正2单可组成两关，正1大＋正1单不能组成两关。各关按其所选项目分别判奖，组合赔率为各关赔率之积；发生和局的关按赔率 1 计算，有任一未中奖的关则该过关注单未中奖，其余有效关均命中才中奖。正码位置波色开 49 按已确认的绿波中奖、红蓝未中奖处理，不误归为和局。由于每位置最多一关、至少两关且开奖号码不重复，不额外设计“各关均因开 49 和局”的不可达场景。此项已实现。

- **正码1–6位置波色的 49**：用户确认某个正码位置开出 49 时，该位置的绿波中奖，红波、蓝波未中奖。此项已实现；不将此确认扩展到位置大小、单双或合数，后者仍按参考页的 49 和局口径。不同位置分别按该位置实际开奖号码判奖。

- **组合赔率口径**：用户确认不采用参考页“最低／最高”取值机制，按具体玩法的已配置赔率计价，不从组合成员的生肖、尾数或号码赔率中选最低或最高。A/B 两盘分别配置各自赔率。此项只确定赔率取值方式，不改变已经存在的奖级命中条件或重复派彩规则；已有独立奖级和含 0 尾档的调整不在此次取最低／最高的确认范围内。按玩法发布固定赔率的现有方式保留。

- **正肖**：以用户最新明确的口径为准，只检查六个正码，**正码中的 49 正常参与生肖匹配和中奖计次**；包括 49 在内，任何号码若处于特码位置，都不参与正肖。按本期生肖快照统计六个正码中属于所选生肖的实际命中数，不另设“四次封顶”。命中后净盈利随命中次数增加，本金只返一次。设投注积分为 S、含本金赔率为 O、六个正码中的实际命中数为 N：N 为 0 时未中奖、返还 0；N 大于 0 时总返还为 S + S × (O − 1) × N，继续遵循平台既有整数积分舍入规则。示例 S=100、O=1.8，命中一至五次的净盈利分别为 80/160/240/320/400，总返还分别为 180/260/340/420/500；若原有四次命中之外再有同生肖的正码 49，则按五次计，总返还 500；若 49 位于特码，不增加次数。参考页示例最后一行的金额与此明确口径不一致，以用户本次说明为准。示例中的“龙对应 01”等历史号码不固化进实现，生肖映射继续取本期快照。此项已实现。

- **特码波色 49**：用户确认按参考页，特码开 49 时绿波中奖，红波、蓝波未中奖。判奖及用户端说明已同步切换；位置波色按独立确认实施。已有已结算记录不重新判奖。

- **A/B 盘**：加入 A、B 两盘，仅区分赔率，玩法和判奖规则共用。此项已实现。确认范围不包含其他未明确的盘口差异。

## 发布与历史记录

- 本轮规则事项均已确认，没有因参考页“最低/最高”措辞而留下的动态取价逻辑；统一采用具体玩法已发布的固定赔率。
- 平台、品牌同时保存 `odds`（A）和 `odds_b`（B）。品牌各盘不得高于对应平台盘赔率；完整目录共669个赔率项，独立奖级也必须配置。过关赔率直接使用各位置已发布的属性赔率之积，不另设过关固定赔率。
- 现有配置不会复制A盘填充B盘，新增项也不自动采用其他价格。未补齐平台和品牌两盘时明确提示并暂停新投注；通过原有分组批量填价完成配置。
- 本轮读取开发库：六合彩10条已结算、0条待结算，包含旧合肖编码。保留记录、赔率、结果和积分流水，迁移仅给历史注单标记原有A盘，不重算或重写已结算明细。开发API与结算进程已更新，健康检查通过。
- 新单要求显式盘口；盘口与原购买快照、过关各关赔率均不可修改。后续调价不影响已购注单，未知结果只允许原内容原请求键重试。
- 号码属性发布要求49为绿波。历史期次及注单属性保持不可变；年度映射由后台发布，不在程序内推算生肖。
