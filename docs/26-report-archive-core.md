# 日月报表不可变快照与版本服务

品牌日/月归档采用已确认的快照与追加版本方式：财务按实际入账时间统计，后续更正不覆盖旧档，重新观察时生成新版本，默认不自动删除。归档不是停止记账的财务封账，也不证明所有注单已经最终完成或外部支付到账。

当前实现为内部统计与持久服务，包含0064、0065迁移、Go调用、权限判定、审计和数据库守卫。管理HTTP、下载授权、幂等原回执、双端后台页面及自动归档任务尚未接入；接入它们时遵守以下边界，不把内部方法当成已发布接口。

## 日历与版本范围

创建输入为kind、period_key、expected_revision和reason。kind为daily或monthly，键分别为严格YYYY-MM-DD或YYYY-MM；不接受空白、补零替代格式、无效日期或任意UTC区间。日历年份为0001至9998，解析后的UTC边界必须落在0001至9999；不支持机器本地Local别名。

首个版本按品牌当前具名时区，把民用日或民用月转换为UTC半开区间[from,to)。使用真实日历边界，不加固定24小时或30天。夏令时日可以是23或25小时；重复午夜从第一次出现开始，午夜跳时从该日第一个真实时刻开始，整天跳过的日期拒绝。Go和PostgreSQL使用相同边界算法，并对纽约、哈瓦那、圣保罗和阿皮亚场景验证一致。

只有to已经过去的日/月能保存归档。新版本复用原记录的timezone、from和to，不随品牌后来修改时区或重新解释日历而改变原范围。同品牌、kind和period_key组成一个版本系列，revision从1连续增加，previous_id指向上一版；不存在覆盖、删除或重置版本的正常操作。

expected_revision为调用方确认的原最新版本；第一版为0。过期版本拒绝，不自动替运营人员选择新版本；同一系列并发提交只有一个成功，忙锁或版本冲突需重新读取。原因须有效UTF-8、非空、已去首尾空白、最多500字节且不含NUL、CR、LF。

## 单一统计快照

reporting.Service.CaptureArchive和CaptureArchiveTimezone在调用方主库事务内执行一个SQL语句，使用同一statement_timestamp和数据库观察快照。后者只覆盖时区标题，不改变调用方明确提供的绝对时间范围；持久服务使用已解析、已冻结的日/月区间。

ArchiveSnapshot的封闭字段为brand_id、format_version、snapshot_at、timezone、from、to、betting、ledger、wallet_snapshot、withdrawals、commissions、rewards、reward_orders，格式版本固定1。统计区块复用现有报表的字段和时间口径，不输出会员身份、支付证明、私有配置或操作原因。

| 区块 | 时间与事实口径 |
|---|---|
| betting | 原投注时间范围内，在snapshot_at观察到的当前最终代次；未结算、异常、取消及未完成更正分开统计 |
| ledger | 实际ledger.created_at内的全部积分变动，保留历史派奖及反向，状态间转移净额为0 |
| wallet_snapshot | at_snapshot及balances；当前账户/可用/冻结/提现预留/总积分观察，不是to时刻的历史余额 |
| withdrawals | 申请created_at范围内、在snapshot_at观察到的状态分布，不冒充实际外部付款 |
| commissions | 实际入账时间的原派发、人工修正及非零结果更正，旧run变更不抹除已发生记录 |
| rewards | 实际奖励发放/反向入账时间与不可变动作审计，撤销不删除原发放 |
| reward_orders | 创建时间范围内，在snapshot_at观察到的granted、revocation_pending、revoked状态 |

所有计数和积分聚合为精确十进制字符串，可以超过int64；净额可以为负。各区块独立聚合，不把人工修正、多次更正或奖励动作连接到原信用记录后重复累计。没有相应事实时才返回规范0，不用假流水填充测试或业务记录。

归档保存当时观察到的内容。后来完成的结算、撤销、补偿或迟提交事务可以改变实时报告及新归档版本，不回填旧版。当前余额变化可以使同一个过去区间的新版本不同，但不能据此声称过去日末余额发生了改写。

## 持久服务和权限

reportarchive.Service提供CreateTx、ReadTx、ListTx和CanonicalPayloadTx，调用方拥有事务、当前认证、授权复核、幂等和最终提交/回滚。不得提交返回错误后的事务，也不得直接把内部读取结果通过无审计HTTP释放。

纯权限判定为report_archive.view.brand或显式report_archive.view.platform；创建还需品牌成员范围及report_archive.create.brand，超级管理员只读。超级管理员标记不替代显式查看权限。当前没有为引导或普通角色授予新能力，也没有新增公开路由；后续接口上线时再注册权限与引导配置。暂停品牌允许归档，停用品牌拒绝新建，历史读取仍由明确授权决定。

Record字段为id、brand_id、window、revision、previous_id、snapshot_at、created_by、reason、payload_sha256、audit_log_id、created_at和snapshot。window包含kind、period_key、timezone、from、to。created_at与snapshot_at相同；这是统计观察时刻，不是所有财务业务完成时刻。列表limit为1至100、offset为0至1000000，按created_at/id倒序，同语句返回精确总数和页。

创建先锁定品牌配置和该归档系列，追加匹配意图审计，再用同一个SQL语句捕获与插入快照。数据库只读STABLE守卫独立重算该语句的实际统计内容、校验时间、原版本、前后审计和摘要。归档与审计同事务，审计失败或伪造内容不能留下半份记录。守卫共用捕获语句的观察快照，正常资金交易在归档读取期间仍可提交；不加全品牌记账排他锁，也不锁定全部钱包。

report_archives拒绝UPDATE、DELETE和TRUNCATE。读取校验保存内容的SHA-256，损坏返回ErrIntegrity，不返回修正后的假快照或自动修复；前一版摘要损坏时也不得继续追加版本，服务与数据库守卫分别校验。三个函数固定pg_catalog、应用schema、pg_temp查找路径。数据库所有者禁用守卫或篡改系统本身不在这些约束可认证的威胁范围内，生产还需最小数据库权限、备份和客户人工审核。

## 内容摘要与后续下载

payload_sha256针对PostgreSQL payload::text的原始UTF-8字节计算。CanonicalPayloadTx返回这些原字节和摘要；不能把Go DTO重新JSON序列化后仍声称是同一个文件摘要，因为键顺序、空白和时间字符串可能不同。

未来下载需独立授权与查询审计，提交审计和复核会话后才输出完整文件。不得通过分页拼凑快照、输出半份附件、自动下载迟到响应或把归档摘要当成积分修复授权。本阶段只有内部原字节读取，不是已实现下载端点或财务CSV模板。

## 升级和验收边界

0063到0065仅新增三个只读/守卫函数及归档表，不改旧业务、账本、审计、角色、通知或对账结果，不为历史日/月补造已归档记录。实际升级测试保留112张旧表的逐行摘要，包含真实积分入账；重复迁移仍不改旧数据，新表保持空。

真实数据库验收覆盖版本追加、原范围/时区冻结、未来期拒绝、跨品牌读取、并发版本冲突、审计回滚、伪造统计/摘要拒绝、UPDATE/DELETE/TRUNCATE守卫、原字节摘要、损坏拒绝及归档读取期间真实资金提交。真实投注最终代次、历史派奖/反向、原佣金/人工修正/结果追回、四来源提现、奖励发放/撤销及跨int64余额与实时报告逐项比较。

这证明内部快照与版本核心，不代表后台已可操作归档、自动日/月任务已运行、财务CSV模板已确认、真机或生产容量已验收。后续阶段必须完成管理接口、未知请求原键恢复、查看/下载、PC与移动UI及自动任务配置；数据自动删除默认保持关闭，OPEN-106的外部文件保留要求和财务模板仍单独确认。
