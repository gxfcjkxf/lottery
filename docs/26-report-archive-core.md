# 日月报表不可变快照与版本服务

品牌日/月归档采用已确认的快照与追加版本方式：财务按实际入账时间统计，后续更正不覆盖旧档，重新观察时生成新版本，默认不自动删除。归档不是停止记账的财务封账，也不证明所有注单已经最终完成或外部支付到账。

0064、0065实现统计与持久服务，0066注册独立权限，并接入四条正式管理接口、幂等原回执和原字节下载。后台“日月归档”已提供PC/移动双语查询、人工创建/追加、原回执恢复和验证后下载。0067接入默认关闭的[自动核心与worker](27-automatic-report-archive-core.md)，[配置只读和任务查询/重试](28-report-archive-task-management.md)已接入双端页面；[正式配置PUT](29-report-archive-activation.md)已按首次当天/月口径接入，无公开历史回补接口，配置编辑页面继续实施。

## 日历与版本范围

创建输入为kind、period_key、expected_revision和reason。kind为daily或monthly，键分别为严格YYYY-MM-DD或YYYY-MM；不接受空白、补零替代格式、无效日期或任意UTC区间。日历年份为0001至9998，解析后的UTC边界必须落在0001至9999；不支持机器本地Local别名。

首个版本按品牌当前具名时区，把民用日或民用月转换为UTC半开区间[from,to)。使用真实日历边界，不加固定24小时或30天。夏令时日可以是23或25小时；重复午夜从第一次出现开始，午夜跳时从该日第一个真实时刻开始，整天跳过的日期拒绝。0067修正有效日期紧邻跳过日期的结束边界，保留前一天，不制造不存在的日期；既有版本范围不变。Go和PostgreSQL对纽约、哈瓦那、圣保罗和阿皮亚场景验证一致。

只有to已经过去的日/月能保存归档。新版本复用原记录的timezone、from和to，不随品牌后来修改时区或重新解释日历而改变原范围。同品牌、kind和period_key组成一个版本系列，revision从1连续增加，previous_id指向上一版；不存在覆盖、删除或重置版本的正常操作。

expected_revision为调用方确认的原最新版本；第一版为0。过期版本拒绝，不自动替运营人员选择新版本；同一系列并发提交只有一个成功，忙锁或版本冲突需重新读取。原因须有效UTF-8、非空、已去首尾空白、最多500字节且不含NUL、CR、LF。

## 单一统计快照

reporting.Service.CaptureArchive和CaptureArchiveTimezone在调用方主库事务内执行一个SQL语句，使用同一statement_timestamp和数据库观察快照。后者只覆盖时区标题，不改变调用方明确提供的绝对时间范围；持久服务使用已解析、已冻结的日/月区间。

ArchiveSnapshot的封闭字段为brand_id、format_version、snapshot_at、timezone、from、to、betting、ledger、wallet_snapshot、withdrawals、commissions、rewards、reward_orders，格式版本固定1。统计区块复用现有报表的字段和时间口径，不输出会员身份、支付证明、私有配置或操作原因。

| 区块 | 时间与事实口径 |
|---|---|
| betting | 原投注时间范围内，在snapshot_at观察到的当前最终代次；未结算、异常、取消及未完成更正分开统计 |
| ledger | 实际ledger.created_at内的全部积分变动，保留历史派奖及反向，状态间转移净额为0 |
| wallet_snapshot | at_snapshot及balances；当前账户/可用/冻结/提现预留/总积分观察，不是to时刻的历史余额 |
| withdrawals | 申请created_at范围内、在snapshot_at观察到的状态分布，不冒充实际外部付款 |
| commissions | 实际入账时间的原派发、人工修正及非零结果更正，旧run变更不抹除已发生记录 |
| rewards | 实际奖励发放/反向入账时间与不可变动作审计，撤销不删除原发放 |
| reward_orders | 创建时间范围内，在snapshot_at观察到的granted、revocation_pending、revoked状态 |

所有计数和积分聚合为精确十进制字符串，可以超过int64；净额可以为负。各区块独立聚合，不把人工修正、多次更正或奖励动作连接到原信用记录后重复累计。没有相应事实时才返回规范0，不用假流水填充测试或业务记录。

归档保存当时观察到的内容。后来完成的结算、撤销、补偿或迟提交事务可以改变实时报告及新归档版本，不回填旧版。当前余额变化可以使同一个过去区间的新版本不同，但不能据此声称过去日末余额发生了改写。

## 持久服务和权限

reportarchive.Service提供CreateTx、ReadTx、ListTx和CanonicalPayloadTx，调用方拥有事务、当前认证、授权复核、幂等和最终提交/回滚。不得提交返回错误后的事务，也不得直接把内部读取结果通过无审计HTTP释放。

纯权限判定为report_archive.view.brand或显式report_archive.view.platform；创建还需品牌成员范围及report_archive.create.brand，超级管理员只读。下载在查看权限之外还需report_archive.download.brand或report_archive.download.platform。超级管理员标记不替代显式查看或下载权限。0066只为既有品牌引导角色追加三项品牌能力，为已分配超级管理员的平台引导角色追加查看/下载，不扩大自定义角色；后续CLI管理员初始化采用相同默认能力。暂停品牌允许归档，停用品牌拒绝新建，历史读取仍由明确授权决定。

人工Record字段为id、brand_id、window、revision、previous_id、snapshot_at、created_by、reason、payload_sha256、audit_log_id、created_at和snapshot。0067系统记录created_by为null，并额外包含automation的task_id及policy_version；人工记录继续省略该对象。window包含kind、period_key、timezone、from、to。created_at与snapshot_at相同；这是统计观察时刻，不是所有财务业务完成时刻。列表limit为1至100、offset为0至1000000，按created_at/id倒序，同语句返回精确总数和页。

创建先锁定品牌配置和该归档系列，追加匹配意图审计，再用同一个SQL语句捕获与插入快照。数据库只读STABLE守卫独立重算该语句的实际统计内容、校验时间、原版本、前后审计和摘要。归档与审计同事务，审计失败或伪造内容不能留下半份记录。守卫共用捕获语句的观察快照，正常资金交易在归档读取期间仍可提交；不加全品牌记账排他锁，也不锁定全部钱包。

report_archives拒绝UPDATE、DELETE和TRUNCATE。读取校验保存内容的SHA-256，损坏返回ErrIntegrity，不返回修正后的假快照或自动修复；前一版摘要损坏时也不得继续追加版本，服务与数据库守卫分别校验。三个函数固定pg_catalog、应用schema、pg_temp查找路径。数据库所有者禁用守卫或篡改系统本身不在这些约束可认证的威胁范围内，生产还需最小数据库权限、备份和客户人工审核。

## 内容摘要与后续下载

payload_sha256针对PostgreSQL payload::text的原始UTF-8字节计算。CanonicalPayloadTx返回这些原字节和摘要；不能把Go DTO重新JSON序列化后仍声称是同一个文件摘要，因为键顺序、空白和时间字符串可能不同。

正式下载采用独立授权与查询审计，提交审计和复核会话后才输出完整文件。不得通过分页拼凑快照、自动下载迟到响应或把归档摘要当成积分修复授权。服务在发送前完整读取并验证文件；网络传输途中仍可能中断，客户端必须再次核验长度与摘要。本阶段下载JSON归档，不新增尚未确认的财务CSV模板。

## 正式管理接口

四条接口都属于/api/v1/admin，品牌由X-Brand-ID选择，不提供品牌路径别名。

| 方法与路径 | 输入与结果 |
|---|---|
| GET /report-archives | 仅limit与offset，默认20/0，返回Page |
| POST /report-archives | 封闭四字段输入，返回201原Record回执 |
| GET /report-archives/{id} | 不接受查询参数，返回该不可变Record |
| GET /report-archives/{id}/download | 不接受查询参数，返回原始裸JSON文件，不是API信封 |

所有GET拒绝正文和裸问号；分页拒绝重复、空值、未知键、负数、前导零及非规范整数。POST拒绝任意查询参数、重复/null/未知或缺失字段、无效日期、非法UTF-8及控制字符原因。expected_revision范围为0至9007199254740990；创建新版需要再加1，不能越过安全整数边界。输入正文最多16KiB并要求application/json与可信同源。

POST必须附Idempotency-Key及X-Report-Archive-Actor-ID，后者为确认时管理员ID，与当前实际身份不同返回401。服务规范化四字段JSON计算请求摘要；原键只能确认原输入，不能用于后来修改的原因、周期或版本。回执随创建事务保存加密内容，后来追加版本不改变原回执；刷新查询不能代替确认未知结果。重放前也核验当前授权，权限撤销后不释放旧回执。

所有操作使用主库事务，锁定当前权限并在业务读取后、审计等待后或写入提交前重新核验会话。品牌不存在404，范围越权403，当前品牌内不存在归档404；系列忙锁503不缓存回执，陈旧版本409，未到周期末或品牌停用409。技术、摘要或审计错误503，不发送快照或附件头，不提交半份归档、创建审计或成功回执。

下载Content-Type为application/json; charset=utf-8，文件名为report-archive-{UUID}-v{revision}.json。响应包含Content-Length、X-Content-SHA256、X-Archive-Revision和X-Archive-Format-Version。下载审计只保存archive_id、revision、format_version、payload_sha256和bytes，不复制文件内容或用户资料。服务器验证原字节摘要后提交审计，复核授权才开始输出，不能用DTO重序列化替代原文件。

## 管理端客户端边界

report-archives-api提供list、read、create与download，不自动下载或渲染页面。客户端拒绝未知字段、跨品牌或错误ID、非法版本和时间、错误分页数量及重复记录；七个统计块都使用精确十进制字符串与BigInt校验内部等式，不把聚合金额转成Number。保存原因兼容内部历史允许的非换行文本，新写原因不接受控制字符。

客户端校验snapshot_at、created_at、钱包at_snapshot和原范围关系，按纳秒级实际时刻比较Z与时区偏移的等价表示。归档期末必须不晚于观察时刻；时区不重新计算既有版本的范围。原Record不是原文件字节：下载先核验完整Content-Length、摘要、版本、格式及附件名，再校验原JSON内容与已选Record对应；时间字符串格式不同但实际时刻相同不能误报篡改，一纳秒的真实差异必须拒绝。

create发送确认时actor及原输入/键，要求201和expected_revision+1。网络中断、服务端错误或成功响应无法验证都返回UNKNOWN_WRITE_STATUS；调用方不得生成新键重试或把刷新列表当成原请求成功。后台按下述可视流程处理，SDK校验不能替代运营人员确认。

## 后台页面与原请求恢复

“日月归档”在桌面侧栏和移动更多菜单独立展示。日/月表单填写民用周期、确认的原最新版本与原因；首版输入0，“以此范围准备追加版本”仅复制所选档的周期和版本，不声称旧档必然仍是最新。最终版本冲突由服务端判定，不以当前一页列表推断整个范围不存在归档。

提交前冻结管理员、品牌、周期、版本、原因和唯一键，弹窗展示全部范围，勾选核对后才发送。一个管理员在一个品牌只保留一个未确定创建请求；该请求存在时锁住新创建及周期/类型/原因输入。刷新列表、改变语言、离页返回不清除原请求，也不自动重放。重放需再展示原输入并勾选确认；成功ACK独立保留，列表及详情分别读取、分别显示错误，后续查询失败不能把成功ACK改成未知或再次提交。

409保留原请求并标记冲突，禁止直接重放；必须成功重读当前列表和原所选档（如存在），再由运营人员勾选并明确丢弃，才允许准备新请求。该操作只是丢弃本地已被拒绝的输入，不删除服务器归档。迟到409只可标记同会话同键，页面已经返回也实时同步冲突。当前401/退出清除所有意图并推进会话代次；旧代次的401、成功或冲突不能影响新登录的意图。

归档意图仅放在会话内存，不存localStorage、sessionStorage或访问令牌。切品牌、账号或权限清空视图并忽略迟到读取，不能显示其他范围的原因/金额；旧品牌意图在同会话仍保留，回到有权范围才能核对恢复。创建和下载权限分别禁用，平台超管不能创建。

详情展示原范围、时区、观察时刻、前版、原因、创建人、审计ID与SHA-256，七块统计采用中英文运营标签。下载捕获所选档后调用原字节SDK校验，只有仍为当前账号/品牌/权限/所选档时才生成临时Blob并触发保存；切档、离页、权限变化或旧会话迟到响应不自动下载。临时URL释放，文件内容不写浏览器持久存储。
