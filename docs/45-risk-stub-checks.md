# 七组配置式伪检查交接

一期风控按品牌配置并提供伪检查，不做真实风险识别。年龄、地区、身份之外新增四组开关，覆盖设备/账号关联、投注风险、排除名单及责任博彩。全部初始关闭；关闭仅表示跳过，不是用户已通过验证。启用但没有真实适配器时返回review并拒绝新的受保护业务，不返回假验证成功、不收集新个人资料、不自动冻结资金。

## 当前配置和检查顺序

| 检查名称 | 必填布尔字段 | 范围 |
| --- | --- | --- |
| age | age_enabled | 年龄，另有minimum_age |
| region | region_enabled | 地区，另有allowed_countries |
| identity | identity_enabled | 身份验证 |
| account_risk | account_risk_enabled | 设备/IP/账号关联 |
| betting_risk | betting_risk_enabled | 异常投注、奖励滥用、套利、多账号 |
| exclusion | exclusion_enabled | 黑名单、自我排除 |
| responsible_gambling | responsible_gambling_enabled | 责任博彩、冷静期 |

config严格包含九键：表中七个boolean，加minimum_age和allowed_countries。年龄/名单原约束不变；缺字段、非boolean或额外字段均拒绝，不补默认值兼容旧请求。伪检查固定按表中顺序返回七项：关闭allow/CHECK_DISABLED，开启review/ADAPTER_NOT_CONFIGURED。任一开启即review，deny/freeze仅为保留决定类型，不会由当前伪适配器自动产生。

## 业务和操作边界

品牌后台通过既有政策PUT、原因、版本、单人核对、权限、审计和幂等保存；新开关也进入冻结的原请求和历史快照。显式检查记录与真实业务拒绝分开，前者不启动注册、投注或提现。平台后台只读取九键及七组说明，不提供编辑或运行检查入口。

真实新注册、首次加入/首次接受品牌条款、运营新增会员、投注预览/提交及提现申请使用现有准入检查。启用且未接入适配器即拒绝；已有正常登录、查询、取消、原路退款及既有订单处理不被当作新业务。重复拒绝的原键只返回原回执，不重复建拒绝证据。资格查询不代表资金授权，内部提现不代表外部付款。

这是四组伪检查开关，不是设备指纹、行为检测、名单管理、自助排除、倒计时冷静期或真人复核队列。真实服务、个体状态、规则和法律参数仍需后续实现及客户验收；不能用本开关宣称责任博彩或KYC已完成。

## 数据库和验证

直接整理进未发布的0001_baseline.up.sql：默认九键、配置约束、七项伪结果和拒绝约束一致。没有增量迁移、旧字段回填或旧格式兼容。现有开发库不会自动升级；新建UTF8空库，保留原库和其配置，前后端必须同时使用当前合同。

模型和真实数据库分别验证四个新开关独立review、缺失字段拒绝、审计/幂等及七项结果。HTTP四个子场景验证注册拒绝不建身份、不改账户数、积分或账本，原键重复仅一条拒绝证据。PC/360px验证四个编辑控件、账户关联风险单独启用、丢失回执的原键确认、真实注册拒绝和恢复原政策；平台双端只读展示与政策前后保持另验。具体执行结果见实施记录，不据专项推定完整CI通过。
