# 安全、风控与合规接口边界

## 1. 基本原则

- 客户和其法律顾问负责确认牌照、目标市场、年龄、地区、支付和博彩合规范围。
- 系统只能启用客户已获授权的品牌、彩种、地区和资金流程。
- 未完成法律确认的能力以配置开关关闭，不因前端隐藏而视为安全关闭。
- 所有高风险操作必须可追溯到账号、品牌、IP、请求 ID、原因和时间。

## 2. 认证和会话

- 密码使用经过审计的慢哈希算法；禁止明文保存和日志输出。
- 登录失败限速；连续失败触发账号或 IP 风险事件。
- 会话支持主动注销、踢人和品牌状态校验。
- 修改密码、补充首次用户名/手机号、Telegram 登录关联等敏感动作写审计。
- 第一阶段不实现二次验证和设备管理，但接口和配置结构预留。

## 3. 品牌隔离

- 品牌业务的API、服务层、数据库查询和缓存 key 都必须带品牌上下文；平台认证和创建品牌使用独立平台分区，不伪造品牌编号。
- 缓存 key 使用 `brand:{brand_id}:...` 前缀，禁止跨品牌复用用户余额、玩法和注单缓存。
- 后台导出、报表和审计查询必须再次校验品牌范围。
- 平台管理员可以跨品牌查看；用户账户修改、踢人和品牌用户状态修改仍按已确认权限执行。
- 定期执行跨品牌访问测试：改变 URL、请求头、ID 和分页条件都不能读到其他品牌数据。

品牌创建仅使用精确 `brand.create.platform` 平台角色权限；超级管理员标记和品牌角色中的同名字符串不授予权限。创建不自动授予任何品牌范围、用户写权限或资金权限。全局幂等回执使用独立表和绑定上下文的加密，重放前再次验证当前授权。空品牌库的管理Host仍须为服务器拥有者配置的启用平台入口，不信任转发Host或客户端选择的任意入口。

## 4. 风控配置

以下能力第一期使用配置开关、接口和伪实现，启用后才执行：

- 年龄验证；
- 地区/国家限制；
- 身份验证/KYC；
- 单用户投注限额；
- 单用户提现限额；
- 设备/IP/账号关联风险；
- 异常投注、刷奖励、套利和多账号检测；
- 黑名单和自我排除；
- 责任博彩提示和冷静期。

风控决策至少返回：`allow`、`review`、`deny`、`freeze`，并记录规则版本和命中原因。

当前已实现品牌年龄、地区、身份检查配置及显式管理检查接口，参见 [API合同](04-api-contract.md)。配置默认关闭，不设隐含法律年龄或市场；年龄18–120与两位大写国家代码只为工程输入约束，客户法律确认仍为OPEN-001。开启检查返回review/ADAPTER_NOT_CONFIGURED，关闭allow/CHECK_DISABLED；不收集真实个人资料，不返回已验证，不因信号freeze自动冻结账户。配置、历史与检查证据有独立品牌权限、版本、审计和加密幂等保护。

新注册、首次入品牌、运营新增/首次同意条款以及新投注已经接入服务端检查：任一检查开启且无适配器即拒绝，旧预览或客户端“已验证”声明不能放行。已有登录、查询、取消、原路退款仍可用。政策行共享锁与启用更新串行，业务拒绝的证据与加密负回执在业务回滚后同事务落库，失败不能保留半条证据或业务；只保存不可变版本、命中原因与内部标识，不采集证件或声称真实验证。

提现资金状态机与HTTP接口已接入，正式服务使用TurnoverChecker按实际有效投注和下单时N快照检查资格；品牌初始提现政策关闭，不默认允许申请。启用而未接入真实适配器的合规检查同样阻止申请，拒绝不占用积分。资格查询不代表授权、预留或外部出款。真实适配器、审核队列、黑名单、自我排除和责任博彩仍待后续。关闭合规检查仅表示跳过，不能据一条allow关闭生产合规验收项。实际客户上线必须完成法律确认和相应真实验证，OPEN-001保持开放。

## 5. 投注和资金保护

- 期次截止、品牌暂停、用户冻结和限额必须在服务端执行。
- 余额扣减、提现冻结和派奖不能通过客户端直接调用数据库或缓存。
- 充值人工确认、佣金人工修正、积分调整和结果纠正需要必填原因。
- 任何冲正使用新流水，不覆盖原流水。
- 外部来源响应必须保存来源、时间、摘要/哈希和校验结果。

## 6. 管理权限

高风险权限单独建模：

- `ledger.adjust`
- `draw.manual_create`
- `draw.correct`
- `settlement.retry`
- `withdrawal.approve`
- `withdrawal.mark_paid`
- `commission.adjust`
- `rule.publish`
- `audit.export`

第一期不要求双人复核，但每个权限都必须有审计和可查询记录；后续可通过配置升级为双人审批。

## 7. 数据和隐私

站内模板只接收受限纯文本，不能访问业务对象或执行脚本；变量仅真实事件的积分和本会员业务编号。消费者先验证不可变业务证据，再复制模板快照；模板编辑不产生资金、中奖或新通知。旧消息不覆盖，派奖/冲正另外保留不可编辑的历史事实说明。管理员理由及人员信息不发给用户，内容/历史有品牌边界和审计；配置投影、修订和事件不能靠任意JSON替代。模板及故障重试边界见 [通知合同](12-notification-templates.md)。

投注/账本导出是独立权限的财务数据读取，只提供当前品牌UUID、汇总和分组，不包含用户名、充值证明或内部操作理由。view与export各自必须满足，审计提交失败不返回文件，等待授权锁期间撤权不可使用旧快照绕过。CSV文本防公式执行、响应no-store，浏览器不持久缓存；下载后客户负责文件访问及保留。摘要用于传输核对，不是独立签名或防恶意代理篡改证明，详见 [CSV合同](11-report-csv-exports.md)。

- 只收集业务所需的用户资料。
- 隐私条款和服务协议保存版本、语言、时间和品牌。
- 密码、授权凭证、外部来源密钥、敏感身份数据加密或使用密钥引用保存。
- 日志脱敏；导出文件设置权限和过期时间。
- 数据删除、注销和保留周期必须在法律确认后配置；有审计、财务或结算义务的数据不能直接物理删除。

## 8. Web/PWA 安全

- HTTPS、HSTS、CSP、CSRF 防护、SameSite Cookie 和安全响应头。
- PWA service worker 不缓存账户余额、提现详情和下注 POST 响应。
- WAF、IP/账号限流、机器人检测和请求体大小限制。
- 前端展示的赔率、积分和规则只作展示，所有关键计算由后端完成。

## 9. 安全测试

第一阶段至少执行：

- 品牌越权测试；
- 角色权限矩阵测试；
- 重复提交、并发扣款和重复消费测试；
- SQL 注入、XSS、CSRF、会话固定和越权测试；
- 敏感日志扫描；
- 备份恢复和灾备演练；
- 500 次/秒投注压力下的安全与一致性测试。
