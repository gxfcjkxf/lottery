# UI 与交互规格

## 1. 终端策略

- `user-web`：用户端独立 PWA，移动端优先，同时适配桌面浏览器。
- `admin-web`：管理端独立 PWA，桌面端完整，移动端支持监控、查询、审核和应急操作。
- 第一阶段不上架任何应用市场。
- 两个项目共享品牌主题、基础组件、类型和多语言资源，但不能共享用户端与管理端的权限逻辑。

## 2. 品牌主题

主题配置至少包含：

- Logo、favicon；
- 主色、辅助色、成功/警告/错误色；
- 字体和字号层级；
- 圆角、阴影、按钮样式；
- 登录页、首页、游戏卡片和公告样式；
- 默认语言、可用语言和文案覆盖。

继承顺序为平台默认 → 品牌覆盖。主题配置发布后清理缓存并返回新版本号。

## 3. 用户端页面

### 3.1 页面路由

| 路由 | 页面 | 必要功能 |
|---|---|---|
| /login | 登录 | 用户名/手机号、密码、Telegram、验证码开关 |
| /register | 注册 | 用户凭证、协议勾选、品牌归属 |
| / | 游戏大厅 | 品牌主题、彩种卡片、公告、状态 |
| /games/:gameId | 彩种首页 | 当前期次、倒计时、玩法列表、开奖结果 |
| /games/:gameId/bet | 选号 | 号码池、玩法、附加属性、排除、复式、倍投 |
| /bet/confirm | 投注确认 | 选号快照、注数、倍数、总积分、规则版本 |
| /orders | 我的注单 | 状态筛选、分页、取消入口 |
| /orders/:id | 注单详情 | 原始选号、规范化选号、扣款来源、结算结果 |
| /results | 开奖结果 | 彩种/期次筛选、结果详情 |
| /wallet | 积分钱包 | 显示/可用/冻结/提现及来源积分 |
| /wallet/ledger | 积分流水 | 前后值、来源、业务类型、时间 |
| /recharge | 充值 | 第一期展示人工充值说明和申请记录 |
| /withdraw | 提现 | 资格、流水进度、来源限制、申请表 |
| /notifications | 通知 | 站内通知和已读状态 |
| /help | 帮助 | 玩法、积分、提现和责任博彩说明 |

### 3.2 选号页

选号页必须始终显示：

- 当前品牌和彩种；
- 当前期次、投注截止倒计时和期次状态；
- 玩法名称、规则摘要和规则版本；
- 普通号码、特别号码或数字位的选中状态；
- 号码属性标签；
- 排除号码入口；
- 复式展开注数；
- 倍投输入和合法范围；
- 单注积分、总积分、可用积分；
- 清空、随机选号、下一步和提交按钮。

确认页不得重新改变选号；如果期次、规则或余额在提交时发生变化，必须重新确认并展示原因。

### 3.3 状态和错误

统一处理：加载中、无数据、网络断开、品牌暂停、期次截止、余额不足、限额超出、重复提交、权限不足和服务暂不可用。

投注按钮提交后立即进入 loading，使用 Idempotency-Key；网络重试必须显示第一次结果，而不是再次创建订单。

## 4. 管理端页面

### 4.1 菜单

- 工作台
- 品牌和域名
- 用户和成员
- 代理树、佣金和奖励
- 彩种、玩法和规则审核
- 期次和开奖
- 注单和异常注单
- 充值、积分和提现
- 报表和对账
- 通知和多语言
- 后台账号、角色和权限
- 审计日志

### 4.2 工作台

展示当前操作者有权限的品牌范围：

- 进行中期次和投注量；
- 待开奖、开奖异常、待结算和异常注单；
- 待审核提现；
- 充值、派奖、佣金和奖励摘要；
- 账本对账差异；
- 外部开奖源健康状态；
- 高风险操作快捷入口。

### 4.3 玩法配置向导

步骤固定为：

1. 选择彩种模型；
2. 配置号码池、位数、重复和特别号码；
3. 配置选号、排除、复式、倍投和号码属性；
4. 配置中奖条件和结果特征；
5. 配置奖级、赔率、排他性、封顶和舍入；
6. 配置投注限额和取消规则；
7. 输入测试选号和测试开奖结果；
8. 查看组合数量、命中奖级和最终积分；
9. 保存草稿并提交品牌管理员审核。

S4-d 实际运营页面：彩种创建可选模板或自定义三种号码模型；普通/特别号码池支持范围或明确列表，数字位置支持 1–10 位。规则草稿可选快捷模板或通用可视化编辑器，条件树用递归控件编辑 AND/OR/NOT、比较、属性和用户所选特征，不提供脚本或可执行 JSON 输入。配置奖级、排他/累加策略、舍入、封顶、组合和倍投限额；附加属性允许多组、多值和号码重叠。

验证编辑器最多 32 组：按完整模型显示开奖号码、按玩法显示选号，再独立填写投注/中奖预期；新增、复制或删除用例不会让未解析的旧输入被忽略。未保存配置不得验证；定义与报告 hash 一致且验证通过才能送审。提交后只读，创建者及所有编辑者不能自审。审核者可查看只读规则树和报告，超级管理员仍不执行这些品牌写操作。当前限额控件只覆盖规则 DSL 的单注限额/组合/倍率，期次、用户总额度和取消业务仍待 S5 接入。

复杂配置在移动端只读；移动端可执行审核、驳回、查看模拟结果和发布确认。

### 4.4 期次和开奖

页面必须显示：

- 期次状态时间线；
- 投注开始/截止、开奖时间和品牌时区；
- 主来源、备用来源和来源切换记录；
- 当前开奖结果及校验项；
- 人工开奖、取消、纠正和结算按钮；
- 操作前确认弹窗、必填原因和影响范围预览。

结果纠正页面必须明确显示：原结果、新结果、预计回溯项目、预计重新结算范围和操作人。

### 4.5 资金和账本

账本列表至少显示：

- 业务类型和来源；
- 变动前显示/可用/冻结/提现积分；
- 变动金额；
- 变动后各余额；
- 关联订单/提现/充值/结算；
- 操作人、请求 ID 和时间。

人工调整不能直接编辑余额，必须填写调整原因并创建调整流水。

## 5. 响应式和可访问性

- 断点至少覆盖 360px、768px、1024px、1440px。
- 手机选号区避免横向滚动；管理端表格在手机改为卡片或横向滚动。
- 颜色不能作为唯一状态标识，必须同时有文字或图标。
- 支持键盘操作、焦点状态、错误信息关联和基本屏幕阅读器语义。
- 关键倒计时、投注金额和提现状态提供文字表达。

## 6. 原型交付

第一版交互原型至少包含：

- 用户注册/登录；
- 游戏大厅到投注提交完整链路；
- 订单取消；
- 钱包和提现；
- 管理工作台；
- 玩法配置和规则审核；
- 期次开奖和结果纠正；
- 异常注单处理；
- 移动端管理审核流程。

原型验收关注业务流程和状态，不要求第一版视觉稿覆盖全部品牌主题。

## S5-a2 用户投注接入边界

- `/games`、`/games/{id}`、`/games/{id}/bet`、`/bet/confirm`、`/orders`、`/orders/{id}` 使用真实接口；首页推荐卡来自公开目录，不再把演示彩种 ID 当作真实彩种。无数据、暂停/未开放、401、服务失败分别显示状态，不回填模拟数据。历史演示本地订单不读入真实列表。
- 规则决定普通/特别候选池、数字位数和每位多选、排除池（包括普通/特别号码的并集）、属性组/值与特征候选；仅显示该玩法需要的号码组。倍率为整数文本，积分显示使用字符串/BigInt，无 Number 金额运算。
- 服务端预览显示组合数、单位、总积分、期次、规则 hash。确认另展示只读候选组、奖级赔率和策略版本；提交请求与确认快照分离于可编辑选号，并绑定当前会员上下文。
- 未变更配置的后台刷新不抹掉选号。选号/倍率/玩法改变使旧预览失效；迟到的响应不覆盖新输入。期次/规则/策略真正变化须重新预览，提交时由服务端最终检查。
- 未知网络结果保留原投注/取消 body 与键，重试不创建新的操作意图；成功后读取真实注单和钱包。取消原因为非空且不超过 500 个 UTF-8 字节。会员冻结、品牌暂停不取消旧订单的原路退款权。
- 360px/1440px 布局与大 UUID/hash/号码内容可换行。视口回归不能推导 iOS/Android/鸿蒙真机兼容或 PWA 安装验收；S5-b 已接入公开开奖展示，结算明细、提现、通知与部分主页/帮助内容仍为显式原型。

## S5-a3 后台投注管理接入边界

- “注单和异常”使用真实品牌/彩种策略和注单 API，不展示演示统计。品牌限额留空表示不限，彩种提供继承、指定值、不限；最低值不允许不限。填写变更原因，以版本号防止覆盖他人的修改。彩种覆盖可高于品牌默认，继承校验使用已保存配置而非未保存草稿。
- 读取、策略写入、取消、异常标记采用独立权限，写权限不隐含读权限；超级管理员只读。无权限、未登录、空数据、加载失败有明确状态；切换账号/品牌或卸载组件后旧响应不可覆盖当前视图。
- 注单列表每页 50 条，可按品牌会员或注单 UUID 查询。详情只读展示规则/赔率与策略快照、原始/标准化选号、最多 20 条展开组合、来源分配、借记/退款引用和异常证据；不开放改投注、金额、赔率或异常原因的输入。
- 管理员取消或标异常需非空且最多 500 UTF-8 字节原因、核对版本与影响，再提交。未知网络结果锁定原正文和请求键，可原请求重试或读取状态；确定 409 则重读新版本并要求重新确认。异常标记不退款，原路退款是单独取消动作；已结算类状态不开放这些操作。
- 第一阶段仍是单人操作并保留可查询审计；此界面不是双人财务审批、自动派奖或异常单重结算入口。

## S5-a4 整期取消与退款接入边界

- “期次和开奖”增加独立期次取消面板。可直接输入期次 UUID 并读取该期真实详情与版本，不依赖列表默认期次；期次版本与取消任务版本明确分开。只读权、发起取消权、失败重试权各自独立，超级管理员不能写入；仅写权限时不调用 GET。
- 投注取消/判定取消、结构化原因与操作说明经核对后再确认。期次立即停止，但必须显示任务处理中/失败/已完成以及总数、待处理、已退款、原已退款和失败计数；不能以 202 起始响应宣称全额退款已完成。已完成快照与历史原始数据只读。
- 网络不确定时固定正文与幂等键，按账号/品牌隔离保存于 sessionStorage，刷新仍可原请求重试；不保存登录凭据。改变账号、品牌、期次或卸载后，旧响应不能覆写当前视图。确定 409 解除旧意图并要求重新核对，不拿任务版本替代期次版本。
- 有读取权时最多每 10 秒读取摘要、连续 6 次，随后可手动刷新。失败任务显示结构化错误码，运营核对并填写原因后显式重试；不自动恢复失败任务。该界面不执行已结算回溯或支付。

## S5-a5 单注判定取消接入边界

- 注单详情新增独立的“判定取消”权限与入口，普通取消、异常标记、判定取消不互相隐含。核对 no_result/invalid_result、非空且最多 500 UTF-8 字节原因，再确认只取消本单并全额原来源退款；确认后锁定原因类型、正文和请求编号。
- 未知网络结果保留原 body/键，重试或按匹配的单注证据核实；确定 409 后重读并重新核对版本、状态与判定依据。判定证据只读显示操作者、结果版本、原因、当时结果引用和退款引用，原异常记录继续保留；整期取消没有单注人工记录时给出明确说明。
- 规则版本编辑器按需加载，避免其完整编辑/验证功能扩大管理首页主包；权限和服务端验证不因懒加载改变。视口回归仍不等同于三类手机 OS 真机验收。

## S5-b 用户公开开奖与历史期次

- `/results` 不再显示固定示例号码。全品牌真实彩种目录、精确期号筛选、开奖/历史切换、上一页/下一页、刷新与当前结果详情使用只读接口；历史需要选彩种。空目录、无匹配结果、尚无结果、错误重试及暂停分别显示，不生成假的开奖或中奖金额。
- 彩种详情增加该彩种最近采用结果和跳转历史入口。三组号码原样显示，按数字位置标出零和重复号码；普通/特别号码不排序去重，以兼容允许重复或有顺序的 X+Y 模型。时间按彩种时区显示计划/实际开奖时间。
- 取消期次保留历史号码但明确标红说明“仅作记录，不用于有效判定或派奖”；已开奖、结算中、已结算与取消状态不能混淆，展示号码不代表订单获奖或已到账。
- 结果详情重新 GET 当前结果并显示公开记录编号；替换后的旧结果 404，不回退到旧快照。品牌/彩种/期号/页签改变或卸载后旧响应不得覆盖新上下文；失败和改筛选清除旧号码及详情。无效 URL/组件彩种参数不得退化成查询全部彩种。
- 完整双语、360px 与 PC 布局；UUID、长中文期号可断行。读取失败只提供安全重试，无投注/资金动作，不自动无限轮询。视口回归不代替真实手机 OS、PWA 安装或容量验收。

## S6-b 用户真实站内信

- `/notifications` 不显示固定演示消息/假未读数；实际 Cookie 会话解析当前会员，双语固定版本模板只展示安全业务事实和精确整数积分。
- 支持加载/空页/读取错误/未登录、分页、单条已读和“本页标为已读”；角标仅使用已成功读取的未读总数，退出、卸载或失效时移除。
- 未知写入保留精确 IDs、账户范围与原幂等键；只读重载后即使消息已经读过仍保留未知提示和同请求重试入口。明确失败才解除旧意图。加载/写入时禁用冲突操作；品牌切换与卸载后旧响应不得覆盖新范围。
- 中英文正文由固定模板插值，不接受富文本/HTML/外部地址，不公开内部审核理由、后台人员或充值证明。消息只说明已经提交的业务事实，不虚构中奖/提现状态。
- 外部渠道、运营模板编辑和后台投递 UI 保持未实现标记，不以站内 sent 推断邮件/短信/Telegram 已发送。

## S6-a 后台提现规则配置

- “资金与账本”新增按需加载的品牌/彩种真实配置，不伪造提现流程。页面明确仅配置、申请/冻结/出款/资格未接入，enabled 保存不代表功能上线。
- 品牌范围、来源、审核模式、N；彩种只覆盖 N 或留空继承，区分 "0" 与 null。有效 N/来源/双方版本读取服务端已保存记录，未保存草稿不影响显示；品牌保存后重读彩种有效值。
- 两步核对、必填原因、冻结正文与原键；未知网络/5xx 原请求重试，读取同值不能证明本次成功；确定冲突重读后新确认。回执必须匹配范围、下一版本、配置与审计。品牌/账号/彩种改变或卸载后迟到响应不得覆盖新范围；未知意图仅在当前页面会话内存隔离保留，不跨刷新/关闭持久化。
- 历史只读、分页，人员/原因/原版本可查。规则读写与目录读权限分离，超管无保存，可直接 UUID 查彩种。金额和 N 用字符串/整数逻辑，360px/PC 可断行；不以界面测试证明提现完成或真机兼容。
