# UI 与交互规格

## 1. 终端策略

- `user-web`：用户端独立 PWA，移动端优先，同时适配桌面浏览器。
- `admin-web`：管理端独立 PWA，桌面端完整，移动端支持监控、查询、审核和应急操作。
- 第一阶段不上架任何应用市场。
- 两个项目共享品牌主题、基础组件、类型和多语言资源，但不能共享用户端与管理端的权限逻辑。

## 2. 品牌主题

主题配置至少包含：

- Logo、favicon；
- 主色、辅助色、成功/警告/错误色；
- 字体和字号层级；
- 圆角、阴影、按钮样式；
- 登录页、首页、游戏卡片和公告样式；
- 默认语言、可用语言和文案覆盖。

继承顺序为平台默认 → 品牌覆盖。主题配置发布后清理缓存并返回新版本号。

## 3. 用户端页面

### 3.1 页面路由

| 路由 | 页面 | 必要功能 |
|---|---|---|
| /login | 登录 | 用户名/手机号、密码、Telegram、验证码开关 |
| /register | 注册 | 用户凭证、协议勾选、品牌归属 |
| / | 游戏大厅 | 品牌主题、彩种卡片、公告、状态 |
| /games/:gameId | 彩种首页 | 当前期次、倒计时、玩法列表、开奖结果 |
| /games/:gameId/bet | 选号 | 号码池、玩法、附加属性、排除、复式、倍投 |
| /bet/confirm | 投注确认 | 选号快照、注数、倍数、总积分、规则版本 |
| /orders | 我的注单 | 状态筛选、分页、取消入口 |
| /orders/:id | 注单详情 | 原始选号、规范化选号、扣款来源、结算结果 |
| /results | 开奖结果 | 彩种/期次筛选、结果详情 |
| /wallet | 积分钱包 | 显示/可用/冻结/提现及来源积分 |
| /wallet/ledger | 积分流水 | 前后值、来源、业务类型、时间 |
| /recharge | 充值 | 第一期展示人工充值说明和申请记录 |
| /withdraw | 提现 | 资格、流水进度、来源限制、申请表 |
| /notifications | 通知 | 站内通知和已读状态 |
| /help | 帮助 | 玩法、积分、提现和责任博彩说明 |

### 3.2 选号页

选号页必须始终显示：

- 当前品牌和彩种；
- 当前期次、投注截止倒计时和期次状态；
- 玩法名称、规则摘要和规则版本；
- 普通号码、特别号码或数字位的选中状态；
- 号码属性标签；
- 排除号码入口；
- 复式展开注数；
- 倍投输入和合法范围；
- 单注积分、总积分、可用积分；
- 清空、随机选号、下一步和提交按钮。

确认页不得重新改变选号；如果期次、规则或余额在提交时发生变化，必须重新确认并展示原因。

### 3.3 状态和错误

统一处理：加载中、无数据、网络断开、品牌暂停、期次截止、余额不足、限额超出、重复提交、权限不足和服务暂不可用。

投注按钮提交后立即进入 loading，使用 Idempotency-Key；网络重试必须显示第一次结果，而不是再次创建订单。

## 4. 管理端页面

### 4.1 菜单

- 工作台
- 品牌和域名
- 用户和成员
- 代理树、佣金和奖励
- 彩种、玩法和规则审核
- 期次和开奖
- 注单和异常注单
- 充值、积分和提现
- 报表和对账
- 通知和多语言
- 后台账号、角色和权限
- 审计日志

### 4.2 工作台

展示当前操作者有权限的品牌范围：

- 进行中期次和投注量；
- 待开奖、开奖异常、待结算和异常注单；
- 待审核提现；
- 充值、派奖、佣金和奖励摘要；
- 账本对账差异；
- 外部开奖源健康状态；
- 高风险操作快捷入口。

### 4.3 玩法配置向导

步骤固定为：

1. 选择彩种模型；
2. 配置号码池、位数、重复和特别号码；
3. 配置选号、排除、复式、倍投和号码属性；
4. 配置中奖条件和结果特征；
5. 配置奖级、赔率、排他性、封顶和舍入；
6. 配置投注限额和取消规则；
7. 输入测试选号和测试开奖结果；
8. 查看组合数量、命中奖级和最终积分；
9. 保存草稿并提交品牌管理员审核。

复杂配置在移动端只读；移动端可执行审核、驳回、查看模拟结果和发布确认。

### 4.4 期次和开奖

页面必须显示：

- 期次状态时间线；
- 投注开始/截止、开奖时间和品牌时区；
- 主来源、备用来源和来源切换记录；
- 当前开奖结果及校验项；
- 人工开奖、取消、纠正和结算按钮；
- 操作前确认弹窗、必填原因和影响范围预览。

结果纠正页面必须明确显示：原结果、新结果、预计回溯项目、预计重新结算范围和操作人。

### 4.5 资金和账本

账本列表至少显示：

- 业务类型和来源；
- 变动前显示/可用/冻结/提现积分；
- 变动金额；
- 变动后各余额；
- 关联订单/提现/充值/结算；
- 操作人、请求 ID 和时间。

人工调整不能直接编辑余额，必须填写调整原因并创建调整流水。

## 5. 响应式和可访问性

- 断点至少覆盖 360px、768px、1024px、1440px。
- 手机选号区避免横向滚动；管理端表格在手机改为卡片或横向滚动。
- 颜色不能作为唯一状态标识，必须同时有文字或图标。
- 支持键盘操作、焦点状态、错误信息关联和基本屏幕阅读器语义。
- 关键倒计时、投注金额和提现状态提供文字表达。

## 6. 原型交付

第一版交互原型至少包含：

- 用户注册/登录；
- 游戏大厅到投注提交完整链路；
- 订单取消；
- 钱包和提现；
- 管理工作台；
- 玩法配置和规则审核；
- 期次开奖和结果纠正；
- 异常注单处理；
- 移动端管理审核流程。

原型验收关注业务流程和状态，不要求第一版视觉稿覆盖全部品牌主题。
