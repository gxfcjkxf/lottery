共551个投注选项；贵宾厅额外两个13/14价格、4.2–4.6额外一个特殊价格，共554个赔率字段。普通赔率包含本金；牛牛价格是手牌盈利倍率的系数，利润和原本金分开入账，不把盈利系数误当作含本金赔率。牛牛AA/BB亏损按庄家点数＋10倍，由用户在本次会话明确确认。

和值总值14～27为大、0～13为小；极值22～27和0～5。顺子要求三个不同连续数字，顺序不限，不循环连接9和0；对子不含豹子。尾玩法只覆盖1～8，尾0和9全部输。定位大小单双以5为大小分界。龙虎和比较指定两个位置，同数时龙虎输、和中奖。

4.2–4.6按会员、彩种和共享期次的全部批次汇总，排除尾投注后判断10000阈值，结算读取封盘后的最终总额。`effective_points`与退款分开计算：加拿大28的特殊退本可以计算有效投注，4.2–4.6的13/14则全部排除。此处有效投注是注单统计值，暂不计入提现流水资格或代理佣金。

## 使用流程

1. 总后台“彩种”创建可重复的三位有序0～9数字模型，进入“加拿大投注”，选择规则类型并明确填写所有价格后发布。规则类型首次发布后不能变更，价格以新版本发布。
2. 品牌在“规则配置”接入同一平台彩种，进入“加拿大投注”，配置启用状态、每注限额、品牌及会员单期限额和全部销售赔率。销售价格不得高于平台价格，发布须确认当前平台版本。
3. 总后台建立共享期次。用户从“游戏”目录进入任一加拿大彩种，跨玩法组选项混合投注，各选项独立积分，预览核对总额后确认。未知响应保留原请求、幂等键和账户归属，不能换正文重试。
4. 总后台通过现有期次界面发布三个有序数字，运行中的worker发现已开奖注单后逐单结算。当前试用采用该发布流程，未接入参考站投注或外部支付。
5. 两个后台查看结算进度，品牌后台查看本品牌逐注明细；用户在彩种页面、“我的注单”和钱包查看记录。

平台改价后旧品牌销售版本暂停，品牌刷新确认并发布后恢复。购买快照包含规则类型、普通及特殊价格；后续配置不重定价历史注单。每会员每期累计派彩上限888888积分，结算通过钱包锁串行应用剩余额度。

## 牛牛资金处理

购买时将A/B的10倍、AA/BB的20倍、梭哈的1倍投注积分从可用转入系统冻结；混合批次汇总冻结需求，余额不足时整批拒绝。结算从原冻结来源扣实际亏损，再按原来源解冻余款，中奖净利润进入中奖可用积分。普通和局全额释放对应风险，豹子例外按庄家点数及模式倍率扣损。

3%抽水和购买盈利系数使用精确有理数计算，最后才按单项四舍五入；中间显示倍率不参与计算。注单、冻结、实际亏损、解冻、派彩、审计及幂等回执均在事务中保存。数据库限制购买快照改写、跨品牌资金证据和风险超额结算，业务对账包含冻结与解冻的两个积分桶。

加拿大彩结构与资金约束已合并到 `0001_baseline.up.sql`，按[空库安装](../README.md#空库安装)操作。资金表为`platform_canada_orders`，通过`profile`区分固定扣款和牛牛冻结；原六合彩链路保留。接口定义同步到OpenAPI，用户接口位于`/api/v1/canada`，管理接口位于`/platform-games/{id}/canada`。
