## 验收原则

- S1 的原型数据须明确标记模拟；任何原型成功提示不得宣称账本业务已执行。
- PostgreSQL 是业务事实来源；不能用内存余额替代资金实现。
- 阶段完成须记录执行命令与实际结果；500 次/秒目标必须由真实业务压测证明。
- 本任务授权开发与阶段提交，不授权部署到客户生产环境。
- 文档默认技术参数可以由实施者确定并记入决策记录；涉及派奖、佣金分配、提款流水公式等业务选择须保留未决标记。

## 测试策略

- 核心业务采用 TDD，先覆盖不变量、错误和并发路径，再实现正常流程；UI 采用可交互原型与浏览器回归迭代。
- 后端使用 Go 测试与真实 PostgreSQL；前端使用 Vitest、类型检查和 Playwright（1440px PC / 360px 移动视口）。
- CI 将后端 race 检查、前端检查与带独立数据库的浏览器测试分成三个任务。测试环境不开真实支付。
- 本机缺少 Docker 和 C 编译器：数据库集成测试已用隔离的本地 PostgreSQL 执行；Compose 和 race 的实际验证需由具备运行条件的环境执行，不能声称本地已通过。

## 文档勘误

- 全局身份属于平台；品牌用户操作权限与全局密码的影响范围需分别校验。
- 规则审核继续遵守创建者不得自审，通用单人流程不会解除玩法审核要求。
- 余额 API 统一以十进制字符串返回 64 位整数，前端使用 BigInt；避免 JavaScript 安全整数溢出。
- 冻结与提现必须保留每种来源的状态分配；只记录三种可用来源余额不足以实现完整原路退款。
- 相同投注内容允许用户有意重复购买；幂等依据客户端操作键和请求摘要，不以内容相同误杀合法订单。

## S1 本地验收（2026-10-06）

已实现：

- pnpm 工作区与独立 Vue 用户端、管理端；整数字符串/BigInt 积分类型。
- Go 服务、配置与数据库主从连接入口、优雅退出、健康检查和品牌上下文只读 API。
- 两个不可变迁移、幂等开发种子；跨品牌外键、会话身份一致性、非负余额和不可改写审计/账本约束。
- 独立的密码/会话加密原语与权限校验原语。尚未接入注册、登录或后台权限 API，不代表 S2 已完成。
- 用户端常用页面、普通/特别号与重复数字选号原型；管理端工作台、规则模拟/审核、提现审核、开奖纠正等本地演示。
- 双端 manifest、静态缓存 worker、响应式布局；完整 iOS/Android/鸿蒙安装与真机兼容性尚待 S7 验收。
- Compose 开发环境定义与后端 Dockerfile、三类 CI 任务；本机无 Docker，容器实际启动尚未验证。

实际执行：

| 检查 | 结果 |
|---|---|
| `pnpm install --frozen-lockfile` | 通过 |
| `pnpm typecheck` | 三个包通过 |
| `pnpm test` | 前端 15 项单元测试 + 4 项 PWA 静态行为测试通过 |
| `pnpm build` | 共享包、用户端、管理端通过 |
| `go vet ./...`（`CGO_ENABLED=0`） | 通过 |
| `go test -count=1 ./...`（带 `TEST_DATABASE_URL`） | 所有包通过，真实 PostgreSQL 集成测试实际执行 |
| `go build -buildvcs=false` | 通过；本机系统 Git 缺少 Xcode，使用独立 Git 运行版本控制 |
| `pnpm test:e2e`（本机 Chrome） | PC/移动视口共 8 项通过 |

浏览器测试覆盖真实 Aurora/Harbor 品牌上下文与隔离、伪造品牌头无效、无水平溢出、重复数字 `121` 的演示确认/取消。真实业务交易、登录会话、500 次/秒吞吐、主从故障切换和容器运行不属于已通过项目。

## 未决业务选择

- 结算：计算后自动派奖，还是由运营确认；用户短回复“1”的指向仍待确认。
- 多层代理佣金采用差额分配还是各层独立计算。
- 开奖纠正时旧中奖积分不足冲正的处理（人工阻断/补足或负债规则）。

这些未决选择不阻塞基础工程，但相应业务模块不得按未经确认的选择上线。
