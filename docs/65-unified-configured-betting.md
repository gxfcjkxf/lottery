# 投注与结算统一为配置化链路

2026-10-28。系统未上线，直接收敛，不提供旧协议兼容、双写、旧订单导入或兜底结算。

## 当前链路

平台彩种 `platform_games` → 已发布配置 `configured_rule_versions`／`configured_rule_heads` → 品牌销售配置 `configured_sales` → 共享期次 `platform_game_periods` → `ConfiguredEngine` 报价、下单与结算 → 唯一注单表 `configured_orders`。

六合彩、加拿大28、995/996、VIP、42、百家乐、牛牛等模型都通过同一个配置解释器运行。玩法规则、价格、销售版本和购买快照在下单时冻结；已购买订单按自己的快照结算，不能用新发布的规则改写旧订单。

用户入口只有 `/api/v1/configured`（及品牌路径对应入口）的彩种、报价、下单和订单查询。个人投注历史只查询配置化订单，离线或删除彩种的配置化注单仍能读取。品牌后台与总后台共享 `/configured-orders` 只读列表和同一个表格组件。

投注结算 worker 只执行 `ProcessConfiguredSettlements`。平台共享自动化负责开期、采集与发布结果；结果发布后逐笔原子结算，失败事务回滚，订单保持待结算，下一次 worker 按同一订单重试。失败记录在 worker 日志与错误指标中；队列监控直接统计已有开奖结果的待结算配置化订单。

## 移除的实现与入口

- 品牌自建游戏／期次／规则版本的旧投注、取消、异常裁决、结算任务、任务审批与开奖更正执行链路。
- 独立六合彩、加拿大投注订单及其专用结算器、查询接口和前端客户端。
- 历史记录、账号汇总、经营总览对四套订单表的合并查询。
- 旧结算任务／计算记录作为佣金和提现资格前提的资金证据适配。
- 对旧协议混用期次的判断；不再存在旧协议售卖和切换条件。
- 旧品牌自建彩种开关、管理入口、专用开发夹具和依赖它们的旧引擎回归。

没有给配置化链路补上旧任务审批、旧期次批量退款或旧开奖更正工作流。当前共享开奖结果发布后不可改写；不支持的旧接口返回404。不要从历史文档恢复这些执行入口。

## 保留的资金保护

1. 预览不扣款。确认请求绑定当前品牌、用户及会员；写入前重新认证，撤销会话不能复用旧确认。
2. HTTP 幂等回执校验原键与请求；改体冲突，原请求重试不多扣。余额锁与精确整数记账防止并发超扣。
3. 下单锁定当前规则／销售版本，检查快照散列、品牌与连接状态、投注窗口和限额。期次写锁串行化跨会员的总限额检查。
4. 借记模式按四来源优先级扣可用积分；风险预留模式只冻结最大亏损。结算消费真实亏损，余款释放至原资金来源；和局退款也按原来源归还。
5. 订单结果、钱包分项、派奖／退款／亏损流水和审计在同一事务中提交。数据库继续校验原借记、资金归属、金额、状态与原来源分配，禁止删除注单或改写购买及结算快照。
6. 待结算订单只能成功转为已结算一次，派奖键按订单固定；重试不会重复派奖或释放。跨品牌的会员、订单、配置和积分流水不能混用。

## 佣金、提现及报表

`betting_financial_facts` 是配置化订单的只读财务投影，不是另一套存储或结算器。它把订单和实际借记账户、原来源分配、有效投注、真实消费、中奖积分和净亏损放在同一读取口径。

- 下单同时保存归属、佣金规则和提现流水倍数快照。品牌接入共享彩种时初始化对应的提现规则；不再要求一份旧品牌游戏记录。
- 佣金直接核对配置化订单的原借记和结算流水，按冻结的代理路径、有效投注或实际净亏损核算。佣金核算自身的运行历史保留；注单不再伪造或依赖旧结算 job／calculation／generation 标识。
- 提现资格按原借记账本版本截取已结算配置化订单，使用投注时保存的倍数及 `effective_points`。待结算、和局退本、未消费的最大亏损预留不计入有效流水；缺少资金或规则证据明确失败，不按零额成功。
- 个人／代理汇总、品牌／平台总览、投注及归属报表和报表归档读取同一订单来源。风险预留的净输赢按实际消费减中奖积分计算。
- 投注与中奖通知核对配置化订单和真实派奖流水，不再依赖旧结算任务。

## 首次销售配置（2026-10-28补齐）

平台创建彩种并保存当前规则后，品牌账号在“彩种管理”明确接入彩种，再点击卡片的“销售配置”。未配置时只生成停用的未保存草稿；价格取自当前发布规则，运营核对价格、四项限额及“接受投注”开关后点击“保存销售配置”。缺少发布规则时不提供销售表单。仅接入或启用目录不会自动生成销售配置，也不会自动接受投注。

品牌唯一写入口为 `POST /api/v1/admin/platform-games/{id}/configured/sales`，沿用 `ConfiguredSales`。查看需要 `platform_game.view.brand`；保存需要 `platform_game.sell.brand`、真实品牌范围、当前会话、匹配Origin及幂等键。总后台无对应POST。首次保存传`version=0`，成功返回1；后续编辑传当前version并递增，不能覆盖另一位运营的修改。规则绑定必须是当前发布版本；价格完整且不超过发布上限，四项正整数限额满足每注及期次关系。沿用现有服务、表和审计，不新增审批、历史页、兼容入口或资金操作。

新规则发布后旧销售不可用于新投注；运营在赔率弹窗逐项编辑，或按当前盘口与玩法批量修改；点击“提交”应用到待保存表单，再保存投注配置，关闭弹窗不应用。保存推进销售版本，旧预览明确冲突；已购买订单仍按自己的价格、规则和原来源快照结算。销售保存本身不改订单、钱包或账本。结果未知时保留原请求、原键并锁定编辑，成功重读配置并刷新彩种卡片。
