# 产品与业务规格

## 1. 第一阶段范围

### 包含

- 多品牌、多租户。
- 用户注册、登录、Telegram 授权登录、品牌成员关系。
- 彩票大厅、选号、确认、投注、注单查询和用户取消。
- 充值、提现、中奖积分派奖；第一期不接入真实支付。
- X+Y、M 选 N、0~9 N 位数字三类模型及可配置衍生玩法。
- 外部开奖源伪实现/适配器、人工开奖、结果校验和开奖结果记录。
- 规则审核、期次管理、注单管理、异常注单、报表和审计。
- 代理层级、输赢/流水佣金、推荐奖励和周结/月结配置。
- 响应式 PWA；用户端和管理端为独立前端项目。

### 不包含

- 真实支付、真实虚拟资产钱包或链上转账。
- 第一阶段应用市场原生 App。
- 完整 KYC、年龄/地区验证和第三方身份接口；只提供配置开关、接口和伪实现。
- 平台自开奖的生产级随机数实现；保留扩展边界。
- 多来源开奖结果比对和共识确认。

## 2. 租户和品牌规则

- `brand_id` 是所有品牌业务数据的强制隔离键。
- 用户全局身份可以加入多个品牌，但余额、订单、注单、提现、品牌资料和代理归属均按品牌隔离。
- 品牌可配置域名、Logo、主题、多语言、功能开关、彩种开关、限额、提现、佣金和风控规则。
- 配置继承顺序：平台默认 → 品牌 → 彩种 → 玩法；更具体层级覆盖上层值。
- 品牌配置未覆盖时读取上层默认值，并在接口响应中返回最终生效配置版本。
- 品牌暂停生效后立即禁止新投注；允许登录和提现；已有期次、注单、开奖和结算继续执行。

年龄、地区、身份检查一期采用品牌配置与伪适配器。任何检查开启而适配器未接入时，拒绝新注册、首次入品牌、运营新增/首次同意条款和新投注；不能默认当作已验证。已存在的正常登录、查询、取消及原路退款不因该开关受阻。默认关闭仅表示跳过，不证明合规；真实验证、审核队列和提现业务仍按各自完整验收执行。
- 品牌由显式平台创建权限建立，初始暂停且版本1。创建不自动授予品牌权限，也不生成用户、域名、彩种或资金；完成后需独立授权和配置，才可运营。

## 3. 用户与后台角色

### 用户

- 注册：用户名或手机号；必须接受隐私条款和服务协议并保存版本、时间和品牌。
- 登录：用户名/手机号 + 密码，或 Telegram 授权。
- 用户名和手机号全局唯一。首次注册时某项未填写，可以补充一次；完成后原则上不可修改。
- Telegram 标识全局唯一绑定，不允许解绑。
- 用户状态：正常、冻结、禁用、过期、注销；默认按品牌管理。
- 品牌管理员/运营可以修改本品牌状态、备注、密码和在线会话；超级管理员对用户只查看。

### 后台

- 账号、角色、权限分离；账号可有多角色，最终权限为并集去重。
- 权限包含资源、动作和范围，例如 `withdrawal.approve.brand`。
- 平台范围权限和品牌范围权限分别校验，不能通过角色绕过品牌隔离。
- 第一阶段高风险操作不要求双人复核，但必须有完整可查询审计。

## 4. 账户和积分

### 余额维度

- 显示积分 = 可用积分 + 冻结积分。
- 可用积分按来源拆分：充值积分、中奖积分、佣金积分、赠送积分。0046已扩展四来源账本；当前人工积分调整可使用佣金来源，0048已接入周期核算，审核和派发仍未接入。
- 冻结积分按原因拆分：系统冻结、人工冻结。
- 提现积分是提现处理中转出的积分，不计入显示积分。
- 所有积分为整数且不过期。

### 扣款和退款

- 四来源默认扣款顺序：充值积分 → 中奖积分 → 佣金积分 → 赠送积分；彩种配置可覆盖并须审核。
- 投注、取消、提现、派奖和人工调整必须保存来源分配。
- 取消全额按原来源、金额和状态原路退回，并生成独立退回流水。
- 原流水不可改写；冲正使用补偿流水。

## 5. 投注业务

标准流程：

`选号 → 确认 → 投注 →（开奖前可取消）→ 开奖 → 结算`

投注提交必须在一个事务中完成：

1. 校验品牌、用户、期次、玩法版本和限额。
2. 计算标准化选号、复式注数、倍投和总积分。
3. 锁定积分账户并按来源扣款。
4. 写入积分流水。
5. 创建注单和幂等结果。
6. 写入 Outbox 事件。

任一步失败，整体回滚。

## 6. 期次、开奖和结算

### 期次状态

正常流转：`待开始 → 投注中 → 已截止 → 待开奖 → 已开奖 → 结算中 → 已结算`。

可进入的异常处理状态：`投注取消`、`判定取消`。每次状态变化记录操作者、原因、来源和时间。

同品牌、同彩种的上一期结算完成后才能开放下一期投注，只有截止或已开奖不足以放行。上一期取消时须等待全部原路退款完成。延迟使后续期次原投注窗口已过时，直接按日历跳过，不补开、不延长；不同品牌或彩种互不阻塞。

### 取消

- 用户能否在开奖前取消由品牌/彩种配置决定。
- 运营发现异常注单可以随时取消。
- 没有开奖结果，或开奖结果异常，可以判定取消期次或相关注单。
- 取消全额原路退回投注积分。

### 开奖

- 外部来源：主来源 + 多个备用来源，按优先级切换。
- 超时、错误、无数据、数据异常时进入下一来源。
- 第一阶段不做多来源比对。
- 外部开奖失败时，授权运营人员可以人工开奖。
- 人工开奖/补录第一阶段不要求双人复核，但必须可查询审计。

### 结算

- 中奖判断完全由注单绑定的玩法规则版本决定。
- 单奖级直接派奖；多奖级按排他性配置选择或累加。
- 赔率、封顶和四舍五入精度读取规则配置。
- 异常注单不自动结算、不参加普通重试；运营可以人工判定异常。
- 期次所有注单均已结算或已标记异常后，期次进入已结算。
- 结果纠正可以重新结算，但必须先用冲正/反向流水回溯原派奖、积分、佣金、奖励、流水统计和通知数据，不能删除原记录。

## 7. 提现

- 状态：`审核中 → 提现中 → 已提现`；另有失败、驳回、取消。
- 提交时积分转入提现积分并保存来源分配。
- 同一用户同一品牌只能有一个进行中的提现。
- 品牌配置提现上下限、来源限制和审核模式。
- 提现流水门槛按申请提交、占用积分前的当前品牌全部可用充值＋赠送余额计算，不按本次申请金额计算，也不包含中奖、佣金、冻结和已占用的提现积分；服务端锁定钱包后保存基数快照。
- N 必须大于 0，彩种 N 优先于品牌 N，未配置时继承品牌。所有来源的有效投注按每笔投注时的 N 快照折算：精确累加 `投注金额 ÷ N`，达到上述基数时满足流水门槛；相同 N 时等价于基数的 N 倍有效流水。
- 充值、中奖、佣金和赠送来源支付的有效投注均计入，取消、异常、无效和未完成投注排除。规则修改仅影响新投注，旧投注不得套用申请时的新 N；缺少历史规则快照时不得补造或用当前配置放行。
- 有效流水排除投注取消、判定取消、异常、无效、测试和未完成注单。
- 成功提现以提交时间作为当前流水周期截止点；失败/驳回不清空流水并按原来源退回。
- 第一期不接真实出款接口，按内部处理流程完成状态流转。

## 8. 代理、佣金和奖励

- 代理层级深度、上下级关系、下级发展权限由品牌配置。
- 品牌管理员设置佣金比例和模式：输赢或流水。
- 下级的有效模式必须与上级一致，只能继承或显式填写相同模式，不允许同一路径混用模式。
- 输赢模式只对有效输钱注单计佣；中奖、平局、取消、异常和无效不计入。
- 流水模式按有效投注流水计佣；取消、异常和无效投注额扣除。
- 代理可配置下级代理比例，但不得超过自己的可分配/已配置比例；后端强制校验。
- 佣金周期按品牌配置为周结或月结。
- 多级佣金按同一基数差额分配；在周/月周期批处理，不按彩票期次生成待结佣金。周期边界及人工/系统派发可配置。
- 注单按投注时间归属周期；迟结算、更正不改变原周期，未结算不能按零佣金忽略。
- 周期边界后等待该周期全部注单最终完成再结佣，不把迟结算转到下期；按代理汇总全部精确差额后统一四舍五入为整数。
- 节点停用仅限制代理操作，仍按每笔投注原快照正常计佣。0047已接入独立金融政策、修订与购买时完整快照；0048已接入手动登记周期、分页核算、历史代次和失败重试，审核及派发尚未接入。
- 佣金派发到独立佣金积分，可投注但不计入提现门槛基数。
- 佣金不产生负数，最低为 0；人工修正必须产生独立调整记录。
- 规则、归属、佣金和奖励均保存版本与历史快照。
