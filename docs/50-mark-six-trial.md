## 历史实现与试用记录

## 可用流程

1. 总后台「彩种」使用「创建六合彩」建立 01–49、6 个正码＋1 个特码的模型；已有相同模型的彩种也可直接配置。列表「六合彩」入口完整发布494项赔率，含正码、六个正码特位置、全部组合玩法、中三奖级和0尾价格。赔率按玩法筛选，正码特可按位置筛选；支持批量填入并逐项修改。所有赔率包含本金；发布须填写原因，创建不可修改的版本。
2. 品牌后台「规则配置 → 平台彩种」接入，打开「六合彩」发布销售配置：开放投注、每项最低/最高积分、品牌单期及会员单期限额、各选项赔率。品牌赔率不得高于平台版本。权限为 `platform_game.sell.brand`；读取仍要求 `platform_game.view.brand`。
3. 总后台在「年度号码属性」完整配置49个号码的波色、生肖、五行，填写配置年份、生效时间和失效时间后发布。日期与时间使用平台统一控件及平台时区，切换日期由运营按业务规则设置，支持农历年切换，不按公历元旦自动推算。再创建共享期次，设置开售、封盘、开奖时间；未配置适用属性的开奖日期明确拒绝创建。用户在首页或彩种目录进入六合彩，混合选择特码和两面，输入每项积分，预览并确认整个批次。各项可独立使用不同积分和赔率。
4. 到开奖时间后，总后台发布六个正码及一个特码，填写原因。独立运行的 `platform worker` 自动发现已发布结果的待结算批次，逐批派奖或退本。
5. 用户在投注页和「我的注单」查询结果。品牌配置弹窗可查看本品牌注单与结算；总后台同一配置入口汇总各品牌结算进度。两品牌共用期次及结果，不共用结算状态。

用户端、品牌后台、总后台新增文案使用中英文 catalog。布局采用现有品牌令牌，缩小留白；手机使用玩法下拉选择，快捷选号默认折叠，投注汇总置于底部导航上方。组合玩法选好号码、生肖或尾数，填写每组合积分后加入批次，再预览实际组合、赔率及总额；可以与普通单项混合投注。

## 明确的玩法语义

- 特码01–49：与最后一个开奖号码完全相同才中奖，49可正常中奖。
- 特大25–48，特小01–24；单双、大单、大双、小单、小双均在01–48内判断。
- 特码为49时，八种两面全部和局；返还对应投注项的原始积分来源，不转为中奖积分，不计有效投注。
- 波色投注包含红波、蓝波、绿波，以特码的波色判奖；特码为49时，三种波色全部和局并退回原积分来源。投注卡片的对应号码排除49，玩法说明明确和局规则。
- 特肖选择一个生肖，以特码的生肖判奖，包含49；五行选择金、木、水、火、土之一，以特码的五行判奖，包含49。这两类不按49和局。
- 正码匹配前六个号码之一；正码特匹配正一特至正六特的指定位置，不能用特码替代。开奖数组的原始顺序保留用于位置判断。
- 连码支持二全中、三中二、三全中，仅使用六个正码；三中二命中三个时只使用中三档赔率，不再叠加中二派彩。
- 一肖至五连肖、二连尾至五连尾使用全部七个开奖号码；每个组合只派彩一次。连尾组合含0时使用独立0尾赔率，复式池展开后分别决定各组合是否含0。
- 自选5至10不中使用全部七个开奖号码，任何一个所选号码出现即不中奖。对应最大选号数为8、9、10、10、11、12，完整展开注数为56、84、120、45、55、66。
- 其他玩法包括特码头尾、特码合肖、家野肖、半波、七色波、总肖及开奖尾数。合肖、家野肖及半波在特码49时和局；头尾正常判奖。七色波正码计1、特码计1.5，最高分并列时三个颜色投注退本，和局投注中奖；总肖按七个号码的不同生肖数判奖，开奖尾数命中只派一次。
- 中奖派彩包含本金，每项用精确小数计算、四舍五入取整数积分。退本与中奖派彩分别入账。
- 波色、生肖、五行均读取期次固定的属性版本，号码映射可按年度调整。投注页显示生肖、五行；号码球、说明、历史开奖及注单使用各自快照。开奖特码加金色外圈，选中状态不覆盖波色。

参考说明中的上述玩法均已开放，未知选项明确拒绝。平台六合彩注单暂不参与代理佣金、提现流水资格及原有品牌注单报表，原有品牌彩种流程不受影响。开奖结果发布后不可覆盖；本期未提供平台注单取消及开奖更正入口。

## 数据与事务

当前 `0001_baseline.up.sql` 包含平台赔率版本、品牌销售配置、品牌注单，不复制共享彩种及期次。配置更新采用版本校验。新平台版本发布后，品牌必须针对新版本重新发布销售；已购买批次保留原赔率和限额快照。

当前基线包含不可变年度属性版本、期次绑定及购买时属性快照。发布新版不会改写已有期次；新期次按开奖时间选择有效版本，注单保存全部49个号码属性。数据库保护期次绑定及购买快照不可篡改。基线中的2026试用表处理仅针对已有试用数据，新建彩种没有默认属性，运营必须完整配置；不自动复制上一年或套用今年数据。

当前基线将属性玩法批次上限设为77项，不改写已发布赔率或历史注单。总后台、品牌后台必须明确补全20项赔率并发布；未补齐时用户端提示配置不完整，服务端拒绝新投注，不自动补赔率。

当前基线将展开后的批次上限设为1000注，同一玩法可有多个不同组合。每注保存排序后的选号、每组合积分、购买赔率、三中二中三赔率及含0尾价格标识，历史快照不可变。新销售必须明确补齐全部494项赔率并发布，不自动继承或补全缺失价格。

一个批次展开后含1–1000个不重复的“玩法＋组合”，可跨全部分组混合投注，整批成功或失败。重复组合、越界选号、重复选号和超量组合在扣款前拒绝。服务端检查登录身份、品牌状态、完整赔率、配置版本、数据库封盘时间、每组合及累计限额和余额，在钱包锁内重新检查。请求通过既有持久幂等引擎执行，重放前重验登录；确认账户不能被替换。浏览器 sessionStorage 保存当前账户、彩种的未确认原始组合池、每组合积分及键，重载后允许显式重试；存储失败时拒绝发送新投注。

API 组合项使用 `selection` 整数数组：号码为01–49的整数，生肖以鼠1至猪12编号，尾数为0–9。`points` 是每组合积分。例如三中二选择 `[1,2,3,4]`、每组合2积分，服务器展开4注、扣款8积分。只读预览与正式购买均由服务器重新展开及计价；客户端不能指定购买赔率或中三奖级。

worker 每次事务处理一个批次，复用整数积分账本及其来源分配；派奖、退本、注单状态与审计同事务提交。已结算批次不可重写，重跑不会重复入账。所有新增资金流水参与既有 `point_business_preview` 对账。配置已有玩法后，号码模型不能改写。

## 验证与本地试用

独立测试数据库覆盖原子批次、未知选项拒绝、相同键重放、并发余额不超扣、版本冲突、49退本来源、派奖取整、双品牌共享开奖与独立结算、跨品牌隔离、权限撤销和登录撤销后回执拒绝。

年度属性专项验证：同一个01号码在不同版本中可分别为红/蓝/绿波，生肖及五行同步变化；已有期次与购买记录保持原属性，新期次使用新版本，失效后未配置的开奖日期被拒绝，品牌后台无属性写入路由。

属性投注专项验证：全部77项同批购买，49开奖时八种两面及三种波色共11项退本，特肖、五行照常判奖；投注后修改年度属性及赔率，仍按购买快照结算，重复处理不重复派彩，账本对账一致。HTTP 验证新增20项混合购买、请求重放、漏配五行赔率拒绝及品牌波色赔率不得高于平台。

组合专项覆盖全部玩法族的命中与未中、六档自选不中展开数量、三中二中三排他奖级、0尾价格分流、七色波和局、重复/超量组合拒绝。资金混合批次展开16注、扣款32，派彩83、和局退本2、有效投注30；重复购买与重复结算不重复记账，原积分来源退款及对账一致。购买后修改当前赔率和生肖映射仍按原快照结算。前端494项赔率与 OpenAPI 合约一致，中英文标签齐全。

本地开发库已执行迁移，并运行 API、worker 及三端试用服务。试用彩种代码为 `mark_six_trial`，入口及独立合成账号记录于未跟踪的 `.local/mark-six-trial.txt`。其中一次真实 HTTP＋运行 worker 的合成积分验证：批次投注30，中奖派彩490、和局退本20、有效投注10。未改变既有体验账号密码。

新增属性玩法也已通过本地总后台和品牌后台界面发布：示例波色赔率2.8、特肖11.5、五行4.5，均可逐项调整。实际 HTTP 混合投注7项共70积分，运行中的 worker 在49开奖后结算为中奖160、波色退本30、有效投注40。已创建新的24小时试用期次，具体封盘时间记录在上述本地账号文件中。
