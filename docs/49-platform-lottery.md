# 平台彩种与品牌接入

> 2026-10-28 执行范围更新：投注、结算、佣金／提现事实与经营统计均以[统一配置化链路](65-unified-configured-betting.md)及当前 OpenAPI 为准。文中的旧品牌期次、专用订单、结算任务、旧夹具与旧容量结果是历史设计或证据，不代表当前可用接口。

## 当前状态（2026-10-25）

品牌后台提供两个独立菜单：“彩种管理”仅展示平台彩种及本品牌启用／停用；“规则配置”默认进入品牌自有彩种、玩法和规则列表，并提供品牌规则模拟及通用规则工作台。两页分别加载对应数据，不互相嵌入平台目录与品牌规则。规则页内切换保留列表和草稿；切换品牌或账号时销毁本品牌页面状态。

总后台的彩种行中，“玩法规则”和“开奖配置”进入独立视图，顶部提供返回列表；期次、号码模型及创建、接入、启停等简单操作继续使用弹窗。业务接口、权限与幂等协议不变。

共享彩种“玩法规则”只读取当前生效规则，编辑后一次保存立即生效，不再提供草稿、版本选择、验证用例、审核或发布流程。保存原子替换当前规则并保留历史快照；原键重试、权限和并发校验继续生效，已下注单仍按原快照结算。品牌后台不再提供销售配置写入口；已有销售配置及历史快照保留，不自动重置价格、限额或封盘时间。开奖来源采用命名修订及显式启用，支持JSON、HTML和JS渲染DOM。普通品牌彩种目录和规则流程仍在使用。下文旧表单步骤、专用协议及迁移编号为历史记录。

安装按[根README](../README.md#空库安装)执行全部迁移；配置式实现见[59号文档](59-configurable-mark-six-rule-design.md)。

## 历史实现与试用记录

平台彩种使用独立的 `platform_games` 目录。`brand_platform_games` 只保存品牌接入关系，接入动作不会复制彩种、玩法、期次或开奖结果。

## 当前可试用流程

1. 总后台“彩种”页使用单一列表，默认加载平台彩种；品牌作为筛选项，选择后显示平台彩种及该品牌自有彩种，并通过“归属”列区分。清除品牌后恢复平台彩种列表。平台彩种在选择品牌后仍只显示一次，不复制为品牌彩种。
   “创建彩种”始终创建平台彩种、定义号码模型，时区通过下拉选择；创建时无需填写原因，仍记录操作人及创建审计。平台与品牌行共用列表分页，各行的“期次”“玩法规则”“号码模型”入口打开其对应弹窗；不再另列品牌彩种表。
2. 列表中的“玩法规则”入口使用表单新增玩法，无需填写 JSON 或原因。名称和代码在顶部对齐，选号、积分、奖级、条件和赔率分区配置，限额与取整可展开，并有中英文业务帮助。支持号码选号、命中数量和常用开奖特征的等于/范围判断、全部/任一条件、多奖级、封顶及排他/累加策略；内部生成 schema-v1 交给现有引擎校验。属性、特征选号及排除选号不在本表单提供，不静默改为其他模式。规则保存后不可重写。
3. 列表中的“期次”入口创建统一期次，无需填写原因，仍记录创建审计。日期输入按平台格式显示，日历按钮打开悬浮日期选择器，不改变表单及弹窗高度；空间不足时向上展开，点击外部或 Escape 关闭。开奖时间到达后，平台发布通过号码模型校验的开奖结果。
4. 品牌后台“彩种管理”的平台彩种列表仅展示名称、状态和启用／停用操作。首次启用沿用品牌接入接口，已接入后使用本品牌可用性接口，继续验证品牌权限、版本及幂等。
5. 品牌平台彩种列表不提供期次、玩法规则、号码模型或开奖配置入口。品牌销售配置和自动开奖／提前封盘的 POST 接口不再注册，调用明确返回接口不存在。用户端开奖记录、历史注单和结算仍沿用既有只读及执行流程。

平台与品牌读取同一个 `platform_game_periods.id` 和 `result`，没有品牌独立的开奖编辑入口。列表与期次均分页，期次按开奖时间降序排列。

彩种列表的刷新与分页操作同栏，顶部仅放创建操作。号码模型创建、查看和修改采用同一可视化表单，按类型展示位数或号码池，不直接展示 JSON。

总后台的期次列表和创建输入共用平台设置的日期格式、时间格式与时区，不显示重复时区提示；输入根据明确的平台时区换算为 UTC 保存，不使用设备时区。日期日历和时间选择器使用应用内控件，月份、星期、今天和上午/下午按当前中英文切换，不依赖浏览器原生控件语言；切换语言保留已选值，12/24 小时制仍由平台设置决定。品牌及用户端保持各自的只读查询入口。

## 权限和写入约束

- 平台查询：`platform_game.view.platform`。
- 平台创建彩种、玩法、期次、发布结果：`platform_game.write.platform`。
- 平台通过 `POST /api/v1/platform/platform-games/{id}/model` 修改未配置玩法、未创建期次的号码模型，须提供当前版本，无需填写原因。写入、重放前重验权限，成功后递增版本并记录审计。模型修改与玩法/期次创建锁定同一彩种行，避免并发绕过使用保护；已有玩法或期次明确拒绝覆盖。品牌没有此写入路由。
- 品牌目录查询：`platform_game.view.brand`。
- 品牌接入：`platform_game.connect.brand`。
- 当前管理入口对平台账号和品牌账号分别校验；品牌写入平台定义的接口不注册。
- 品牌目录允许查看可接入彩种；完整详情和用户端列表必须满足已接入关系。
- 创建、接入与开奖发布都使用现有持久化幂等引擎和审计事务。重放前重验当前权限；未知响应只重试原请求正文和键。
- 同一品牌只允许接入一次，同一彩种期号不能重复，同一期不能重复发布或改写开奖结果。数据库也阻止已发布结果改写。

平台彩种结构已合并到 `0001_baseline.up.sql`，按[空库安装](../README.md#空库安装)操作；现有彩种仍保留品牌归属。已按用户要求对本地试用数据库执行迁移并重启后端，原有业务数据保留。自动化数据库测试使用独立测试数据库。

## 当前范围

### 原因字段全局核对

已检索用户端、品牌后台、总后台及共享组件的原因输入，并对照请求验证、服务和数据库约束处理。普通创建/配置移除：平台彩种、期次、玩法、未使用模型修改、品牌接入、品牌外观、通知模板。当前 `0001_baseline.up.sql` 中的外观和模板约束允许空原因，客户端校验、冻结重试正文和历史响应同步支持，历史原因及操作人、时间、版本和审计保留。

保留：充值/奖励/提现、投注取消与判定、结算与开奖更正、佣金政策和派发、财务限额、账号权限与密码/登录配置、域名归属、合规、已有品牌投注规则的审核/发布及排期，以及失败任务的人工重试。这些操作影响资金、身份/权限、已生效业务或异常处置，需要记录人工决策依据。用户端的账本/提现结果原因、审计历史和系统失败原因属于只读业务信息，不作为多余的填写项删除。

平台定义、品牌接入及共享开奖查询是通用基础。六合彩另提供专用销售配置与资金链路，用户可投注特码、两面、属性投注、正码、正码特、连码、连肖连尾、自选不中及其他参考玩法；总后台维护完整494项赔率和带生效区间的年度号码属性，品牌独立配置销售赔率和限额。操作流程及一期范围见 [六合彩试用](50-mark-six-trial.md)。参考站的八个加拿大盘口现提供用户投注、两级销售价格和资金结算，详见[加拿大彩种试用](51-canada-games-trial.md)。其他尚未配置专用销售的模型仍只提供目录及开奖查询，接入状态不代表可以投注。

六合彩通过 `platform_mark_six_orders` 区分共同期次/结果与品牌注单结算状态，已验证品牌独立钱包扣款、幂等、派奖和退款。原有品牌彩种继续使用 `games/periods/draw_results`；六合彩平台注单暂不参与代理佣金和提现流水资格，也未接入原品牌注单报表、取消及更正入口。

## 总后台开奖入口补齐（2026-10-25）

左侧“开奖”菜单的彩种选择器同时提供平台彩种及当前品牌自有彩种；平台六合彩无需先选择品牌。“彩种 → 期次／开奖配置”也进入同一开奖概览。品牌自有彩种保留原查询流程，品牌端不能调用新增的平台查询接口。

开奖概览提供实时采集、待开奖期次及按年份分页的开奖历史。历史合并 `platform_draw_history` 导入记录和已发布业务期次，同一期号优先展示已核对的导入证据、不重复列出；未记录的日期明确标示，不补造时间，不把导入记录变成可结算的业务期次。来源最近完整结果单独标示，不冒充已发布业务结果。

待开奖显示开始投注、平台封盘、开奖时间及尚未开盘／平台投注时段／已封盘／到时待发布状态；这不是品牌销售已启用的承诺。到时未发布的期次可由有写权限的总后台账号进入原发布表单，继续使用既有模型、权限及幂等校验。最多展示最早50个待开奖期次，更多记录由手动开奖结果分页浏览。

概览每5秒读取当前来源状态和期次，保留所选年份及页码。来源失败、时间冲突、属性缺失和超过两分钟未检查均明确提示；刷新失败保留上次成功数据并显示错误。数据源编辑及手动开奖结果继续在独立页签，读取不会自动启用或切换数据源。

新增 `GET /api/v1/platform/platform-games/{id}/draw-overview?year=2026&limit=50&offset=0`，要求 `platform_game.view.platform`，只在总后台注册。不修改数据库结构、历史结果、现有数据源配置或资金链路。

## 开盘、封盘与开奖时间（2026-10-25）

总后台“彩种 → 开奖配置 → 开奖数据源”在同一彩种的日程中配置“开奖前开盘（秒）”“开奖前封盘（秒）”；固定周期的开奖时间由“首期开奖时间 + 开奖周期”确定，来源排期则采用来源明确公布的下期开奖时间。手动创建期次继续直接填写开盘、封盘、开奖三个时间。

新数据源修订必须明确填写 `open_before_seconds`：开盘提前量须大于封盘提前量，固定周期时不得超过开奖周期。例如开奖为 21:30:00，开盘提前 3600 秒、封盘提前 20 秒，对应 20:30:00 开盘、21:29:40 封盘。品牌可以提前封盘，但不能早于或等于开盘。保存数据源后须明确启用修订，已预约期次及历史注单保留原时间，不追溯修改。

自动生成期次按开奖时间减去对应提前量保存 `bet_start_at`、`bet_end_at`。来源排期不再用采集时刻充当开盘时间。用户端期次栏显示开盘、封盘、开奖三个时间，开盘前提示尚未开盘并显示开盘倒计时，到开盘时切换封盘倒计时，到封盘时切换开奖倒计时。报价和下单继续在服务端校验 `开盘时间 <= 当前时间 < 封盘时间`，前端同步禁用选号与投注。

结构变更合并到 `0001_baseline.up.sql`。已有开发库先备份，在副本与新建基线数据库验证结构一致及原有158张业务表数据完整，再显式同步迁移记录并重新编译重启 API/worker。原固定周期修订的开盘提前量按其原周期补记；旧来源修订与已预约期次不改写，新增配置使用现行字段映射数据源。

本次检查覆盖中英文、Pixel 7 与 iPhone 13 横竖屏、桌面及 320 CSS px；实际投注页验证开盘前不可选、开盘后可选及封盘后禁用，加上619/620/621 CSS px断点前后检查，共30项设备/断点场景通过。独立数据库验证来源期次的三个时间、开盘前报价/下单拒绝、无注单写入及钱包余额与版本不变。三端与共享目录类型检查、全部前端构建和总后台159项单测通过。OpenAPI源与文档同步，但全仓文档生成/覆盖检查仍受现有推荐关系两个GET路由缺失文档覆盖阻塞。证据与数据库备份位于 `.local/opening-times-20261025/`。

### 自建彩种授权

总后台在品牌列表的操作菜单中提供“配置”，以分组表单展示品牌设置，当前“彩种”分组包含自建彩种授权，由具备
`brand_operation.view.platform` / `brand_operation.write.platform` 的平台管理员读取和修改
“允许自建彩种”。新建及已有品牌默认关闭。配置使用品牌共享版本控制，支持原键重试并保留审计记录。

关闭后，品牌后台隐藏规则配置、创建及试算入口；服务端拒绝创建、规则修改和试算请求，写入事务中再次核验配置；彩种和规则的只读查询保留，供已有业务处理使用。
平台彩种启停、已有期次及注单的查询和业务处理不受该开关影响。

未开放自建彩种且没有自建彩种记录时，品牌端同时隐藏期次、开奖、结算、更正及取消菜单，移动端底部入口改为彩种管理。品牌列表返回 `has_custom_games`，以实际自建彩种记录判定历史业务入口是否需要保留；有历史自建彩种时保留操作入口，规则配置和试算入口仍受授权开关控制。
