# 平台彩种与品牌接入

## 当前状态（2026-10-21）

品牌后台“规则配置”主页只展示平台彩种列表及“自有彩种规则”“规则模拟”入口；规则版本管理、模拟器和通用规则工作台按需进入独立视图。通用工作台从“自有彩种规则”进入，返回保留草稿和原请求回执；列表返回保留筛选及分页。切换品牌或账号时销毁本品牌页面状态。

平台与品牌后台的彩种行中，“玩法规则”和“开奖配置”进入独立视图，顶部提供返回列表；期次、号码模型及创建、接入、启停等简单操作继续使用弹窗。业务接口、权限与幂等协议不变。

共享彩种“玩法规则”统一进入配置式工作台，编辑、验证、审核和发布后，由品牌明确保存销售价格、开关与限额。开奖来源采用命名修订及显式启用，支持JSON、HTML和JS渲染DOM。普通品牌彩种目录和规则流程仍在使用。下文旧表单步骤、专用协议及迁移编号为历史记录。

安装按[根README](../README.md#空库安装)执行全部迁移；配置式实现见[59号文档](59-configurable-mark-six-rule-design.md)。

## 历史实现与试用记录

平台彩种使用独立的 `platform_games` 目录。`brand_platform_games` 只保存品牌接入关系，接入动作不会复制彩种、玩法、期次或开奖结果。

## 当前可试用流程

1. 总后台“彩种”页使用单一列表，默认加载平台彩种；品牌作为筛选项，选择后显示平台彩种及该品牌自有彩种，并通过“归属”列区分。清除品牌后恢复平台彩种列表。平台彩种在选择品牌后仍只显示一次，不复制为品牌彩种。
   “创建彩种”始终创建平台彩种、定义号码模型，时区通过下拉选择；创建时无需填写原因，仍记录操作人及创建审计。平台与品牌行共用列表分页，各行的“期次”“玩法规则”“号码模型”入口打开其对应弹窗；不再另列品牌彩种表。
2. 列表中的“玩法规则”入口使用表单新增玩法，无需填写 JSON 或原因。名称和代码在顶部对齐，选号、积分、奖级、条件和赔率分区配置，限额与取整可展开，并有中英文业务帮助。支持号码选号、命中数量和常用开奖特征的等于/范围判断、全部/任一条件、多奖级、封顶及排他/累加策略；内部生成 schema-v1 交给现有引擎校验。属性、特征选号及排除选号不在本表单提供，不静默改为其他模式。规则保存后不可重写。
3. 列表中的“期次”入口创建统一期次，无需填写原因，仍记录创建审计。日期输入按平台格式显示，日历按钮打开悬浮日期选择器，不改变表单及弹窗高度；空间不足时向上展开，点击外部或 Escape 关闭。开奖时间到达后，平台发布通过号码模型校验的开奖结果。
4. 品牌后台“规则配置”的“平台彩种”列表提供接入按钮。接入无需填写原因；已经接入的品牌显示“已接入”。
5. 已接入品牌可以查看玩法、号码模型、共同期次及开奖结果。用户端“开奖”页也可以查看当前品牌接入的平台彩种。

平台与品牌读取同一个 `platform_game_periods.id` 和 `result`，没有品牌独立的开奖编辑入口。列表与期次均分页，期次按开奖时间降序排列。

彩种列表的刷新与分页操作同栏，顶部仅放创建操作。号码模型创建、查看和修改采用同一可视化表单，按类型展示位数或号码池，不直接展示 JSON。

总后台的期次列表和创建输入共用平台设置的日期格式、时间格式与时区，不显示重复时区提示；输入根据明确的平台时区换算为 UTC 保存，不使用设备时区。日期日历和时间选择器使用应用内控件，月份、星期、今天和上午/下午按当前中英文切换，不依赖浏览器原生控件语言；切换语言保留已选值，12/24 小时制仍由平台设置决定。品牌及用户端保持各自的只读查询入口。

## 权限和写入约束

- 平台查询：`platform_game.view.platform`。
- 平台创建彩种、玩法、期次、发布结果：`platform_game.write.platform`。
- 平台通过 `POST /api/v1/platform/platform-games/{id}/model` 修改未配置玩法、未创建期次的号码模型，须提供当前版本，无需填写原因。写入、重放前重验权限，成功后递增版本并记录审计。模型修改与玩法/期次创建锁定同一彩种行，避免并发绕过使用保护；已有玩法或期次明确拒绝覆盖。品牌没有此写入路由。
- 品牌目录查询：`platform_game.view.brand`。
- 品牌接入：`platform_game.connect.brand`。
- 当前管理入口对平台账号和品牌账号分别校验；品牌写入平台定义的接口不注册。
- 品牌目录允许查看可接入彩种；完整详情和用户端列表必须满足已接入关系。
- 创建、接入与开奖发布都使用现有持久化幂等引擎和审计事务。重放前重验当前权限；未知响应只重试原请求正文和键。
- 同一品牌只允许接入一次，同一彩种期号不能重复，同一期不能重复发布或改写开奖结果。数据库也阻止已发布结果改写。

平台彩种结构已合并到 `0001_baseline.up.sql`，按[空库安装](../README.md#空库安装)操作；现有彩种仍保留品牌归属。已按用户要求对本地试用数据库执行迁移并重启后端，原有业务数据保留。自动化数据库测试使用独立测试数据库。

## 当前范围

### 原因字段全局核对

已检索用户端、品牌后台、总后台及共享组件的原因输入，并对照请求验证、服务和数据库约束处理。普通创建/配置移除：平台彩种、期次、玩法、未使用模型修改、品牌接入、品牌外观、通知模板。当前 `0001_baseline.up.sql` 中的外观和模板约束允许空原因，客户端校验、冻结重试正文和历史响应同步支持，历史原因及操作人、时间、版本和审计保留。

保留：充值/奖励/提现及余额修复、投注取消与判定、结算与开奖更正、佣金政策和派发、财务限额、账号权限与密码/登录配置、域名归属、合规、已有品牌投注规则的审核/发布及排期，以及失败任务的人工重试。这些操作影响资金、身份/权限、已生效业务或异常处置，需要记录人工决策依据。用户端的账本/提现结果原因、审计历史和系统失败原因属于只读业务信息，不作为多余的填写项删除。

平台定义、品牌接入及共享开奖查询是通用基础。六合彩另提供专用销售配置与资金链路，用户可投注特码、两面、属性投注、正码、正码特、连码、连肖连尾、自选不中及其他参考玩法；总后台维护完整494项赔率和带生效区间的年度号码属性，品牌独立配置销售赔率和限额。操作流程及一期范围见 [六合彩试用](50-mark-six-trial.md)。参考站的八个加拿大盘口现提供用户投注、两级销售价格和资金结算，详见[加拿大彩种试用](51-canada-games-trial.md)。其他尚未配置专用销售的模型仍只提供目录及开奖查询，接入状态不代表可以投注。

六合彩通过 `platform_mark_six_orders` 区分共同期次/结果与品牌注单结算状态，已验证品牌独立钱包扣款、幂等、派奖和退款。原有品牌彩种继续使用 `games/periods/draw_results`；六合彩平台注单暂不参与代理佣金和提现流水资格，也未接入原品牌注单报表、取消及更正入口。

## 验证

独立 PostgreSQL 测试覆盖两个品牌读取相同期次/结果、品牌禁止写入、重复接入与重复开奖、已发布结果的数据库不可变保护。HTTP 测试覆盖平台入口授权、接入幂等重放、跨品牌拒绝和权限撤销后旧回执拒绝。

三端类型检查与生产打包通过；平台端单元测试及静态检查通过。浏览器检查覆盖 1440px、820px、360px 的列表、只读期次弹窗和页面无横向溢出。全仓单元测试中，品牌后台原有报表归档/任务相关的 21 个失败仍存在。


六合彩与加拿大彩新销售已统一到配置式规则及 `/configured/:gameId`。专用目录/报价/下单与旧规则、销售写入已退役；历史注单、未结订单结算和资金证据保留。当前流程见 [配置式链路说明](59-configurable-mark-six-rule-design.md#1513-六合彩加拿大专用新销售退出)。
