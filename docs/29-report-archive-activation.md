# 自动归档启用接口交接

用户已确认首次启用从当天／当月开始。每种归档类型独立记录首次起点：日归档为品牌时区的当前民用日，月归档为当前民用月。完整周期结束后才生成系统首版，不自动回补首次启用前的日或月；历史仍可使用人工归档接口。

“当天／当月”是完整日/月，不是从启用的小时分钟开始切片。例如品牌当地10月8日启用月归档，首个范围为10月1日至11月1日；启用日归档则首个范围为10月8日至9日。周期内统计仍使用原快照合同，财务按实际入账时间，旧档不覆盖，默认不自动删除。

## 正式配置接口

PUT `/api/v1/admin/report-archive-policy`，与现有GET同一路径，使用主库，不接受查询参数或品牌路径别名。正文恰好为 `version,daily_enabled,monthly_enabled,reason`，全部必填；日/月开关必须是真实布尔值，null、缺失、未知及重复键拒绝。version为1至MAX_SAFE_INTEGER−1，reason去首尾空白、非空、最多500 UTF-8字节且无控制字符。客户端不能提交起点、时区或当前时间。

必须携带 `X-Brand-ID`、`Idempotency-Key` 和确认时的 `X-Report-Archive-Actor-ID`。需要该品牌成员范围、`report_archive.view.brand` 与 `report_archive_policy.write.brand` 同时成立，超管只读。平台查看不能替代品牌写入的查看授权。暂停品牌可以配置，停用品牌不能配置。

服务先锁定当前品牌及时区、当前配置版本，再使用数据库时间计算首次起点；不使用客户端或API机器的本地时钟。首次启用日/月分别只为原null起点填当前周期，未启用过且仍关闭的类型保持null。关闭及重新开启沿用原保存起点，原任务及原区间不变；不通过反复开关把起点改成历史周期。继续沿用27号核心的暂停及恢复处理，不删除队列。

配置、不可变修订、启用类型对应游标及 `report_archive.policy.update` 审计同事务提交，记录原/后版本、原因、实际actor、请求ID和IP。保存配置本身不创建归档、不运行worker、不改变积分。独立worker只发现已结束的周期；新启用的当日/月尚未结束时零任务是正常状态。

HTTP200返回原操作的完整AutomaticPolicy九字段，版本是输入+1，开关与正文一致，起点为服务端实际保存值，审计非空。成功回执不表示已有归档或当前配置仍相同。当前配置通过独立GET查询；原键在后来关闭或改配置后仍返回原ACK，不重新计算跨日/月起点。幂等命名空间为 `admin.report_archive.policy.update`，指纹为品牌及规范四字段正文。

当前会话、确认actor、权限和品牌状态在回执查询、锁等待及业务提交前复核；旧成功回执不能绕过撤权或停用品牌。版本冲突409；忙锁和技术/审计错误503不缓存成功回执，不留下半份配置/游标。非法正文沿用REQUEST_INVALID，其他错误沿用归档合同及生成OpenAPI。

## 后台编辑与原回执恢复

独立SDK支持PUT、明确品牌/平台查看与品牌写权限判定、闭合输入及回执校验。发送前复制四字段正文；调用方在请求进行中改动表单不能改变回执匹配。断网、5xx或畸形成功响应视为结果未知，调用方须保留原账号/品牌/版本/正文/键，只能显式原样确认，不自动发新键。

后台“自动归档任务”页面已接入PC与360px移动布局、中英文配置编辑。日/月独立启停，填写操作原因后核对当前完整九字段策略以及实际账号、品牌、原版本、两个目标开关、原因和原幂等键；明确勾选确认后才提交。页面没有历史起点、时区或当前时间输入，不能从浏览器预测首次保存起点。平台查看、超管查看及只有品牌查看权限的账号不可保存。

每个账号/品牌最多保存一个冻结的配置更新意图，与任务重试意图分开。结果未知时表单及新请求锁定；离页、切换语言或GET读到相同或更新配置都不自动重发，也不能把GET当作原请求ACK。管理员核对原正文并勾选后，使用原账号、品牌、版本、开关、原因和键显式重放。HTTP200原九字段ACK独立保存与显示，随后GET失败不丢失ACK；例如原启用回执为v2开启，另一操作已将当前策略改为v3关闭，两者分别显示，不把v3替换成回执。

409保存冲突意图，读取当前策略成功并明确勾选丢弃后才释放表单；成功回执也须重新读取及明确丢弃后才能开始下一次编辑。当前读取失败禁止新保存。账号/品牌/权限变化隔离视图，旧scope的401不退出新账号；当前401、退出及账号切换清除配置与任务意图。会话代次和冻结键保护迟到回执/冲突，旧请求不能污染新会话。意图仅存页面运行时内存，完整浏览器刷新、关闭或崩溃不保留，不写localStorage/sessionStorage。

专用Playwright配置及CI按桌面/移动拆分全新合成库，用正常迁移、seed和Harbor管理员创建命令初始化，不生成伪任务或资金记录。真实管理接口创建会员并充值37积分，首次启用真实提交后丢弃响应，再用另一真实操作关闭并读到v3，明确重放原请求恢复v2完整回执。钱包和全部会员流水保持原值，当前周期尚未结束时归档/任务为零；该测试不代替worker的跨日/月核心测试或苹果/安卓/鸿蒙真机验收。

初始化器验证命令符号链接的目标为可执行普通文件，但保留原绝对调用路径。Debian/Ubuntu的psql可链接到按调用名称分派的pg_wrapper，不能直接执行其真实目标路径替代psql；见[Debian客户端包装器说明](https://manpages.debian.org/bookworm/postgresql-client-common/pg_wrapper.1.en.html)。实际子进程回归覆盖psql链接、父目录链接和两种视口；数据库名、用户、零public表必须仍精确匹配，检查失败不运行迁移。

部署无新迁移，仍正常升级至0067并协调API/worker/管理端版本。所有未启用品牌保持关闭，原开发库与服务不迁移或切换；不执行生产启用或客户真实数据回补。OPEN-106仍保留外部文件年限与财务模板，生产容量、真机及客户人工代码审核另验。
