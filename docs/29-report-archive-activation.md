# 归档配置与定时执行

归档功能统一位于总后台，品牌后台不提供归档入口。平台唯一的“归档配置”管理日、月两条独立规则，所有品牌继承同一套计划；“归档记录”按品牌筛选，查看日/月快照和详情、下载。配置页不展示任务列表，不请求任务列表或任务详情。原来的日/月归档起点属于内部游标，不再作为页面字段展示。

## 业务规则

执行时间统一使用**平台设置的时区**，不能在归档配置中修改。日归档设置每日执行时间和归档前几天（1–365）；月归档设置每月执行日（1–31）、执行时间和归档前几个月（1–120）。时间采用严格的 `HH:mm`，日/月开关独立，关闭时也可保存执行规则。

- 日偏移 1 表示执行日期的昨天，2 表示前天。
- 月偏移 1 表示执行月份的上个月，2 表示上上个月。
- 例如每月 5 日 06:00、月偏移 2，在平台当地 2026-11-05 06:00 保存 2026 年 9 月整月的快照。
- 月份没有所选执行日时，使用该月最后一天；31 日计划在平年二月 28 日、闰年二月 29 日执行。
- 夏令时按 PostgreSQL 的民用时间规则解释：不存在的钟点向后移动，重复钟点采用较晚一次。目标日/月边界仍使用既有真实日历解析。
- 保存或重新启用后，从数据库时刻之后的下一次计划执行开始，不追补此前的计划。修改偏移可以使首次目标早于启用日/月；不再使用旧版“首次从当天/月开始”的限制。
- 未修改配置时，停机期间错过的计划由持久游标继续发现，按原目标逐个处理。关闭暂停发现及待处理任务执行，不删除记录；旧失败任务仍需显式重试。
- 已有该周期归档时任务跳过，不覆盖或自动追加新版；需要再次观察该周期时使用人工追加。

归档是在执行时保存目标周期的数据观察，财务仍按实际入账时间统计，余额是观察时余额，不是目标期末历史余额。归档不封账、不改变积分。

## 配置接口

`PUT /api/v1/platform/report-archive-policy` 必填：

| 字段 | 说明 |
| --- | --- |
| version | 确认的当前配置版本 |
| daily_enabled / monthly_enabled | 独立日/月开关，布尔值 |
| daily_execution_time | 每日执行时间 HH:mm |
| daily_period_offset | 前几天，1–365 |
| monthly_execution_day | 每月执行日，1–31 |
| monthly_execution_time | 每月执行时间 HH:mm |
| monthly_period_offset | 前几个月，1–120 |

`reason` 仍可省略或为空。不能提交起点、时区或客户端当前时间。旧版缺少定时字段的请求明确拒绝，不设置兼容分支。新品牌继承平台开关及规则，内部按品牌保留执行游标和不可变证据。开发库升级仅在原品牌规则一致时提取为平台配置；不一致时明确报错。

请求需要 `Idempotency-Key`、确认账号的 `X-Report-Archive-Actor-ID`，以及 `platform_settings.write.platform`；读取需要 `platform_settings.view.platform`。禁止携带 `X-Brand-ID`，品牌配置 GET/PUT 已关闭。版本冲突 409；技术/审计失败不提交部分配置或成功回执。

GET 和 PUT 返回完整配置、五个定时字段，以及 `next_runs: { daily, monthly }`。每个非空计划包含平台下一次计划的 `execute_at` 和 `period_key`；关闭时为 null。PUT 保存的是当次原回执，之后当前游标变化不改写旧回执；最新配置应独立 GET。

## 持久化与平台时区变更

平台配置及所有品牌派生配置、不可变配置修订、游标、审计和幂等回执同事务保存；任一品牌同步失败则整体回滚。执行时间由目标周期、偏移、执行日和配置时区在数据库内计算；发现任务及推进游标的守卫都验证计划确已到期。任务继续按品牌/类型/目标周期唯一，worker 并发不会重复生成归档。

平台时区变更在同一事务追加系统审计和新配置修订，为当前启用规则计算下一次计划；不修改已有任务、旧配置修订、旧归档或资金数据。新建品牌使用平台时区初始化配置。

## 页面及验证

总后台复用统一日/月表单组件，提供中英文时间、执行日和周期偏移；标题左侧、输入右侧，两栏及输入带边框，日归档留占位行与月执行日对齐。配置按平台权限编辑，不显示品牌选择、时区说明和冗余提示；下次执行时间及目标周期只展示服务器结果。配置页没有历史起点和任务列表。

保存前冻结账号、版本、五个定时字段、开关和唯一键，点击保存后提交。结果未知只能核对原输入并显式原键重放；刷新、离页和语言切换不自动提交。409 须重读当前配置并明确丢弃冲突输入；账号、权限及会话代次继续隔离迟到响应。

数据库回归覆盖每月 5 日 06:00 归档上上个月、跨年、月末/闰年、夏令时、提前不执行、到时一次生成、停机游标、失败重试、跨品牌权限和时区变更保留旧任务。浏览器在独立测试库验证完整保存、回执丢失及原键恢复，使用独立测试账号；配置操作不生成资金流水。

正式发布前结构合并在 `0001_baseline.up.sql`。已有开发库升级须先备份，在副本验证结构及原业务数据完整，再显式同步迁移记录。API 和 worker 不自动迁移；修改后重新编译并按原配置重启本地服务。

空库安装使用唯一基线 `backend/migrations/0001_baseline.up.sql`，步骤见 [README 空库安装](../README.md#空库安装)。已有开发库须先备份并在副本验证结构和业务数据，再显式同步迁移记录。
