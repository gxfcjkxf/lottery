# 第一阶段实现任务拆分

## 任务规则

- 每个任务必须有数据库迁移、权限校验、审计、测试和接口文档。
- 资金/投注任务必须包含并发和幂等测试。
- UI 任务必须覆盖桌面和 360px 移动视口。
- 未决事项通过 `08-acceptance-and-open-items.md` 的编号关闭后，才能进入对应生产实现。

## 核心闭环交付顺序

按用户要求，当前运营工作台完成并验收后，开发优先级调整为完整提现、佣金计算与派发、奖励。先完成可由用户与运营实际操作的业务闭环，再补齐对应报表、通知和剩余界面翻译；不继续拆分外围小阶段。阶段成果仍提交远程仓库，进度按已验收闭环及剩余模块报告，不使用没有固定权重的完成百分比。

提现交付包括资格预览、并发幂等申请、来源积分占用、审核、内部模拟出款、成功周期截止以及失败/驳回/取消原路返还。门槛基数为占用前全部可用充值＋赠送余额；所有已支持来源的有效投注按每笔投注时 N 快照折算后精确累加，N 必须大于 0，规则修改只影响新投注。OPEN-109业务选择及真实快照、流水查询和正式资格接入已完成开发验证，生产容量与客户人工审核另验，真实支付不在第一期内。佣金按差额分配，新增佣金来源，按周/月周期批处理，不按彩票期次计提，周期边界及人工/系统派发可配置；0046已实现四来源账本及退款/提现兼容；继续实现周期结算、修正、派发和更正回溯，OPEN-112至114已确认：佣金可投注、扣款顺序充值→中奖→佣金→赠送且不计入提现门槛基数；下级有效模式与上级一致；周期按投注时间归属。2026-10-08已确认OPEN-111/115/116：混合周期整期人工审核；佣金追回不足时暂停并等待运营处理后手动继续；奖励第一期为人工奖励订单与撤销，原赠送可用不足同样人工处理。均不得扣其他来源、自动解冻或形成负余额，业务选择不再阻塞，完整实现和验收仍须完成。

实现过程中先运行变更相关单元、真实数据库和短浏览器链路，模块闭环验收时运行必要的全量回归。资金幂等、并发余额、原路退款、品牌隔离和权限仍是强制检查；复用独立测试环境，不重复运行没有变化的整套模块，也不反复重写历史交接。
