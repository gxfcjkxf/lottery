## 核心闭环交付顺序

提现、佣金周期核算/派发/差额修正和人工奖励闭环均已实现，并已接入对应报表、站内通知和中英界面。当前优先验证整套业务与剩余尺寸、压力及故障场景，不把已实现模块再次列作待开发。阶段成果仍提交远程仓库，按已验证范围和实际缺口报告，不使用没有固定权重的完成百分比；生产验收不由开发测试代替。

提现包括资格预览、幂等申请、来源占用、审核、内部完成、成功流水截止及失败/驳回/取消原路返回。门槛为占用前全部可用充值＋赠送余额；有效投注按投注时N快照精确折算，N必须大于0。佣金按投注时间归属周/月周期，全部注单最终完成后精确差额累加、统一取整，可配置边界及人工/系统派发。佣金可投注，扣款顺序充值→中奖→佣金→赠送；佣金余额不计入提现门槛基数，下级模式必须与上级一致。混合周期整期人工审核、人工差额修正、结果更正追回不足时暂停并手动继续已接入。奖励一期为人工订单与撤销，不足时不扣其他来源、自动解冻或形成负余额。上述已确认口径不再作为待用户选择或待开发项；完整尺寸、压力、客户人工审核与生产仍需验收，真实支付不在第一期。

实现过程中先运行变更相关单元、真实数据库和短浏览器链路，模块闭环验收时运行必要的全量回归。资金幂等、并发余额、原路退款、品牌隔离和权限仍是强制检查；复用独立测试环境，不重复运行没有变化的整套模块，也不反复重写历史交接。
