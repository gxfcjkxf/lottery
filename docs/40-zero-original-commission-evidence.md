# 零原派发后的实际佣金入账保护

原派发金额为0、没有原派发流水，不等于此周期从未有实际资金。独立人工修正可能已经入账，后续结果更正必须保留原支付并按当前真实授予净额计算差额，不能将原支付stale后再登记全额新派发。

例如原核算及派发为0，运营人工修正至1；新核算为1时，之前实际净额1、目标1、差额0。原支付进入blocked并保留原0金额；新差额须按保存模式取得新批准，零目标完成不生成流水，最终实际净额仍1。如果新核算为0，应按既有新审核/运行门控追回1，不自动删除原人工修正或扣其他积分来源。

## 资金检测与守卫

0075扩展原派发失效判定及数据库守卫，检查原目标及独立人工修正的账本指针和反向业务绑定，并识别已实际执行的更正资金。观察到资金或可疑绑定时只能保留资金历史、阻止新的全额派发，不能当作无入账状态重置；检测本身不证明来源合法，计划准备和实际执行仍必须通过完整来源守卫。

原零目标的审核和不可变见证保留。候选之前积分沿用原人工净额头或后来真实更正净额头，不使用当前钱包余额；实际执行仍只移动commission.available。混合/人工模式的新审核、原支付和更正开关、版本、幂等、审计、暂停及显式继续均不放宽。迁移保留原函数OID和固定搜索路径，不回填流水、改历史、开启门控或自动结算。

## 旧错误历史与升级

旧逻辑可能已将带有真实人工修正资金的零原派发标为stale，甚至登记后续新支付。不得靠升级自动把旧状态改成blocked、删除后续任务、重新发款或改写旧账本。0075预检发现任何stale支付仍关联实际或可疑资金时，拒绝并回滚整个未应用迁移事务；原数据、审核和资金保持原样。

生产部署前停止旧金融worker及相关写入，先检查这种历史并保存证据。若存在，暂不完成升级或开启新资金处理，交由授权财务/技术人员核实。现有离线准备和检查可读取完整历史，但追加差额恢复流程尚未交付，也不是待用户选择的计佣业务规则；不能通过修改迁移记录、禁用守卫、通用钱包调账或删除历史来规避预检。整个项目目标仍继续实施。

## 离线准备与完整周期检查

仅供有授权的部署/数据库与财务人员使用，不是品牌用户接口或恢复权限。先排空并停止API、worker及其他金融写入，确认备份和密钥已保留；数据库主连接配置沿用安全部署环境，两个从库配置均须清空。命令不会替操作者停止旧进程，运行中旧写入仍可能改变历史。

正常`platform migrate`因旧stale资金回滚到0073后，可显式运行：

```sh
platform prepare-commission-history-review --confirm=offline-commission-review
platform commission-history-review "$LOTTERY_REVIEW_BRAND_ID" "$LOTTERY_REVIEW_CYCLE_ID"
```

两个ID必须是已核实的规范小写UUID；不传密码、密钥或数据库URL作命令行参数。准备步骤只接受嵌入SQL校验和完全一致的0001—0073历史，正常执行原0074并登记其真实校验和，停在0074；重复准备仅核验该检查点。不接受缺失、篡改、未知或已有0075的迁移集，也不修改已应用文件。与普通部署共用事务级锁，锁等待最多5秒、整个准备最多2分钟；DDL失败全事务回滚。既有0074索引的生产锁等待/容量仍须实测，不宣称无停机。

0074是离线检查点，不是完整服务版本。`platform check`、`serve`和`worker`继续拒绝启动；检查命令仅接受严格0074，不放宽普通版本准入。0075预检原样保留，检查报告或准备成功不能让带实际资金的stale历史通过升级，更不能自行将它改成blocked或删除后续任务。

检查在主库REPEATABLE READ/READ ONLY、15秒整体限制内核验迁移、整个指定周期及所有原/后续支付。按已保存受益代理输出完整核算/实际历史分析，包含窗口外的人工修正、补发和追回；未知目标保持null，损坏或无法归属的证据不释放部分报告。报告`format_version=1`、`review_only=true`、`execution_authorized=false`；`payments`保留每笔原状态、run、epoch、版本、原总额及已完成目标数量，`has_money_evidence`只是指针/反向绑定观察，金额仍须通过完整来源校验。`analysis`为coverage、summary、beneficiaries及total_beneficiaries，不是分页HTTP DTO。

最多1000笔周期支付及10000个受益代理，完整分析沿用34列CSV的4MiB及精确汇总验证；超限失败，不截断、翻页后冒充完整清单或将金额转为浮点。配置/连接失败输出脱敏错误，JSON只在事务成功后写出；输出失败不代表准备事务未提交，应先核验检查点，不盲目重复普通升级。离线读取不追加应用审核或审计；授权人员须按运维流程保存命令、身份、完整报告及事件记录。报告不是审批回执、稳定证据令牌或可执行补偿计划。

原零派发实际人工+1，新核算1时报告实际净额1、数学差0；若旧逻辑随后又实际派发1，报告须列出两笔支付，实际净额2、数学差-1，不能只看最新任务而报差0。尚未批准的后续支付也保留状态但不冒充入账。未来受控恢复须重新验证整周期及所有历史源，执行新审核、仅佣金来源差额、不足暂停和显式继续；本命令不执行这些资金动作。

## 开发验证

隔离PG17中使用正常服务生成中奖、零佣金派发、人工调增1和新的实际结算。修正前复现原支付被错误stale；修正后原支付blocked、没有第二笔全额支付，差额0取得新审核后完成，唯一资金流水仍为原人工+1。

0073已有真实零派发/人工入账正常迁移0074/0075后，资金、支付、人工修正/审计摘要及原函数OID保持。另在真实0073守卫下复现旧元数据失效动作，预检拒绝升级，整个事务回滚至0073，真实资金和历史不变。该验证只在自有随机schema执行，无真实客户资金或原开发库迁移。

显式准备真实旧stale资金至0074后，原资金、支付、人工修正及审计保持，普通升级仍拒绝；完整检查分别验证只有旧人工+1、后续待审批及后续实际再派发1三个状态，实际净额1/1/2及差额0/0/-1准确，前后16桶和历史摘要不变。真实测试进程证明API/worker拒绝0074。损坏校验和、临时元数据伪装、缺失/未知迁移及第三条索引DDL失败均失败关闭或完整回滚。
