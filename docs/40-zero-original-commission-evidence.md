# 零原派发后的实际佣金入账保护

原派发金额为0、没有原派发流水，不等于此周期从未有实际资金。独立人工修正可能已经入账，后续结果更正必须保留原支付并按当前真实授予净额计算差额，不能将原支付stale后再登记全额新派发。

例如原核算及派发为0，运营人工修正至1；新核算为1时，之前实际净额1、目标1、差额0。原支付进入blocked并保留原0金额；新差额须按保存模式取得新批准，零目标完成不生成流水，最终实际净额仍1。如果新核算为0，应按既有新审核/运行门控追回1，不自动删除原人工修正或扣其他积分来源。

## 资金检测与守卫

0075扩展原派发失效判定及数据库守卫，检查原目标及独立人工修正的账本指针和反向业务绑定，并识别已实际执行的更正资金。观察到资金或可疑绑定时只能保留资金历史、阻止新的全额派发，不能当作无入账状态重置；检测本身不证明来源合法，计划准备和实际执行仍必须通过完整来源守卫。

原零目标的审核和不可变见证保留。候选之前积分沿用原人工净额头或后来真实更正净额头，不使用当前钱包余额；实际执行仍只移动commission.available。混合/人工模式的新审核、原支付和更正开关、版本、幂等、审计、暂停及显式继续均不放宽。迁移保留原函数OID和固定搜索路径，不回填流水、改历史、开启门控或自动结算。

## 旧错误历史与升级

旧逻辑可能已将带有真实人工修正资金的零原派发标为stale，甚至登记后续新支付。不得靠升级自动把旧状态改成blocked、删除后续任务、重新发款或改写旧账本。0075预检发现任何stale支付仍关联实际或可疑资金时，拒绝并回滚整个未应用迁移事务；原数据、审核和资金保持原样。

生产部署前停止旧金融worker及相关写入，先检查这种历史并保存证据。若存在，暂不升级或开启新资金处理，交由授权财务/技术人员核实。针对这类历史的追加差额恢复流程尚未交付，也不是待用户选择的计佣业务规则；不能通过修改迁移记录、禁用守卫、通用钱包调账或删除历史来规避预检。整个项目目标仍继续实施。
