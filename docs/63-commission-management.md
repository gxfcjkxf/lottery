# 品牌佣金核算与派发

品牌端按周期浏览核算，按状态处理派发。沿用当前品牌的佣金查看及独立核算、审核、重试、人工修正权限。周期、计佣及派发设置继续由总后台统一管理。

## 页面结构

- 品牌后台统一使用「佣金管理」入口，以核算周期为主列表；不再单独提供「佣金派发」「佣金更正」菜单。实际佣金入账统计置于「业务报表」，核算与派发记录留在佣金管理。
- 每条核算记录提供查看、派发、更正入口；尚无核算代次时不开放派发与更正。查看以居中弹窗展示核算结果、计算明细和核算记录，失败核算保留原重试流程。
- 派发、更正从核算记录或核算详情进入共享居中弹窗，始终固定当前周期。查询、队列切换、重置及分页保留周期约束；不再切换到独立页面或在主列表末尾展开面板。没有相关记录时显示真实空状态，不创建派发或更正数据。
- 派发保留待审核、处理中、需处理和全部队列，详情包括摘要、代理明细、人工修正和操作记录。更正保留待处理、处理中、历史和全部队列，展示更正前后积分、代理差额和执行进度。
- 弹窗中的审批、重试、更正设置及人工修正沿用原权限、确认、版本和幂等校验；请求提交时禁用外层弹窗关闭，结果未知仍保留原请求恢复。回到核算列表时保留筛选和分页；品牌或账号变化清除弹窗上下文。
- 桌面复用共享管理表格，窄屏按共享规则重排成卡片；普通表单、按钮、弹窗和中英文沿用现有设计系统。内部任务编号和代次放在详情的技术信息中。

## 列表接口

`GET /api/v1/admin/commission-cycles` 和 `GET /api/v1/admin/commission-payments` 在 `limit/offset` 外接受：

| 参数 | 含义 |
| --- | --- |
| `from/to` | 成对提供 RFC3339 时间，按保存的 `cycle.window_to` 选择完整周期，from 包含、to 不包含 |
| `state` | 核算或派发状态；不传则全部 |
| `cycle_id` | 当前品牌保存的周期 |
| `agent_id` | 当前品牌的受益代理 |

日期控件按平台时区解释，结束日期包含当天，再转换为次日零点的排他边界；不使用浏览设备时区推断。核算按 `window_to DESC,id DESC` 排序，派发同周期内按创建时间及 ID 倒序。数据库在同一条查询内生成匹配总数和当前页，不从当前页数据推导全量统计。

核算 `state=ready` 要求周期和当前代次均就绪且证据 epoch 一致；`state=stale` 选择原 ready 但当前证据不再就绪的周期。派发 `state=needs_attention` 包含失败记录和当前核算来源尚无已完成更正的阻止记录；stale 及当前来源已有完成更正的旧阻止记录只在全部记录中保留。该数量是状态查询，不代表欠付金额。代理筛选从派发绑定代次的收益读取，因此待审核且尚无执行目标的派发也可被正确查到。

`GET /commission-payments/{id}/targets` 支持 `agent_id/state`，仍只返回真实保存的执行目标，用于人工修正；未生成目标时不会伪造目标。

## 审核前代理明细与执行记录

新增 `GET /api/v1/admin/commission-payments/{id}/beneficiaries`，支持 `limit/offset/agent_id/state`：

- 从派发记录绑定的保存代次读取所有受益代理及原计划积分，不读取今天的代理比例。
- `id` 是原收益记录的编号；`target_id` 只有实际创建执行目标后才有值。
- 尚未执行时显示 pending，`target_id/paid_at/adjusted_points` 为 null；该读取不创建目标、账本或修正记录。
- 原计划积分、执行状态、实际入账时间和人工修正后的积分分别展示，零额目标也不伪造资金流水。

新增 `GET /api/v1/admin/commission-payments/{id}/history`，使用 `limit/offset`，从该品牌该派发的不可变审计记录投影创建、审核、重试、逐代理入账、完成、失败、来源变化和人工修正；只返回操作人、动作、派发状态及时间，不暴露原始审计 JSON、IP 或任务内部字段。人工修正事件没有派发状态，返回 null；变更前后积分等明细仍在对应代理的修正页内查看。

两项读取沿用佣金查看权限、读取前后会话和权限复核及审计。未知、外品牌周期、代理或派发不返回其他品牌数据。没有新增资金写入口、默认授权或数据库迁移；已有审批、版本、资金不足、幂等及原请求重试规则不变。

- 品牌后台类型检查与完整单元测试。
- 独立命名测试数据库中的真实投注、核算、派发、人工修正、品牌隔离、筛选分页与账本不变检查；各测试使用独立 schema 并清理。
- OpenAPI 生成检查及佣金接口契约测试。
- `LOTTERY_LAYOUT_PORT_BASE=16273 pnpm exec playwright test --config playwright.commission-management.config.ts`：中英文、安卓/iOS 横竖屏及 320/640/900/901/1440px，检查真实 Vue 组件的布局、核算／派发／更正弹窗切换、周期约束和确认信息。该浏览器布局用例使用明确合成的只读接口响应；资金行为由真实数据库及组件业务测试验证，不据此宣称真机或生产验收完成。

## 佣金更正与佣金报表

更正列表按计划关联其唯一执行记录，划分待处理、处理中、历史及全部；历史包含来源已失效的计划或已完成、已失效的执行。详情区分更正前与新核算积分、代理差额及执行进度，批准、继续和重试保留各自权限与二次确认。计划失效优先显示失效状态；来源、版本或证据不匹配时不允许提交执行操作；更正执行还须同时满足平台派发开关和品牌更正开关，计划重试须满足平台派发开关。资金开关放在更正设置，保持原有默认关闭策略。

`GET /api/v1/admin/commission-correction-cases` 为佣金查看权限下的只读分页接口，参数 `from/to` 使用周期结束时间的包含起点、排他终点，`state` 支持 `pending/processing/history`，另可按已保存周期和代理筛选。总数与本页在同一查询快照生成，关联执行为可空字段；读取不创建计划、执行目标或资金流水。原计划与执行详情及写接口保持不变，继续执行仍要求已批准、周期持有、当前证据及后端来源检查。

业务报表统一为投注、账本、提现、奖励和入账统计五个页签。代理、代理范围及会员加入方式的统计合并进投注报表，按原有独立权限调用归属统计接口；普通投注查询仍使用投注接口，查询失败不切换接口或扩大范围。分页和导出沿用已查询的完整筛选。取消独立归因和周期核对页签，不在周期详情另建对账页面；已有核算、派发、人工修正与更正记录保留，服务端查询接口及历史数据不删除。


## 人工修正与菜单归属

人工奖励归入资金管理，保持原有独立权限和业务流程。派发详情中的人工修正可按品牌内已保存代理在服务端筛选实际派发目标；切换代理或分页读取时清除旧代理历史，读取失败显示明确错误和重试；筛选草稿变化时须先重新查询，才能对结果发起修正。修正确认显示代理、当前积分、修正后积分和差额；可填写原因。保留既有审批权限、并发版本、余额校验、幂等和结果未知时原请求恢复。更改查询不会把当前页数量当作全量数量，未生成目标也不伪造可修正记录。

业务报表各页签统一使用筛选卡片和结果卡片，不重复页签标题、品牌及快照摘要；查询按钮统一为「查询」，结果右上方统一提供「导出完整 CSV」及导出权限提示。指标、空状态和分页使用同一布局，周期覆盖、余额及奖励类型等业务差异保留。样式维护在 `admin-web/src/report-workspace.css`。
